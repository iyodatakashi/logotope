# Implementation Plan

> 討論を圧縮した「討論ダイジェスト」を先に用意し、それを入力にイントロ・クロージングを生成して、既存の編集チェーンに best-effort ステップとして差し込む。生ディベートは不変。表示は当面 admin Phase6 プレビュー（イントロ＝章の前・クロージング＝章の後）。

- [x] 1. Foundation: 型定義
- [x] 1.1 討論ダイジェストの型を定義する（Functions）
  - 章ごとの圧縮散文・論点、ペルソナの立場・信念変化、テーマ名を持つ非永続の中間表現型を定義する
  - 完了条件: `DebateDigest` / `ChapterDigest` / `PersonaDigest` が Functions 型として存在し、型チェックが通る
  - _Requirements: 1.1, 2.1_

- [x] 1.2 イントロ・クロージング成果物の型を定義する（Functions / フロント）
  - `intro` と `closing` をそれぞれ `string | null`（未生成/失敗は null）で持つ永続形を、Functions とフロント（models）の双方に定義し一致させる
  - 完了条件: 両側に成果物型が存在し、Firestore 永続形と一致（変換関数は持たない）
  - _Requirements: 6.1, 6.2_

- [x] 2. Core: 討論ダイジェスト（圧縮）
- [x] 2.1 (P) 章要約エージェントを実装する
  - 1章分の会話ターンを、意味・立場・帰属を保ったまま中立に圧縮した散文へ要約する（結論・優劣・特定立場の支持/否定を含めない）
  - LLM をモックした単体テストで、圧縮結果が非空・非結論であることを検証する
  - 完了条件: 章の会話を渡すと圧縮散文（または失敗時エラー）を返す関数が単体テスト付きで動作する
  - _Requirements: 1.1, 2.1, 3.1, 3.2, 3.3_
  - _Boundary: debate-digest-agent_

- [x] 2.2 討論ダイジェスト生成を実装する
  - 原本章と承認済みペルソナ（信念・気づき）を読み、章ごとに要約して討論全体のダイジェストを組み立てる。イントロ・クロージング固有の意図を混ぜない（消費者中立）
  - 全章の要約成功でダイジェストを返し、1章でも失敗すればエラーを返す（部分成功を許容しない）。Firestore には保存しない
  - 完了条件: トピックIDを渡すと消費者中立の `DebateDigest`（または失敗時エラー）が得られ、単体テストが通る
  - _Depends: 2.1_
  - _Requirements: 1.1, 1.3, 2.1, 2.2_
  - _Boundary: buildDebateDigest_

- [ ] 3. Core: イントロ・クロージング生成と保存層
- [x] 3.1 (P) イントロ・クロージング生成エージェントを実装する
  - ダイジェストとテーマ文脈（テーマ説明・参考資料・事実基盤）から、イントロ（テーマの位置づけ・立場の多様性・全体を俯瞰する導入）とクロージング（論点と立場の広がりの振り返り・問いを開いたまま締める）を独立に生成する
  - 専用プロンプトで結論・優劣・勝敗・落としどころ・特定立場の支持/否定を禁止し、個人の主張是非でなく論点と立場の広がりを扱わせる
  - LLM をモックした単体テストで、生成成功/失敗と非結論制約を検証する
  - 完了条件: ダイジェストを渡すとイントロ・クロージングそれぞれの散文（または失敗時エラー）を返す2関数が単体テスト付きで動作する
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 2.1, 2.2, 2.3, 2.4, 3.1, 3.2, 3.3_
  - _Boundary: intro-closing-agent_

- [x] 3.2 (P) イントロ・クロージング成果物の保存層を実装する
  - 成果物ドキュメントの書き込み/読み取りを追加し、既存の編集成果物一括破棄処理にイントロ・クロージングの破棄を加える（原本は読み取りのみ・不変）
  - 単体テストで冪等な上書きと、再実行時の即時破棄（空化）を検証する
  - 完了条件: 成果物の書き込み・読み取りができ、編集成果物破棄で成果物が空化される（原本は無変更）
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 5.2_
  - _Boundary: edited-repository_

- [x] 4. Integration: 編集チェーンへの組み込み
- [x] 4.1 イントロ・クロージング生成ステップ本体を実装する
  - ダイジェスト生成 → イントロ・クロージングを独立生成 → 成果物保存、の順で実行する。ダイジェスト失敗時は両方 null、片方の生成失敗時は成功側を保持し失敗側を null で保存する
  - 生成・ダイジェストの失敗は例外にせずログのみとし、ステップは必ず正常終了する（後続ステップ・完了確定を妨げない）。原本は改変しない
  - 単体テストで「両 null / 片方保持 / 例外を投げない」を検証する
  - 完了条件: ステップ実行後に成果物が保存され、生成失敗でも例外を投げず後続へ進める
  - _Depends: 2.2, 3.1, 3.2_
  - _Requirements: 1.1, 2.1, 6.4, 7.1, 7.3_
  - _Boundary: runIntroClosingStep_

- [x] 4.2 編集チェーンにステップを配線する
  - 編集ステップ種別にイントロ・クロージングを追加し、最終章編集の次にこのステップ、その次に既存のコメント編集ステップへ連鎖させる。完了確定（コメント編集ステップ内包）は変更しない
  - このステップ進行中も編集フェーズは実行中のままとし、生成中であることが管理画面で分かる状態を保つ
  - 完了条件: 編集開始から `章編集 → イントロ・クロージング → コメント編集 → 完了確定` の順で実行され、既存の完了確定判定は不変
  - _Depends: 4.1_
  - _Requirements: 5.1, 5.3_
  - _Boundary: editing-orchestrator, enqueue-editing-step_

- [x] 4.3 編集開始のサーバ側 討論完了ゲートを追加する
  - 編集開始処理で討論フェーズが完了（generated 到達）しているかを検証し、未完了なら拒否する。既存の章存在チェックは討論完了判定には使わない
  - 完了条件: 討論未完了のトピックで編集開始を呼ぶと拒否され、完了済みなら通る
  - _Requirements: 5.4_
  - _Boundary: startEditing_

- [x] 5. Frontend: 表示と画面ゲート
- [x] 5.1 (P) イントロ・クロージング購読ストアを追加し配線する
  - 成果物ドキュメントを onSnapshot で購読するストアを追加し、トピック詳細のストア構成に配線する（既存の編集後章ストアと同型）
  - 完了条件: 成果物の変更が購読で受け取れ、画面から参照できる
  - _Requirements: 4.1_
  - _Boundary: editedIntroClosing store_

- [x] 5.2 Phase6 プレビューにイントロ・クロージングを表示する
  - イントロを章群の前、クロージングを章群の後に、本編（章・ターン）と区別できるセクションとして表示する。値が無い側は領域ごと非表示にする
  - 完了条件: 生成済みのイントロが冒頭・クロージングが末尾に区別表示され、未生成側は表示されない
  - _Depends: 5.1_
  - _Requirements: 4.1, 4.2, 4.3, 4.4_
  - _Boundary: Phase6Editing_

- [x] 5.3 Phase6 の編集開始ボタンを討論完了までゲートする
  - 討論が完了するまでは編集開始ボタンを出さない/無効にする（画面側の大前提ゲート。サーバ側ゲートと二重化）
  - 完了条件: 討論未完了のあいだは開始操作ができず、完了後に操作可能になる
  - _Requirements: 5.4_
  - _Boundary: Phase6Editing_

- [x] 6. Validation: 統合・回帰・E2E
- [x] 6.1 編集チェーンと再実行の統合テストを追加する
  - チェーン順序（章編集 → イントロ・クロージング → コメント編集 → 完了確定）を検証し、ダイジェスト/生成が失敗してもコメント編集・完了確定へ到達し完了（generated）になることを確認する
  - 編集パス再実行で旧イントロ・クロージング成果物が破棄され再生成されることを確認する
  - 完了条件: 上記シナリオの統合テストが通る
  - _Depends: 4.2, 3.2_
  - _Requirements: 5.1, 5.2, 7.1, 7.2_

- [x] 6.2 既存編集の回帰（parity）テストを追加する
  - ステップ追加後も、編集後章・編集後コメント・完了確定の判定が従来どおり不変であることを確認する
  - 完了条件: 既存編集フローに回帰がないことを示すテストが通る
  - _Depends: 4.2_
  - _Requirements: 7.1_

- [ ]* 6.3 Phase6 表示の E2E テストを追加する
  - イントロが章の前・クロージングが章の後に表示され、未生成側が非表示になることを画面で確認する（受け入れ基準 4.1–4.4 の補助的検証、MVP後に回せる）
  - 完了条件: 表示位置と非表示の E2E が通る
  - _Depends: 5.2_
  - _Requirements: 4.1, 4.2, 4.3, 4.4_
