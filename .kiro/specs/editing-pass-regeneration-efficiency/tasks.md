# Implementation Plan

> 実装は functions 変更後に手動デプロイが必要（Claude はデプロイしない）。移行 backfill は「backfill 先 → デプロイ」の順序を守る。

- [x] 1. 命名整理（機械的リネーム・振る舞い不変）
- [x] 1.1 バックエンドの命名を整理する
  - editorial（導入・締め・所感）を指す識別子から `Element` を排し `Editorial` へ統一（writer 型・その状態遷移メソッド 3 つ・進捗ステータス型・終端スイープ関数）。`EditorialElement` は用いない。
  - editorial を build する共通部品ファイル、および記事全体の再生成コア関数ファイルを、それぞれ editorial 由来／`ArticleElement` を略さない名前へ改名する。
  - 型 `ArticleElement` を受ける変数・引数の `element` を `articleElement` に改める。editorial だけを指すコメントの「記事要素」を「editorial」に是正する。
  - 観測可能な完了: 型チェックと既存テストが green で、editorial を指す識別子に単独の `Element` が存在しない。
  - _Requirements: 7.1, 7.2, 7.3_
- [x] 1.2 フロントエンドの命名を追随させる
  - editorial の進捗ステータス型の参照名をバックエンドに合わせて更新し、`ArticleElement` を受ける引数 `element` を `articleElement` にする。
  - 観測可能な完了: FE の型チェックが green で、editorial／`ArticleElement` の呼称がバックエンドと一致する。
  - _Requirements: 7.1, 7.2, 7.3_

- [x] 2. 討論ダイジェストのキャッシュ基盤を作る
- [x] 2.1 ダイジェスト専用ドキュメントのリポジトリを新設する
  - 討論ダイジェストをサーバー内専用の別ドキュメントに保存・読取・削除する機能を用意する（FE には購読させない）。単一書き込み・トランザクション不使用。
  - 読取は未保存で「無し」を返し、削除は未存在でも成功する。
  - 観測可能な完了: 保存→読取で同一ダイジェストが得られ、削除後の読取が「無し」を返す単体テストが green。
  - _Requirements: 5.1, 5.2, 5.3, 6.2_
  - _Boundary: digest-cache-repository_

- [x] 3. editorial 成果物ドキュメントの命名整理と既存データ移行
- [x] 3.1 成果物ドキュメントの保存先を outputs へ切り替える
  - editorial 成果物（導入・締め・所感）の保存/読取先を、無名の singleton から `outputs` という名前付きドキュメントへ変更する。データ形は不変。
  - 観測可能な完了: 生成・再生成・クリアが `outputs` に対して行われる。
  - _Requirements: 6.1_
  - _Depends: 1.1_
- [x] 3.2 既存データ移行の backfill をリポジトリに実装する
  - 全トピックの旧成果物ドキュメントの内容を `outputs` へコピーするスクリプトを、リポジトリに残す冪等な形（既に `outputs` があればスキップ）で実装する。使い捨てにしない。
  - 観測可能な完了: backfill 実行で公開済み含む全トピックの `outputs` が用意され、再実行しても二重コピーしない単体テストが green。
  - _Requirements: 6.3, 6.4, 6.5_
  - _Boundary: backfill script_
  - _Depends: 3.1_
- [x] 3.3 フロントエンドの読み取り先を outputs へ更新する
  - 管理編集画面の購読と、公開記事の読み取りを `outputs` へ向ける。移行順序（backfill 先）で公開記事が成果物を失わないようにする。
  - 観測可能な完了: FE が `outputs` を読んで導入・締め・所感を表示する。
  - _Requirements: 6.1, 6.5_
  - _Depends: 3.1_

- [x] 4. 生成中への切替を重い前処理より前に出す（順序統一・失敗整合）
- [x] 4.1 段階書き込みの「生成中への切替」を呼び出し側の責務にする
  - 導入・締めの共通 build 部品から、先頭で行っていた「生成中への切替」を除去し、切替は呼び出し側が事前に行う契約に変える（所感の build 部品は既に切替が先頭のため基準として維持）。
  - 観測可能な完了: build 部品が「生成中への切替」を呼ばず、切替済み前提で原本生成→整え→完了を行う。
  - _Requirements: 4.1, 4.2_
  - _Depends: 1.1_
- [x] 4.2 導入・締めの個別再生成を「切替→前処理→生成」の順に組み替える
  - 個別再生成で、まず「生成中への切替（旧内容クリア）」を単一書き込み・非トランザクションで行い、その後に重い前処理（ダイジェスト入力構築）を実行する。前処理が失敗しても終端ステータスへ確定し「生成中」で固着させない。
  - 観測可能な完了: 再生成トリガー直後に onSnapshot で「生成中」が反映され、前処理失敗時は生成失敗で終端する。
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 2.2, 3.1, 4.1, 4.2_
  - _Depends: 4.1_
- [x] 4.3 一括ランも「切替」を前処理より前に行う
  - 編集ラン全体の導入・締め生成で、未生成の editorial に対する「生成中への切替」をダイジェスト構築より前に行い、build 部品の切替除去に追随させる。前処理失敗・未達の editorial は既存の終端スイープで確定する。
  - 観測可能な完了: 一括ランでも切替が前処理より先に走り、未達 editorial が終端化される。
  - _Requirements: 1.1, 1.2, 3.2, 4.1, 4.2_
  - _Depends: 4.1_

- [x] 5. 討論ダイジェストの再利用と無効化を組み込む
- [x] 5.1 ダイジェスト入力構築をキャッシュ対応にする
  - 導入・締めの入力構築を「キャッシュに有れば再利用、無ければ構築して保存」に変える。初回の一括ランと個別再生成が同一の入力構築を通すため、初回ランが保存したダイジェストを以降の再生成が再利用する。
  - 観測可能な完了: 個別再生成を連打してもダイジェスト構築は一度きりで、以降は再利用される統合テストが green。
  - _Requirements: 5.1, 5.2, 5.4_
  - _Depends: 2.1, 4.2_
- [x] 5.2 上流変更・編集ラン開始でダイジェストを無効化する
  - 編集成果物を破棄する既存の中央処理に、ダイジェストキャッシュの削除を相乗りさせる（討論・ペルソナ・章・fact 変更、編集ラン開始のすべてで無効化される）。
  - 観測可能な完了: 上流変更後の再生成でダイジェストが作り直される統合テストが green。
  - _Requirements: 5.3_
  - _Depends: 2.1_

- [x] 6. テストで振る舞いを担保する
- [x] 6.1 順序・失敗整合・命名の単体テストを追加する
  - 個別再生成で「生成中への切替」が重い前処理より前に呼ばれること、前処理失敗時に終端へ落ちること、build 部品が切替を呼ばないこと（契約変更の回帰防止）、ステータス変更が単一書き込みであることを検証する。
  - 観測可能な完了: これらの単体テストが green。
  - _Requirements: 1.1, 1.2, 2.1, 2.2, 3.1, 4.1, 4.2_
- [x] 6.2 キャッシュ再利用・無効化・移行の統合/単体テストを追加する
  - 初回生成→個別再生成連打でダイジェスト構築が一度きりであること、上流変更後に作り直されること、backfill が冪等で公開済み含む全トピックを移行することを検証する。
  - 観測可能な完了: キャッシュ再利用・無効化・backfill 冪等のテストが green。
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 6.3, 6.4, 6.5_
  - _Depends: 5.1, 5.2, 3.2_
