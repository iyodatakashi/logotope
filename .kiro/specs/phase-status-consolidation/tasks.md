# Implementation Plan

> 前提（コード外の運用）: デプロイ前に既存 `topics` コレクションを削除する。移行コードは作らない（全削除・再作成）。

- [x] 1. 基盤: 共有型と状態導出の一元化
- [x] 1.1 フロント共有型から旧ステータスを除去し2軸を必須化する
  - 旧トピックステータス enum と、トピック/サマリの旧ステータスフィールドを型定義から削除する
  - トピックの「現在のフェーズ」と「フェーズ状態」を必須フィールドにする（任意指定をやめる）
  - 討論セッションからワークフロー進行ステータス型・フィールドを削除し、セッションは討論コンテンツ専用にする
  - 完了状態: 型レベルでトピックが `(phase, phaseStatus)` を必須に持ち、旧ステータス型への参照が型定義から消えている
  - _Requirements: 1.1, 1.5, 2.1, 6.1_
- [x] 1.2 フェーズ状態に「停止」を追加し、論理状態導出を純粋関数化する
  - フェーズ状態の値集合に「停止（stopped）」を追加し、全フェーズ共通の失敗・停止状態として扱う（エラーは停止に集約）
  - 論理状態の導出を「トピックの状態」と「対象フェーズ番号」のみを入力とする純粋関数にし、セッション/クライアントのヒント引数を撤廃する
  - 旧ステータスからの導出・互換ヘルパーと関連マッピングを完全削除する（互換コードパス・移行ロジックを残さない）
  - 一覧バッジのラベル/スタイル導出を停止状態に対応させ、同一トピック状態から一覧と各画面が同一結果を出す
  - 完了状態: 論理状態が `(phase, phaseStatus)` 入力のみから決まり、停止を含む全状態が導出でき、旧ヘルパーがコードベースから消えている
  - _Requirements: 1.2, 1.3, 5.1, 5.2, 5.3, 5.5, 5.6, 5.7, 6.2, 6.3, 6.4_
  - _Depends: 1.1_
- [x] 1.3 (P) Functions 側の型から討論セッションステータスを除去し停止を追加する
  - Functions 共有型のフェーズ状態に「停止」を追加する
  - 討論セッション専用ステータス型を削除し、フェーズ状態導出がセッションを参照しない前提を型で固定する
  - 完了状態: Functions の型からセッションステータス型が消え、フェーズ状態が停止を含む4値になっている
  - _Requirements: 2.1, 2.2, 4.6, 6.1_
  - _Boundary: functions types_

- [x] 2. コア: 状態書き込みのトピック一元化（クライアント）
- [x] 2.1 (P) トピックストアの停止・失敗・公開書き込みをトピック状態へ寄せる
  - 討論の停止操作を、セッションへの書き込みではなくトピックのフェーズ状態を「停止」にする処理へ置き換える
  - フェーズ1〜4の生成系操作で失敗を捕捉した際にトピックのフェーズ状態を「停止」に書く
  - 公開操作から旧ステータス書き込みを外し、公開判定はタイムスタンプのみに依存させる（公開機能自体はオミット、enum 依存のみ除去）
  - 旧ステータスの公開・読み取り経路を撤去する
  - 完了状態: 停止・生成失敗・公開のいずれの操作後もトピックの `(phase, phaseStatus)` のみが権威として更新される
  - _Requirements: 1.4, 4.3, 6.1_
  - _Boundary: Topic store_
  - _Depends: 1.1, 1.2_
- [x] 2.2 (P) 取材フローの失敗時にトピックを停止状態にする
  - フェーズ3取材の実行で失敗を捕捉した際にトピックのフェーズ状態を「停止」に書く（実行中・完了は既存のまま）
  - 完了状態: 取材失敗後にトピックが停止状態になり、画面が再実行導線を出せる
  - _Requirements: 1.4_
  - _Boundary: Personas store_
  - _Depends: 1.1, 1.2_

- [x] 3. コア: 討論ライフサイクルと停止ゲート（Functions）
- [x] 3.1 リポジトリの状態書き込みをトピック権威へ再編する
  - 討論セッションステータスの更新・エラー終端・旧トピックステータス更新の各関数を削除する
  - セッション作成・章進捗破棄・討論完了の各処理からステータス書き込みを外し、コンテンツ（ターン・章・コメント・インデックス）保持に限定する
  - トピックを「停止」にする処理と、現在が実行中のときのみ「生成完了」に進めるトランザクション処理を追加する
  - 完了状態: セッションにステータスが書かれなくなり、討論完了は「実行中のときのみ完了」が保証され停止を上書きしない
  - _Requirements: 2.2, 2.3, 4.4, 4.7, 6.1_
  - _Boundary: Repository status fns_
- [x] 3.2 (P) オーケストレータの停止判定をトピック参照に付け替える
  - 各章タスク先頭でトピックを一度読み、章ターンループの停止判定をセッション参照からトピック参照へ置き換える
  - 停止条件を「現在フェーズが討論かつ実行中であること」が成立しない場合に停止・以降の生成と状態上書きを行わない、に統一する（上流フェーズの再生成でフェーズが戻った場合も停止する）
  - 討論完了の書き込みを「実行中のときのみ生成完了」に変更し、停止を上書きしない
  - 完了状態: セッションステータスを参照せず、トピック状態のゲートで討論が継続/停止し、停止後に状態が上書きされない
  - _Requirements: 2.1, 4.1, 4.2, 4.4, 4.6_
  - _Boundary: Debate orchestrator gate_
  - _Depends: 3.1_
- [x] 3.3 (P) 討論APIの開始・異常終了をトピック状態へ寄せる
  - 討論開始でセッションステータス更新をやめ、トピックを討論・実行中にする書き込みに一本化する
  - 章タスクの最終リトライ失敗時の終端を、セッションのエラーではなくトピックの「停止」書き込みに変更する
  - 再開は停止時の章インデックスから再投入し、トピックを実行中に戻す（既存の章単位再開を維持）
  - 完了状態: 討論の開始・異常終了・再開のいずれもトピックの `(phase, phaseStatus)` のみで表現される
  - _Requirements: 2.3, 4.1, 4.5, 4.7_
  - _Boundary: Debates API_
  - _Depends: 3.1_

- [x] 4. 統合: phaseController 解体と画面のリアクティブ導出
- [x] 4.1 状態を持たない操作群へ分解し PhasePanel を導出状態駆動にする
  - フェーズ操作（生成・承認・再生成・停止・再開・やり直す）を、実行中フラグや論理状態を保持しない操作群に分解する
  - PhasePanel をコントローラ依存から「フェーズ番号・論理状態・操作ハンドラ」を受け取る形へ変更し、実行中フラグ参照を全廃してボタン無効化や進行表示をトピックのフェーズ状態から導出する
  - 実行中分岐と停止分岐に全フェーズ共通の回復アクション（やり直す／停止／再開）を提示する
  - 完了状態: クライアントが独自の実行中状態を持たず、PhasePanel の表示・操作可否がトピック状態のみから決まる
  - _Requirements: 3.1, 3.2, 3.3, 3.6, 5.4, 5.6_
  - _Boundary: phase actions, PhasePanel_
  - _Depends: 1.2, 2.1, 2.2_
- [x] 4.2 各フェーズ画面を自フェーズ定数とトピック購読から導出する
  - 各フェーズ画面で、自身のフェーズ番号（定数）とリアルタイム同期されたトピック状態から論理状態をリアクティブに導出して PhasePanel に渡す
  - 停止・再開・やり直すの各操作を操作群へ接続し、討論の再開が章インデックスから継続するようにする
  - リロードや別タブでもクライアント状態に依存せずトピックのみから表示が復元されることを担保する
  - 完了状態: 5画面すべてがコントローラ注入なしにトピック購読＋導出で表示し、リロード後も同一状態を再現する
  - _Requirements: 3.1, 3.4, 3.5, 4.3, 4.5, 5.2, 5.4_
  - _Depends: 4.1_
- [x] 4.3 (P) ルーティングと一覧から旧ステータス依存を除去する
  - フェーズルーティングの現在フェーズ算出を旧ステータス互換からトピックの現在フェーズ直接参照へ変更する
  - 一覧画面のバッジ算出から旧ステータスのフォールバックを削除し、トピックの `(phase, phaseStatus)` を直接用いる
  - 完了状態: ルーティングと一覧が旧ステータスを一切参照せずトピック状態のみで動作する
  - _Requirements: 1.1, 3.4, 5.6, 6.2_
  - _Boundary: Admin routing, TopicListPage_
  - _Depends: 1.1, 1.2_
- [x] 4.4 (P) 公開一覧の判定をタイムスタンプ基準に退避する
  - 公開トップの一覧フィルタを旧ステータス判定から公開タイムスタンプの有無へ置き換える（公開機能はオミット、enum 依存のみ除去）
  - 完了状態: 公開一覧が旧ステータスを参照せずビルド・表示できる
  - _Requirements: 6.1_
  - _Boundary: Public top page_
  - _Depends: 1.1_

- [x] 5. 検証: ユニット・統合・UI テスト
- [x] 5.1 状態導出のユニットテストを停止対応・ヒント撤廃で更新する
  - 論理状態導出が `(トピック状態, 対象フェーズ)` のみから、待機/実行中/生成完了/停止/承認済みを正しく返すことを検証する
  - 一覧ラベル/スタイル導出が停止を含む全状態で正しいこと、同一入力で一覧と各画面が一致することを検証する
  - 旧ヘルパー・ヒント引数に依存する既存テストを削除または書き換える
  - 完了状態: 純粋関数とラベル導出のユニットテストが緑で、ヒント引数を使うテストが残っていない
  - _Requirements: 1.2, 1.3, 5.1, 5.2, 5.3, 5.6, 5.7_
  - _Depends: 1.2_
- [x] 5.2 討論ゲートと終端の統合テストを追加・更新する
  - トピックを停止にするとオーケストレータが次ターン境界で停止し、以降の生成・上書きをしないことを検証する
  - 上流フェーズの再生成でフェーズが戻った場合も討論が停止することを検証する
  - 「実行中のときのみ生成完了」により停止が上書きされないこと、停止後の再開が章インデックスから継続することを検証する
  - 完了状態: セッションステータスに依存しない停止・完了・再開の統合テストが緑
  - _Requirements: 2.3, 4.2, 4.4, 4.5, 4.6, 4.7_
  - _Depends: 3.2, 3.3_
- [x] 5.3 リロードと固着回復のUIテストを更新する
  - リロード/別タブでクライアント状態に依存せずトピックのみから同一表示になることを検証する
  - 実行中固着および停止状態から全フェーズで「やり直す」により再実行・回復できることを検証する
  - コントローラ・実行中フラグに依存する既存コンポーネントテストを書き換える
  - 完了状態: 固着回復とリロード復元のUIテストが緑で、実行中フラグ参照のテストが残っていない
  - _Requirements: 3.3, 3.4, 3.6, 4.7_
  - _Depends: 4.2_
