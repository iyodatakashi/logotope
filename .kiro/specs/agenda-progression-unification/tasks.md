# Implementation Plan

- [x] 1. Foundation: 維持対象挙動の回帰テストを固定する
  - 章終了の既存条件（全論点 addressed による終了、未消化が残る間の早期終了取り消し、章ターン上限・全体上限のハード終了、章末の未応答指名に対する最終応答+1）を検証するテストが現行コードで通ることを確認し、不足があれば追加する
  - 撤去着手前に「壊してはいけない挙動」をテストで固定する（研究ログのリスク緩和方針）
  - 観測可能な完了条件: 上記4挙動の回帰テストが現行コードで green
  - _Requirements: 5.1, 5.2, 5.3, 5.4_

- [x] 2. 進行編成を「クールダウン→3値判定→行動」に再構成する
  - 進行評価を、クールダウン到達時に3値判定を1回実行し、結果で行動を一意に決める単層フローへ再構成する（ongoing は何もしない、drifted は引き戻し、exhausted はアクティブ論点を addressed 化して次論点を投入、未提示が残らなければ発言なしで addressed のみ永続して章終了へ渡す）
  - 立場カバレッジによる前進封じ・高意欲による前進抑止・指名チェーンによる前進禁止の各ゲート判定を進行編成から除去し、exhausted 判定を前進の十分条件にする
  - 介入トリガーの種別構築（指名なし／ペルソナ間指名／ファシリテーター指名の分岐）と種別ごとの別クールダウンを廃し、唯一の呼び出し元が末尾指名状態に関わらず単一クールダウンで進行評価を常時委譲するようにする（ファシリテーター発言直後はクールダウン未達で自然にスキップされる）
  - 前進直前に高意欲者の発言意図をキューへ積む既存処理は維持する（前進しても発言機会を保全する）
  - 引き戻しの指名先が有効な参加者IDでない場合は介入を採用せず継続する
  - 観測可能な完了条件: 高意欲な参加者が残る状態でも exhausted 判定で論点が addressed になり次論点が投入される。ongoing では状態変更・永続が発生しない
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 2.4, 3.1, 3.2, 3.3_

- [x] 3. Core: 立場カバレッジ機構と bring-in を撤去する
- [x] 3.1 (P) 発言コミット・オープニング経路のカバレッジ追跡を除去する
  - 発言確定後の共通後処理から、アクティブ論点への発言者記録とその永続呼び出しを除去する（論点ステータスの永続は遷移発生箇所に一本化する）
  - オープニング・章導入での論点提示から関連参加者リストの受け渡しを除去し、提示処理を論点インデックスのみで行うようにする
  - 論点ごとの発言済み集合・関連参加者の追跡関数（発言者記録・未発言関連参加者算出）を削除し、論点状態の永続出力からカバレッジ由来のフィールドを除外する
  - 観測可能な完了条件: 論点ステータスの永続結果にカバレッジ由来フィールドが含まれず、発言コミット時に発言済み集合が更新されない
  - _Requirements: 1.5, 4.2, 4.3_
  - _Boundary: agenda 状態モジュール, executeTurn / step.ts_
  - _Depends: 2_
- [x] 3.2 (P) bring-in 介入と関連参加者生成を撤去する
  - ファシリテーターの介入行動から bring-in（未発言の関連参加者を引き込む）の種別と発言生成分岐を削除し、介入行動を投入・引き戻しの2種に限定する
  - 論点投入・オープニング・章導入の各生成から関連参加者リストの出力（スキーマ項目と生成指示）を削除する。先頭論点を提示対象とする挙動は維持する
  - 観測可能な完了条件: 介入行動が投入・引き戻しの2種のみになり、投入・オープニング・章導入の出力に関連参加者リストが存在しない
  - _Requirements: 1.1, 3.1, 4.1, 4.3_
  - _Boundary: facilitator-agent_
  - _Depends: 2_

- [x] 4. 未使用の定数・ゲート関数・型フィールドを一掃する
  - 前進抑止に使っていた高意欲判定関数と、その閾値定数・指名チェーン用クールダウン定数を削除する
  - 論点状態型からカバレッジフィールド（発言済み集合・関連参加者）を、ファシリテーター応答型から関連参加者フィールドを削除する
  - 削除後にビルドが通り、死んだシンボルが残らないことを確認する
  - 観測可能な完了条件: 撤去対象のシンボル・型フィールドが存在せず、functions のビルドが green
  - _Requirements: 1.4, 2.3, 4.2, 4.3_
  - _Depends: 3.1, 3.2_

- [x] 5. Validation: テスト更新と回帰・互換検証
- [x] 5.1 進行系ユニットテストを書き換え、撤去系テストを削除する
  - 3値判定の各分岐（ongoing は無変更、drifted は引き戻しでステータス不変・指名先無効なら不採用、exhausted はカバレッジ・意欲に依らず addressed 化＋投入、未提示残なしで発言なしの章終了シグナル、クールダウン未達で判定を呼ばない）を検証するテストへ更新する
  - bring-in・カバレッジ追跡・指名チェーン別クールダウン・高意欲ゲートに関する既存テストを削除する
  - 観測可能な完了条件: 進行系ユニットテストが新挙動で green、撤去対象を検証するテストが存在しない
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 3.1, 3.2, 3.3, 4.1, 4.2, 4.3_
- [x] 5.2 回帰・互換の統合テストとフル検証を確認する
  - 末尾指名状態に関わらず単一の3値判定が実行されることを統合で検証し、旧形式のカバレッジフィールドを含む論点状態からの復元・続行がエラーなく行えることを検証する
  - Foundation で固定した章終了の回帰（全論点 addressed 終了・早期終了取り消し・上限・最終応答+1）が新実装でも通ることを確認し、functions のフルビルドとユニット・統合スイートが green であることを確認する
  - 観測可能な完了条件: 回帰・互換の統合テストが green、functions のフルビルドと全スイートが green
  - _Requirements: 2.2, 4.4, 5.1, 5.2, 5.3, 5.4_
  - _Depends: 4_
