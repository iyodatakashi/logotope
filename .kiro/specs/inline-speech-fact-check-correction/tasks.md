# Implementation Plan

- [x] 1. 基盤: 補正トレース型・再生成フィードバック型・タイムアウト定数を定義する
  - 補正トレース（検証状態 checked/unverified、補正有無、適用した指摘、補正前ドラフト）を表す型を追加し、ペルソナターンに任意の埋め込みフィールドとして保持できるようにする
  - 発言生成へ渡す「指摘フィードバック」（主張・判定・訂正・理由）の入力型を生成コンテキストに追加する
  - インライン検証の上限時間を表す定数（既定 120 秒）を定義する
  - フロントエンドのターン／ファクトチェック型にも同等の埋め込みフィールドを型として追加する（表示UIは変更しない）
  - 完了状態: 型・定数がビルドを通り、ターンに補正トレースを載せられる型基盤が揃っている
  - _Requirements: 4.1, 4.2, 4.3, 7.2_

- [x] 2. コア: 検証ロジックの content ベース化と再生成拡張
- [x] 2.1 (P) 検証コアを発言本文ベースに抽出し、既存の発言検証をその薄いラッパにする
  - 既存の発言検証（断定ゲート→グラウンディング→構造化→修正適否ジャッジ）を、発言本文・発言モード・話者種別を入力とするコア処理として切り出す
  - 既存の発言単位検証はコアを呼び出し、検出された指摘に対象発言IDを後付けするだけのラッパに退避させ、後追い検証の挙動を不変に保つ
  - 断定主張がない本文ではグラウンディングを起動せず指摘ゼロで即時通過することを、コア経由でも維持する
  - 完了状態: コア処理がドラフト本文だけで検証でき、既存の発言検証テストが回帰なく通る
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 7.1_
  - _Boundary: checkContent_

- [x] 2.2 (P) 指摘フィードバックによる発言再生成を生成処理に組み込む
  - 発言生成にフィードバック（誤った主張・判定・訂正・理由）が渡されたとき、それを踏まえて誤りを含まない発言を生成するよう生成指示を拡張する
  - 立場・口調・論旨方向性・指名整合を維持しつつ、訂正により結論が変わることは許容する旨を指示に含める
  - 検証不能の指摘は不確実性を含む表現に改めるか取り下げる方針を指示に含める
  - 既存の出力スキーマ・検索ツール構成は変更せず、フィードバック未指定時は従来どおりの生成結果になる
  - 完了状態: フィードバック指定時に補正された発言が返り、未指定時の生成は従来と同一であることがテストで確認できる
  - _Requirements: 3.1, 3.2, 3.3, 3.4_
  - _Boundary: generateTurn_

- [x] 3. インライン補正オーケストレーション（ドラフト検証→再生成→トレース構築）を新設する
  - ドラフト発言を検証コアで検証し、修正対象の指摘が無ければドラフトをそのまま採用する
  - 修正対象の指摘があれば再生成を1回だけ行い、再生成した発言と補正前ドラフト・適用指摘を含むトレースを返す
  - 検証は最大1巡・再生成は最大1回とし、再生成後の再検証は行わない
  - 検証がエラーまたは上限時間超過のときは未補正で採用し、未検証フラグを立てたトレースを返す
  - 再生成がエラーのときはドラフトを採用し、検出済み指摘を記録したトレースを返す（補正は断念）
  - 例外を呼び出し元へ伝播させず、常に「採用する発言＋トレース」を返す
  - 完了状態: 4分岐（指摘なし／補正成功／検証失敗／再生成失敗）それぞれで期待する発言とトレースが返ることがテストで確認できる
  - _Requirements: 1.4, 3.5, 6.1, 6.3, 6.4_
  - _Depends: 2.1, 2.2_
  - _Boundary: verifyAndReviseDraft_

- [x] 4. 結線: 発言生成ループへの組み込みとトレース永続化
- [x] 4.1 ペルソナ発言生成にドラフト分離と補正工程を挿入する
  - ペルソナ発言生成で、まずドラフトを生成し、討論が継続中であれば補正モジュールを経由してから正式登録するよう変更する
  - 検証文脈（テーマ名・章タイトル・フォーカス・基準日）を組み立てて補正モジュールへ渡せるよう、テーマ名を生成処理まで引き渡す
  - 補正後に採用された発言の内容で指名先の再検証・発言モード確定を行い、正式登録する
  - ファシリテーター発言は従来どおり検証を通さず直接登録する（経路分離で対象外）
  - 完了状態: ドラフトが検証・補正を経て正式登録され、補正済み発言のみが後続の話者選定・文脈に使われる
  - _Requirements: 1.1, 1.2, 1.3, 1.5, 6.2, 7.3_
  - _Depends: 3_

- [x] 4.2 補正トレースをターンに永続化する
  - 正式登録時に補正トレース（検証状態・補正有無・適用指摘・補正前ドラフト）をターンへ埋め込んで保存する
  - 補正なしで登録された場合・未検証で登録された場合も、その事実をトレースに残す
  - トレースは後追い結果ドキュメントとは別管理とし、既存の指摘データ構造と整合する形で保存する
  - 完了状態: 登録済みターンを読むと、どのように補正されたか（または未補正・未検証）が判別できる
  - _Requirements: 4.1, 4.2, 4.3, 4.4_
  - _Depends: 4.1_

- [x] 5. (P) 後追い検証でインライン検証済みターンを再グラウンディングしないようにする
  - 章の後追い検証で、インライン検証済み（checked）のターンはグラウンディングを起動しない
  - 補正済み（revised）ターンの埋め込み指摘は補正前ドラフトに対するもので本文と一致しないため、結果ドキュメントへ流さない（解決済みとして扱い、監査はトレースに留める）
  - 補正なし（revised でない）かつ指摘ありのターン（再生成失敗で原ドラフト登録）のみ、埋め込み指摘を対象発言IDに復元して結果へ反映する
  - 未検証（unverified）ターンとトレースの無い旧データのターンのみ、従来どおりグラウンディング検証する
  - 結果ドキュメントを単一の表示読取り面として維持し、同一発言に対する指摘が重複・矛盾しないようにする
  - 完了状態: 補正済み章の後追い実行でグラウンディングが再起動されず、補正済み発言に解決済み指摘が再提示されないことがテストで確認できる
  - _Requirements: 5.1, 5.2, 5.3, 5.4_
  - _Depends: 1_
  - _Boundary: checkChapter_

- [x] 6. 検証: 補正フローと後追い非重複の統合テストを追加する
  - ドラフト生成→検証→再生成→正式登録の結線で、補正済み発言が登録され指名先再検証・発言モード確定が正しく行われることを検証する
  - 検証失敗・再生成失敗時に討論生成が停止せず、未補正で登録され適切なトレースが残ることを検証する
  - 後追い検証がインライン検証済みターンを再グラウンディングせず、補正済みターンには解決済み指摘を再提示せず、未検証ターンのみ検証することを検証する
  - 完了状態: 上記シナリオを網羅する統合テストが通る
  - _Requirements: 1.1, 1.2, 1.3, 5.2, 5.3, 6.1, 6.2_
  - _Depends: 4.2, 5_
