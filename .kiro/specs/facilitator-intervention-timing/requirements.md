# Requirements Document

## Project Description (Input)
討論の流れの修正。ペルソナ同士の指名が多発しすぎて、いつまでも話が途切れない。もう少し適切なタイミングでファシリテーターに介入させたい。

## Introduction

討論では、ペルソナ発言が `targetedBy='persona'` で別ペルソナを指名すると、次ターンはその指名先に強制的に応答させる。現状、ファシリテーター介入は「末尾に指名がないとき（`step.ts` の `!targetPersona` ゲート）」のみ評価されるため、ペルソナ間の指名が連鎖している間はファシリテーターが一切介入できない。`evaluateTopicDrift` 自体は「指名済みターンでも上書きしうる」設計（`facilitator-agent.ts` のコメント）であるにもかかわらず、呼び出しゲートによって指名チェーン中は一度も評価されない。結果として指名の応酬が章の強制終了上限まで途切れず続く。

本仕様の本質的な解決策は、**ファシリテーター介入を指名チェーン中にも評価し、その判断軸を「論点ずれ（逸脱）」だけでなく「出尽くし（発展性のない応酬）」にも広げること**にある。指名チェーンでは、誰かの指摘・質問に無理やり答え、それにまた別の誰かが答える、という新たな発展のない応酬に陥りやすい。これはオンテーマのまま（逸脱ではない）かつ高活性（既存の「落ち着いた出尽くし」=低エンゲージメントでもない）で進むため、既存のドリフト介入・スタール介入のどちらでも捕捉できない。ファシリテーターが「もうこの応酬に発展性がない」と判断したときに、指名チェーンへ割り込んで引き戻し・次論点投入を行えるようにする。

逆に、逸脱でも出尽くしでもなく議論が本当に深まっている最中であれば、介入せずスルーする（内容駆動）。連続指名長は「長く続くほど出尽くしを疑う」ソフトなシグナルとして判断に渡すに留め、ターン数ベースの機械的な強制介入は設けない。討論が暴走しないための最終的な終了保証は既存のハードキャップ（`TURN_CAP_RATIO` / `AGENDA_TURN_CAP_RATIO` / `MAX_TURNS`）に委ねる。あわせて、ペルソナが過剰に指名し続けないよう発言生成側の抑制も扱う。既存の冪等性・世代分離は壊さない。

## Boundary Context

- **In scope**:
  - ファシリテーター介入を「末尾にペルソナ指名がある状態」でも評価する（`step.ts` の `executeTurn` 介入ゲートの緩和）
  - 介入の判断軸に「出尽くし（発展性のない応酬）」を加え、逸脱・出尽くしのいずれかで指名チェーンを上書きして引き戻し／次論点投入する
  - 連続指名長の計測と、「出尽くしを疑わせる」ソフトシグナルとしての利用
  - 介入による指名チェーン打ち切りと通常フローへの復帰
  - ペルソナ発言生成における過剰な（特に直前話者への）再指名の抑制（`persona-agent.ts`）
- **Out of scope**:
  - ターン数ベースの強制介入（機械的に一定間隔で介入する仕組みは設けない。終了保証は既存ハードキャップに委ねる）
  - 章末 +1 最終応答（freeze）フローでの指名先強制応答の変更
  - 既存のスタール介入（低エンゲージメント前提）の発火条件の変更
  - engagement スコアリング・話者選択（キュー/スコア）ロジックの再設計
  - Firestore スキーマ変更・フロントエンド表示の変更
- **Adjacent expectations**:
  - `facilitator-intervention-engagement-fix`（実装済み）の「介入発火イテレーションはファシリテーターターンのみ保存し、メンバー応答は次ターン」の順序保証を維持する
  - 既存のドリフト介入（`evaluateTopicDrift`）と介入クールダウン（`DEFAULT_INTERVENTION_COOLDOWN`）の枠組みを再利用する

## Requirements

### Requirement 1: 指名チェーン中のファシリテーター介入評価（本機構）

**Objective:** As a 討論の閲覧者, I want ペルソナ同士が指名し合っている間でもファシリテーターが介入を評価できる, so that 逸脱や発展性のない応酬に割り込んで流れを整理できる

#### Acceptance Criteria

1. When 末尾ターンが `targetedBy='persona'` のペルソナ指名で、かつ介入クールダウンを満たしている, the 討論オーケストレーター shall 指名先への強制応答の前にファシリテーター介入を評価する
2. If 介入が発火する（content と targetPersonaId を返す）, then the 討論オーケストレーター shall 末尾のペルソナ指名を上書きしてファシリテーター介入ターンを保存し、同イテレーションでペルソナ応答を生成しない
3. If 介入が発火しない（逸脱でも出尽くしでもないと判断された）, then the 討論オーケストレーター shall 末尾の指名先ペルソナに応答させて流れを継続する
4. While 介入クールダウン（直近ファシリテーター発言からのペルソナ発言数 < `DEFAULT_INTERVENTION_COOLDOWN`）を満たさない, the 討論オーケストレーター shall 介入を評価せず指名先ペルソナに応答させる
5. When 末尾ターンが `targetedBy='facilitator'` の指名である, the 討論オーケストレーター shall 介入を評価せずその指名先に応答させる

### Requirement 2: 出尽くし（発展性のない応酬）の検知と介入

**Objective:** As a 討論コンテンツの編集者, I want ファシリテーターが「逸脱」だけでなく「もう発展性のない応酬」も判断して介入する, so that 無理やり答え合うだけの応酬が延々と続くのを止められる

#### Acceptance Criteria

1. When 指名チェーン中の介入を評価する, the ファシリテーターエージェント shall 「フォーカス問いから逸脱しているか」に加えて「この応酬に新たな発展性が残っているか（指摘・質問に無理やり答えるだけの往復になっていないか）」を判断軸として評価する
2. If 逸脱している, then the ファシリテーターエージェント shall フォーカス問いへ引き戻す介入を行う
3. If 逸脱はしていないが応酬に発展性がない（出尽くし）, then the ファシリテーターエージェント shall 未完了論点を1件投入する（未完了論点が無ければ引き戻し・振り直しを行う）介入を行う
4. When 介入が未完了論点を投入する, the 討論オーケストレーター shall 当該論点を introduced に更新する（既存挙動を維持）
5. While 議論が本題に沿って新たに深まっている最中である, when 介入を評価する, the ファシリテーターエージェント shall 介入を見送り指名チェーンを継続させる（過剰介入の防止）

### Requirement 3: 連続指名チェーン長の計測とシグナル化

**Objective:** As a 討論パイプラインの設計者, I want ペルソナ同士の連続指名チェーンの長さが把握され出尽くし判断に渡される, so that 応酬が長引くほどファシリテーターが出尽くしを疑いやすくなる

#### Acceptance Criteria

1. When 次ターンの介入を決定する, the 討論オーケストレーター shall 章ローカルの永続ターン列末尾から遡り、`targetedBy='persona'` の指名が連続している長さを連続指名チェーン長として算出する
2. When 末尾ターンがファシリテーター発言、または指名を伴わないペルソナ発言、または `targetedBy='facilitator'` の指名である, the 討論オーケストレーター shall 連続指名チェーン長を 0 とみなす
3. When 介入を評価する, the ファシリテーターエージェント shall 連続指名チェーン長を文脈シグナルとして受け取り、長いほど出尽くしと判断する側に寄せる
4. The 討論オーケストレーター shall 連続指名チェーン長を永続ターン列のみから決定論的に算出し、メモリ上の状態に依存しない

### Requirement 4: 終了保証は既存ハードキャップに委ねる

**Objective:** As a 討論パイプラインの保守者, I want 介入が機械的な一定間隔にならず、暴走時の終了は既存の上限で保証される, so that 内容駆動の介入と確実な終了を両立できる

#### Acceptance Criteria

1. The 討論オーケストレーター shall ターン数（連続指名長）に基づく強制介入を設けず、介入の発火可否はファシリテーターの逸脱・出尽くし判断にのみ委ねる
2. The 討論オーケストレーター shall 介入が一度も発火しない場合でも、既存の章強制終了上限（`TURN_CAP_RATIO`／`AGENDA_TURN_CAP_RATIO`）・全体ターン上限（`MAX_TURNS`）による終了保証を維持する

### Requirement 5: 介入後のチェーンリセットと流れの復帰

**Objective:** As a 討論パイプラインの設計者, I want ファシリテーター介入後に連続指名状態がリセットされ通常フローに戻る, so that 介入が一度きりで終わり再び自然な議論に復帰する

#### Acceptance Criteria

1. When ファシリテーター介入ターンが保存される, the 討論オーケストレーター shall 末尾の未応答ペルソナ間指名を解消し、次ターンの連続指名チェーン長を 0 として扱う
2. When 介入ターンがペルソナを指名している（`targetedBy='facilitator'`）, the 討論オーケストレーター shall 次ターンでその指名先に応答させ、それをペルソナ間連続指名チェーンに含めない
3. When 介入ターンが誰も指名していない, the 討論オーケストレーター shall 次ターンの話者を通常のキュー／スコア選択で決定する

### Requirement 6: ペルソナによる過剰な指名の抑制

**Objective:** As a 討論の閲覧者, I want ペルソナが必要なときだけ相手を指名する, so that そもそも指名の多発が減り議論が一方向に偏りにくくなる

#### Acceptance Criteria

1. When ペルソナ発言を生成する, the ペルソナエージェント shall 自分の発言内容が特定の参加者に直接関係しない場合は `targetPersonaId` を指定しないよう指示される
2. While 直前に自分が他ペルソナから指名されて発言している, when ペルソナ発言を生成する, the ペルソナエージェント shall 直前話者への再指名を、直接の確認・反論が必要な場合に限定するよう指示される
3. If 採用された発言の `targetPersonaId` が自分自身、または参加者リストに存在しないIDである, then the 討論パイプライン shall 指名を無効化し指名なしの発言として扱う（既存挙動を維持）

### Requirement 7: 既存の終了・冪等性・分離保証の維持

**Objective:** As a 討論パイプラインの設計者, I want 介入タイミング変更が既存の終了条件・冪等性・世代分離を壊さない, so that チェーン駆動の安定性と再入可能性が保たれる

#### Acceptance Criteria

1. The 討論オーケストレーター shall 早期終了（`QUIET_STREAK_LIMIT`）・論点カバレッジ補正の既存挙動を変更しない
2. When 同一 frontier を狙う複数タスクが並走する, the 討論オーケストレーター shall 追記トランザクションの単一勝者規則と `runId` 世代照合を維持し、二重の介入ターンを生成しない
3. While 章末 +1 最終応答（freeze）フローを実行している, the 討論オーケストレーター shall 指名チェーンによる介入判定を適用せず、従来どおり指名先に最終応答させる
4. The 討論オーケストレーター shall 本仕様で追加する指名チェーン経路以外では、既存のドリフト介入・スタール介入・介入クールダウンの発火条件を変更しない
