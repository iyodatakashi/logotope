# Implementation Plan

- [x] 1. 配色計算の基盤
- [x] 1.1 パレット計算モジュールを実装する
  - `@14ch/color-palette-generator` を依存に追加する
  - スクロール量と画面高から色相角を返す変換を用意する。1 画面スクロールするごとに一定量だけ回り、記事件数やページの高さに依存しない
  - 色相角を間引き幅で量子化する変換を用意する
  - 色相角からパレットを生成し、各段を OKLCH 記法の文字列として CSS カスタムプロパティのレコードにまとめる。生成はライブラリに任せ、色空間の変換を自前で書かない
  - 色を明度・彩度・色相へ分解して個別に扱わない。段ごとに 1 つの色として保つ
  - 色相の起点・1 画面あたりの変化量・間引き幅・パレット生成の設定を、このモジュールの名前付き定数として公開する
  - 完了条件: 任意のスクロール量と画面高を渡すと、11 段ぶんの OKLCH 記法の色を持つレコードが返る
  - _Requirements: 5.3, 5.5, 5.6, 5.7, 5.10, 5.12, 5.14, 5.19, 5.20, 5.24_

- [x] 1.2 パレット計算のユニットテストを書く
  - 色相角がスクロール量に対して単調に増え、同じ入力に同じ値を返す
  - 1 画面ぶんスクロールすると設定した度数だけ回る。画面高が 0 のときは起点の色相を返す
  - 量子化が刻み幅の内側では同じ値を返し、跨いだときだけ変わる
  - 返るレコードが 11 段ぶんで、値がすべて OKLCH 記法であり HEX を含まない
  - 色相を変えると段ごとの明度・彩度も変わる（色を分解していないことの回帰検知）
  - 完了条件: 上記がテストとして通り、パレット計算が実装に依存せず検証できる
  - _Requirements: 5.3, 5.6, 5.12, 5.14, 5.19, 5.20_

- [x] 2. ページの骨格
- [x] 2.1 2 領域レイアウトと取得状態の表示を組む
  - 公開ページ共通の枠の使用をやめ、紹介領域と記事が流れる領域の 2 領域で構成する
  - 紹介領域はスクロールしても画面内に留まる。狭い縦長画面では単一カラムに切り替え、紹介領域を圧縮して記事の領域に画面の大半を割り当てる
  - 読み込み中・記事 0 件・取得失敗を記事の領域の中に描画する。失敗時は全体エラーページへ遷移せず、紹介領域を保ったまま失敗と次の行動を伝える
  - ページのタイトル・説明・OGP を提供する。管理機能への導線を描画しない
  - 管理用コンポーネントを流用しない
  - ルート配下のファイルは feature コンポーネントを差し込むだけの最小ラッパーのまま保ち、マークアップを持たせない
  - 完了条件: 3 つの状態のいずれでも紹介領域が描画されたままページが成立する
  - _Requirements: 1.1, 1.3, 1.4, 6.1, 6.2, 6.3, 6.4, 7.2, 7.4, 9.4, 10.3, 10.6_

- [x] 2.2 (P) 紹介領域を実装する
  - サービス名をページ唯一の見出しとして置き、サービスの位置づけを示す短い説明文を添える
  - 狭い縦長画面では圧縮された形で成立する
  - 見た目のためだけの修飾タグを使わず、文書構造として正しいマークアップにする
  - 完了条件: ロゴと概要文が紹介領域に表示され、見出し階層が記事タイトルと矛盾しない
  - _Requirements: 1.2, 1.4, 7.2, 8.5_
  - _Boundary: PublishedArticleListIntro_

- [x] 2.3 (P) 記事に対応しない円を置かないことを保証する
  - 画面に現れる円はすべて公開済み記事に対応させ、模様としての円を描かない
  - 記事に対応しない要素を支援技術のツリーに出さず、操作対象にもしない
  - 完了条件: 円の数が記事の件数と一致し、支援技術から隠される要素が存在しない
  - _Requirements: 5.1, 5.2, 8.4, 10.4_
  - _Note: 当初は背景に装飾の円を漂わせる計画だったが、「円はすべてトピックに対応する」というユーザーの判断により削除した（PublishedArticleListDecoration は廃止）_

- [x] 3. 記事を円として表現する
- [x] 3.1 円としての表示とリンクを実装する
  - 記事 1 件を 1 つの円として描き、内側に全記事共通の種別ラベル・タイトル・公開日を置く
  - タイトルが長い場合も円の内側に収め、円の形状を崩さない
  - 円全体を記事ページへの遷移導線にする
  - 記事ごとに表示を独立させ、ある記事の情報量が他の円に影響しない状態にする
  - 寸法は標準サイズの 1 通りだけを定義する。形状名ではなく意味づけされた既存のコンポーネント名・Block 名を維持する
  - 完了条件: 記事の円が一覧に並び、選択するとその記事ページへ遷移する
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 7.3, 8.5, 9.1, 9.2_

- [x] 3.2 スクロール連動の変倍・配置・重なりを実装する
  - 円が画面下部から上部へ移動する過程で、下部では縮小、中央付近で標準、上部で再び縮小して消えるようにする。上方向のスクロールでは対応する状態へ戻る
  - 変倍は円と内側の要素をまとめて行い、直径と内側テキストのサイズ比を拡大率によらず一定に保つ。直径とフォントサイズを個別に算出しない
  - 各円の水平位置を記事ごとに一定にする。乱数を使わず、サーバ描画とクライアント描画で一致させる
  - レイアウト上のスロット高を直径より小さく取ることで円を重ねる。重ならないための位置調整は行わない。手前の円の内側は読み取れる状態に保つ
  - 一覧の前後に余白を置き、先頭と末尾の記事の円も画面中央（標準サイズ）まで到達できるようにする
  - フォーカスによるスクロールの着地点を画面の端から離し、フォーカスした円が標準サイズで表示されるようにする
  - スクロール駆動アニメーション未対応時と動きの抑制時は等倍表示にフォールバックし、リンクと情報を完全に保つ
  - 完了条件: スクロールに応じて円が下から上へ通り過ぎながら変倍し、先頭・末尾を含むすべての円が中央で標準サイズになる
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8, 3.9, 3.10, 3.11, 3.12, 4.4, 7.1, 8.2, 8.3, 8.4, 10.4_

- [x] 4. 配色の適用と統合
- [x] 4.1 役割変数とデザイン値を 1 か所に集約する
  - 背景・円の面・円の中のテキスト・種別ラベルと公開日・ロゴと概要文の色を、意味づけされた役割変数として定義する
  - 役割変数から段への割り当てと、パレット未適用時のフォールバック色を 1 つのブロックにまとめ、ユーザーが編集する前提であることを明示する
  - 円の標準直径・縮小率・スロット高・前後の余白・色の移行にかける時間も同じ場所に集める
  - 色・寸法・余白・フォントサイズ・アニメーションの数値をコンポーネント側に直書きしない。既存の公開コンポーネントに残る直書きも解消する
  - 完了条件: 見た目に関わる値がこの 1 ブロックにのみ存在し、他のセレクタは役割変数を参照するだけになっている
  - _Requirements: 5.11, 5.22, 9.1, 9.3, 9.5_
  - _Depends: 2.1, 2.2, 2.3, 3.1, 3.2_

- [x] 4.2 スクロールに連動した配色の適用を実装する
  - スクロール量と画面高から色相を求め、量子化した値が変わったときだけパレットを作り直してページのルート要素へ書き込む。スクロールイベントごとには再生成しない
  - 背景・円の面・円の中のテキスト・ロゴ・概要文の色をすべて同じパレットから取り、一体で追従させる
  - 色を実際に適用する各要素に移行アニメーションを掛ける。フレームごとの色計算を自前で行わず、移行はブラウザに委ねる。移行の途中で次の色が来ても現在の表示色から続ける
  - 動きの抑制が設定されている場合はパレットを書き換えず、フォールバック色（起点の色相）で固定する
  - 特定の色相を基調色として固定せず、閲覧の過程で複数の色相を巡る状態にする
  - 完了条件: スクロールすると背景と文字を含む配色全体が滑らかに移り変わり、動きの抑制時は起点の色相で固定される
  - _Requirements: 5.4, 5.8, 5.9, 5.13, 5.15, 5.16, 5.17, 5.18, 5.21, 5.22, 5.23_
  - _Depends: 1.1, 4.1_

- [x] 4.3 一覧の描画と順序を通す
  - 取得済みの記事すべてを 1 度だけ円として描き、同じ記事を繰り返し循環させない
  - 公開日時の新しい順で並べる（既存の取得処理の順序をそのまま用いる）
  - 最後の記事が流れ終わったところをスクロールの終端とし、それを超える空のスクロール領域を作らない
  - すべての記事へのリンクを、円の表示位置にかかわらず文書構造として提供する
  - 完了条件: 公開済み記事が新しい順に円として流れ、最後の記事の先にスクロールが続かない
  - _Requirements: 4.1, 4.2, 4.3, 8.1_
  - _Depends: 3.2_

- [x] 5. 検証と非回帰
- [x] 5.1 円のコンポーネント spec を更新する
  - 種別ラベル・タイトル・整形済みの公開日が円の内側に表示される
  - リンク先が記事ページの URL になる
  - 水平位置の決定に使う値が同じ入力に対して同じになる
  - 完了条件: 既存の spec が新しい円の表現に追従し、テストが通る
  - _Requirements: 2.2, 2.3, 3.6_

- [x] 5.2 配色の可読性を実測する
  - 色相を一定間隔でサンプリングし、円の中のテキスト・ロゴ・概要文のコントラスト比を測る
  - どの色相でも可読性が保たれることを確認する。不足があれば役割変数の段の割り当てを見直す
  - 間引き幅を変えたときに移行の中間色にくすみが知覚されるかを確認し、許容できる刻みの上限をコメントとして残す
  - 完了条件: 全サンプル色相で可読性の基準を満たし、刻み幅の妥当な範囲が記録されている
  - _Requirements: 5.9, 5.13, 5.20_
  - _Depends: 4.2_

- [x] 5.3 到達性と縮退表示を検証する
  - キーボードだけですべての記事へ到達でき、フォーカス位置が視覚的に分かり、画面外の円へ移動したときに標準サイズで着地する
  - 動きの抑制を有効にすると、変倍が止まり、配色が起点の色相のまま変わらない
  - スクロール駆動アニメーション未対応の環境で、等倍表示になってもすべての記事へ到達できる
  - 狭い縦長画面で、変倍が維持され、紹介領域が圧縮され、円の内側の情報が読み取れ、タッチスクロールで操作できる
  - 完了条件: 上記いずれの条件でも記事一覧としての到達性と可読性が失われない
  - _Requirements: 7.1, 7.2, 7.3, 7.4, 8.1, 8.2, 8.3, 8.4, 8.5_

- [x] 5.4 公開挙動の非回帰を確認する
  - 未認証のブラウザで開き、公開済みの記事のみが表示され、非公開の記事が現れない
  - サーバ描画の HTML に記事データとメタ情報が含まれ、クライアント描画後も内容が一致する
  - 記事の取得経路が公開専用の初期化のみを用い、認証や関数呼び出しに依存していない
  - 記事 1 件・0 件の場合に空のスクロール領域が生じない
  - 完了条件: リデザイン前と同じ条件で記事へ到達でき、検索・共有向けの情報が失われていない
  - _Requirements: 4.4, 10.1, 10.2, 10.3, 10.4, 10.5_

- [x]* 5.5 ページの状態表示のコンポーネント spec を追加する
  - 取得失敗・0 件・通常の 3 状態が記事の領域の中に描画される
  - いずれの状態でも紹介領域が描画される
  - 完了条件: 3 状態の分岐がテストで固定され、以後の変更で崩れないことを検知できる
  - _Requirements: 6.2, 6.3, 6.4_
