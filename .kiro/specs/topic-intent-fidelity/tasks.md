# Implementation Plan

- [x] 1. 立場と人物の型に所在と3軸を持たせる
- [x] 1.1 立場の型に所在・当事者性・当事者である理由を持たせる
  - 当事者性の段階を、少数性・専門や意識の高さとは独立した第3の軸として型に加える
  - 所在を、国（自由記述）と都道府県（47件の有限集合）の2つの任意項目として加える。どちらも値を持たないことを許す
  - 当事者である理由を必須項目として持たせ、従来の「理由」から名前を改める
  - 専門や意識の高さを必須項目に改め、型だけが任意になっていた欠損分岐を消す
  - フロントエンドのミラー型を同じ形に揃える
  - 完了条件: バックエンドとフロントエンドの立場の型が一致し、所在・3軸・理由を持つ状態で型検査が通る
  - _Requirements: 2.4, 2.6, 3.1_

- [x] 1.2 (P) 人物の型の所在を任意の2項目に改める
  - 必須だった居住都道府県と国籍を、都道府県（有限集合）と国（自由記述）の任意項目へ改名する
  - 空文字で「値が無い」を表す運用をやめ、値を持たない状態を項目の不在で表す
  - フロントエンドのミラー型と、公開表示型に所在を持ち込まないことを検査している既存テストを新しい項目名へ追随させる
  - 完了条件: 人物の所在が2つの任意項目になり、公開表示型に所在が現れないことをテストが機械的に保証する
  - _Requirements: 4.2, 6.4_
  - _Boundary: Persona 型（BE / FE ミラー・公開表示型）_

- [x] 2. テーマの共通前提の整形を1本に集約する
- [x] 2.1 共通前提を整形する唯一の関数を新設する
  - テーマの詳細説明・参考資料・確定した事実を1つの節に組み立てる関数を、共有の整形置き場に新設する
  - 見出しは最も強い形（方向性を最優先として提示する形）に統一し、呼び出し側で重みを切り替える引数を持たせない
  - 本文から工程固有の語（論点・章立て等）を外し、どの工程に載せても文脈が合う一般形にする
  - 参考資料を切り詰めない。上限は取り込み時に決まっているため、保存されている本文をそのまま載せる
  - 詳細説明・参考資料が未設定なら該当の節を出さず、空文字へ縮退する
  - 完了条件: 同じ入力に対して常に同一の文字列を返し、未設定時は空文字になることを単体テストが示す
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_

- [x] 2.2 既存3工程の自前整形を共有へ置き換える
  - 論点・章立て、取材、導入締めが各自持っている整形を削除し、共有の整形を呼ぶ形に統一する
  - 取材と導入締めが独自に持っていた参考資料の字数上限を撤廃する
  - 文言が変わる3工程のプロンプト期待値テストを更新し、方向性が最優先として提示され続けることを検査する
  - 完了条件: 共通前提の整形がリポジトリに1本だけ存在し、5工程すべてがそれを呼ぶ
  - _Requirements: 1.3, 6.5_

- [x] 3. キャストを決める2段を改訂する
- [x] 3.1 立場の選定基準を「問われていることへの当事者性」へ移す
  - 詳細説明・参考資料を共通前提として受け取り、立場の選定に反映させる
  - 「直接・間接の全利害関係者を網羅的に」という拡散の指示を撤去し、そのテーマで問われていることへの当事者性を選定基準に据える
  - 題材領域一般にのみ当事者である立場を選ばないこと、主題となる当事者群を単一の立場に畳まず複数の具体的な立場へ分解することを指示する
  - 各立場に、問われていることに対してどう当事者かを理由として出力させる
  - 当事者性・少数性・専門や意識の高さを独立に付けさせ、専門や意識の説明から「当事者」の語を外して軸の混同を解く
  - 射程を絞ったうえで、その射程内の少数性・専門や意識の幅・生活者目線の一般層を満たすよう指示する
  - テーマの舞台に基づいて所在を決めさせ、特定の国を既定としない。テーマが決めていない項目は値を持たせない。複数の国にまたがるテーマでは立場ごとに国を選ばせる
  - 件数・比率の固定値で割り当てず、当事者の分布に応じた構成にさせる（下限のみ維持し上限は置かない）
  - 理由と3軸を必須、所在の2項目を任意として生成スキーマで強制する。都道府県は有限集合として受け取り、表記ゆれが起きない形にする
  - 完了条件: 拡散の指示がプロンプトから消え、詳細説明・参考資料が載り、理由と3軸が欠けた出力がスキーマで弾かれることを単体テストが示す
  - _Requirements: 1.1, 1.4, 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 3.1, 3.2, 3.5_

- [x] 3.2 (P) 人物生成の国籍既定を撤廃し、立場の所在を引き継ぐ
  - 詳細説明・参考資料を共通前提として受け取り、人物像の設定に反映させる
  - 「基本的には日本人」「海外は例外」という既定の構造をプロンプトから削除する
  - 立場の全項目（立場・理由・関心事・所在・3軸）をプロンプトへ渡し、死蔵を解消する
  - 立場が所在を持つとき、生成後にコードがその値を採用し、生成結果で上書きしない。立場が空にした項目だけを生成結果から採ることで、別の国の相当職への翻案が構造的に起きない状態にする
  - 立場が土地を決めていない人物に、土地を推測で埋めさせない
  - 日本語の姓名の人物は姓を空で返させる指示を残し、姓の割り当ては既存の仕組みに委ねる。都道府県があればその地域の語彙から、無ければ全国の語彙から姓を引く
  - 都道府県が有限集合で渡るため、表記ゆれを吸収する正規化処理を生成経路から外す
  - 出自として自然な氏名、同一キャスト内での表記形式の一貫性、出自によらない生活の細部の具体性を指示する
  - 立場の具体化・専門や意識レベルに応じた描き分け・性のあり方の2軸・架空の一人の人物であることという既存の要求を保持する
  - 完了条件: 立場が所在を持つ場合に生成結果が別の所在を返してもペルソナの所在が立場の値になることを単体テストが示し、「基本的には日本人」の記述がプロンプトに存在しない
  - _Requirements: 1.1, 1.4, 3.2, 3.3, 3.4, 3.6, 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 6.1, 6.2, 6.3_
  - _Depends: 1.1, 1.2, 2.1_
  - _Boundary: PersonaGenerator, SurnameAssignment_

- [x] 4. 下流と既存スクリプトを新しい項目名へ追随させる
- [x] 4.1 (P) アバター生成の経路を新しい所在の項目へ追随させる
  - 人物から受け取る仕様・生成エンジン・プロンプト組み立ての3段すべてで、国籍を国の任意項目へ改める
  - 国が無い人物では服装の手がかりの括弧書きを出さない。空文字で埋めて欠損を隠す分岐を新しい項目へ持ち越さない
  - アバター生成の検証スクリプトの固定値を追随させる
  - アバタープロンプトの既存テストを更新し、国が無い人物で括弧書きが出ないことを検査する
  - 完了条件: 国を持たない人物でもアバター生成が破綻せず、プロンプトに空の括弧が現れない
  - _Requirements: 6.4_
  - _Depends: 1.2_
  - _Boundary: Avatar（仕様・エンジン・プロンプト）_

- [x] 4.2 (P) 既存の姓・居住地スクリプトを追随させる
  - 旧項目名を読んでいる2本の移行スクリプトを、実行済みの記録として冒頭に位置づけを明記したうえで新しい項目名へ追随させ、ビルドを通す（削除しない）
  - 氏名の分布を確認するスクリプトを、都道府県別に加えて日本語の氏名か否かでも出せるよう拡張する
  - 完了条件: 旧項目名を参照するコードがリポジトリから無くなり、氏名の分布が出自の別でも取得できる
  - _Requirements: 4.1, 6.4_
  - _Depends: 1.2_
  - _Boundary: scripts_

- [x] 5. 既存ペルソナの所在を移行する
- [x] 5.1 所在フィールドの改名を行う移行スクリプトを新設する
  - 全テーマの人物について、居住都道府県を都道府県へ、国籍を国へ移し、旧項目を削除する
  - 値の解釈を伴わない改名とし、空文字だった項目は未設定にする。国外の人物の国を捨てない
  - 書き込みを伴わない計画表示を既定とし、明示の指定があるときだけ適用する既存の移行スクリプトの型を踏襲する
  - 旧項目を持たない人物を対象外とし、中断後の再実行で同じ結果になるようにする
  - 完了条件: 計画表示で対象件数と、都道府県の正式表記として読めない値の一覧が出力される
  - _Requirements: 6.4_

- [x] 5.2 移行を計画表示で確認し、承認のうえ適用する
  - 計画表示を実行し、対象件数と手動判断が要る値の件数を確認する
  - 手動判断が要る値は推測で埋めず、根拠を添えて列挙し、扱いを決めてから進める
  - 適用の実行はユーザーの承認を得てから行う
  - 完了条件: 適用後に旧項目を持つ人物が0件であり、都道府県の値がすべて有限集合に含まれることを確認できている
  - _Requirements: 6.4_

- [x] 6. キャスト構成の検証ハーネスを新設し、旧ハーネスを撤去する
  - テーマ文（タイトル必須・詳細説明任意）を受け取り、本番と同一の立場生成・人物生成を順に通す。検証専用の生成経路を持たない
  - 立場を固定したモードを持たず、生成された立場をそのまま検査対象にする。国内向け・国外向けの既定テーマを1本ずつ持ち、引数なしでも両方の観点を確認できるようにする。国内の既定テーマは地域に結びつく立場が確実に出るものを選ぶ
  - 機械判定は生成結果を対象とする項目に限る（都道府県を持つ人物に該当地域の姓が引かれているか、日本語の姓名の人物が姓を空で返しているか、表示名の形式）。コードが確定させる所在の引き継ぎは検査しない
  - 各検査を何件に対して実施したかを出力し、0件（そのテーマで地域性が問われなかった）と未実施を読み手が区別できるようにする
  - 人手判定のために、立場ごとの当事者である理由・3軸の分布・所在・氏名・背景の冒頭を提示する。舞台の人物として自然か、問われていることの当事者が場にいるかは判定せず提示する
  - Firestore へ書き込まない。旧ハーネス（日本人の命名に閉じた固定立場リストのもの）を削除する
  - 完了条件: 引数なしの実行で国内・国外の両テーマについて、機械判定の結果（実施件数つき）と人手判定用の一覧が標準出力に出る
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5_

- [x] 7. 結線と回帰を確認する
  - 立場の生成から人物の生成へ至るチェーンで、立場の属性（所在を含む）が人物生成へ届き、由来の突合が維持されることを統合テストで確認する
  - バックエンドとフロントエンドの立場・人物の型が一致することを型テストで確認する
  - 固定値に旧項目名を含む既存テスト群を新しい項目名へ揃え、全テストを通す
  - 完了条件: 全テストが通り、旧項目名がリポジトリのどこにも残っていない
  - _Requirements: 6.3, 6.4_
