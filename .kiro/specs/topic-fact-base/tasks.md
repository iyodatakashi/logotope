# Implementation Plan

- [x] 1. フェーズ挿入基盤（fact-research をフェーズモデルに追加）
- [x] 1.1 FE フェーズモデルに fact-research を先頭挿入する
  - `PhaseSlug` に `fact-research` を追加し、`PHASE_DEFS` の先頭に label＋statusLabels を持つエントリを入れる
  - 新規トピックの初期フェーズを `fact-research` にし、承認遷移 `approveFactResearch` を `nextPhase` 前進で追加する
  - FE の正準リスト self-check・ラベルスナップショットを 7 フェーズ構成へ更新する
  - 完了状態: 新規トピックが `fact-research` 先頭で作成され、StepNav 先頭に事実リサーチが表示され、FE フェーズテストが緑
  - _Requirements: 2.1, 3.4_

- [x] 1.2 BE フェーズモデルに fact-research を追加する
  - `PhaseKey` と生成確定部分集合 `GeneratePhase` に `fact-research` を追加する
  - BE の正準リスト self-check（`PhaseKey`/`GeneratePhase`）を更新する
  - 完了状態: フェーズ確定ヘルパーが `fact-research` を受理し、BE フェーズ self-check テストと tsc が緑
  - _Requirements: 2.1_

- [x] 2. 事実基盤データ型を FE/BE 対称に定義する
  - 事実（statement＋出典）・事実基盤（facts＋生成基準日）・その Firestore 永続型を FE/BE 双方で定義する（型と型ガードのみ）
  - 共有コンテキスト型に事実基盤フィールドを FE/BE 双方で追加し、ユーザー提供資料とは別データとして扱う
  - 完了状態: FE/BE 双方でコンテキスト型が事実基盤を保持でき、tsc が緑
  - _Requirements: 3.1, 3.3, 9.1_
  - _Boundary: FactBase types_

- [x] 3. (P) 事実リサーチ生成エージェントを実装する
  - 現在日付を基準に Google Search Grounding で客観的事実（出来事・結果・数値・固有名詞・日付）を収集し、既存の出典抽出・リダイレクトURL解決を経て構造化する
  - 主観的な立場・信念・評価を含めず検証可能な具体的事実に限定する
  - grounding が事実を返さない／時事性が無い場合は捏造せず事実基盤を空として返す
  - 完了状態: タイトルと現在日付から事実基盤を返し、grounding 空時に空の事実集合を返すユニットテストが緑
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6_
  - _Depends: 2_
  - _Boundary: fact-research-agent_

- [x] 4. 事実リサーチ API を実装し永続とフェーズ確定を配線する
  - 事実リサーチを onCall で実行し、生成した事実基盤をユーザー提供資料とは別のサブコレクション文書に生成基準日・出典付きで永続する
  - 永続成功後、running 限定・冪等でフェーズを生成済みに確定する
  - 再実行時は承認前の事実基盤を再生成する
  - 完了状態: 呼び出しで事実基盤文書が保存されフェーズ状態が生成済みに確定する統合テストが緑
  - _Requirements: 1.1, 2.3, 2.7, 3.1, 3.2, 3.3_
  - _Depends: 1.2, 2, 3_
  - _Boundary: api/fact-research_

- [x] 5. (P) 事実基盤を合成する BE 権威コンテキスト経路を実装する
  - トピック文書と事実基盤文書を読み、テーマ説明・参考資料・事実基盤を含む共有コンテキストを合成する唯一の経路を用意する
  - 事実基盤が不在なら事実基盤未設定で返し、テーマ説明・参考資料は現行合成を踏襲する
  - 全消費者が同一の事実基盤を得る（フェーズ別分岐を持たない）
  - 完了状態: 事実基盤あり／なしで正しい共有コンテキストを返すユニットテストが緑
  - _Requirements: 4.1, 5.1, 6.1, 7.1, 8.1, 9.1, 9.3_
  - _Depends: 2_
  - _Boundary: getTopicContext_

- [x] 6. 事実リサーチ画面と承認導線
- [x] 6.1 (P) 事実基盤ストアを実装する
  - 事実基盤文書を購読し、管理者の編集内容を保存する
  - 完了状態: 画面が事実基盤の各事実・出典を表示・編集・保存でき、保存が永続に反映される
  - _Requirements: 2.4, 3.4_
  - _Depends: 2_
  - _Boundary: factBase store_

- [x] 6.2 事実リサーチ画面・空承認導線・承認遷移を実装する
  - 事実リサーチ画面（実行・確認・編集・承認）とルートを追加する
  - 状態別アクション表示に「実行せず承認（空確定）」の導線を未実行状態で追加する（他フェーズは既定で不変）
  - 承認で事実基盤を確定し次フェーズ（ステークホルダー）へ前進する。実行せず承認した場合は空の事実基盤で確定して同じ経路で前進する
  - 未承認の間はステークホルダー以降のフェーズへ進めない
  - 完了状態: 実行→編集→承認、および実行せず承認の両経路でステークホルダーへ前進し、未承認では先へ進めない
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 3.4_
  - _Depends: 1.1, 4, 6.1_
  - _Boundary: PhaseFactResearch, PhasePanel_

- [x] 7. 消費者への事実基盤配線
- [x] 7.1 (P) ステークホルダー抽出に事実基盤を配線する
  - 抽出処理が共有コンテキストを受け取り、事実基盤を「確定した客観的事実（共通前提）」として参考資料と区別してプロンプトに反映する
  - 事実基盤が空のときはテーマ情報のみで従来どおり動作する
  - 完了状態: 承認済み事実基盤が存在するとき抽出プロンプトに事実が含まれ、空のとき従来出力になるテストが緑
  - _Requirements: 4.1, 4.2_
  - _Depends: 2, 5_
  - _Boundary: stakeholder-agent, api/stakeholders_

- [x] 7.2 (P) ペルソナ生成に事実基盤を配線する
  - 生成処理が共有コンテキストを受け取り、事実基盤を共通前提として反映する
  - 事実基盤が空のときはテーマ・ステークホルダー情報のみで従来どおり動作する
  - 完了状態: 事実基盤の反映有無を検証するテストが緑
  - _Requirements: 5.1, 5.2_
  - _Depends: 2, 5_
  - _Boundary: persona-generator-agent, api/personas_

- [x] 7.3 (P) 章立て生成に事実基盤を配線する
  - 章立てのコンテキスト構築を BE 権威経路に置換し、コンテキスト整形に事実基盤の節を追加する
  - 事実基盤が空のときは従来どおりテーマ・ペルソナ情報で動作する
  - 完了状態: 章立てプロンプトに事実基盤の節が含まれ、空のとき無出力になるテストが緑
  - _Requirements: 7.1, 7.2_
  - _Depends: 2, 5_
  - _Boundary: chapter-agent, chapter-generator_

- [x] 7.4 (P) 取材の事実収集責務を共有基盤へ移管する
  - 取材のグラウンディング検証からテーマ事実の収集を外し、ペルソナ固有信念の反証検証に純化する
  - 共有事実基盤を取材に共通前提として注入し、そのペルソナに関連する具体的事実を一般論に薄めず反映する。関連事実が無ければ盛り込まない
  - ペルソナの信念を事実基盤と区別して生成・保持し、テーマ事実の個別重複検索を行わない。信念反証の検索結果が空でもエラーにしない
  - 完了状態: 取材が共有事実基盤を参照してテーマ事実の個別検索をせず、関連事実を反映するテストが緑
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5, 9.2_
  - _Depends: 2, 5_
  - _Boundary: interview-agent, api/interviews_

- [x] 7.5 (P) 討論に事実基盤を共通前提として注入する
  - ターン生成コンテキストに事実基盤を載せ、ペルソナとファシリテーターのプロンプトへ共通前提として供給する
  - 事実への関与の濃淡をプロフィール・関心度に応じて決め、件数ノルマを課さない。暗唱的な羅列を避け自分の立場からの反応にする（知ったかぶり禁止と両立）。関心が薄いペルソナは概括的に反応してよい
  - 完了状態: ターン生成に事実基盤が渡り、件数ノルマなしで各ペルソナが自然に事実へ関与するテストが緑
  - _Requirements: 8.1, 8.2, 8.3, 8.4, 8.5_
  - _Depends: 2, 5_
  - _Boundary: persona-agent, facilitator-agent, debate step_

- [x] 8. 挙動検証と全体通過
  - 新規トピックが事実リサーチ先頭で始まり、実行→編集→承認および実行せず承認の両経路でステークホルダーへ前進し、未承認ではステークホルダー以降へ進めないことを検証する
  - 事実基盤が全ペルソナへ同一値で供給される一貫性を確認する
  - FE/BE 双方のフル lint とテストを通過させる
  - 完了状態: 上記シナリオが緑で、FE/BE の全テストと lint が通過する
  - _Requirements: 2.2, 9.3_
  - _Depends: 6.2, 7.1, 7.2, 7.3, 7.4, 7.5_
