# Implementation Plan

- [x] 1. FE フェーズモデル基盤の slug 化
- [x] 1.1 フェーズ識別子を slug に昇格し数値型を撤廃する
  - `PhaseSlug` をフェーズの唯一の識別子とし、数値の `Phase` 型を削除する
  - フェーズ定義に状態別ラベル（running/generated/not_started/stopped）を内包する構造を持たせる
  - 完了状態: `Phase`（数値）への参照がフェーズモデルから消え、`tsc` がフェーズ定義まわりで数値型エラーを出さない
  - _Requirements: 1.1, 1.2, 1.3, 4.1_

- [x] 1.2 フェーズ定義を順序配列の単一情報源にする
  - フェーズ順序を定義配列の位置のみで表し、番号キーの並行ラベルテーブルを廃止する
  - 状態別ラベル文言は現行と一字一句同一に移設する
  - 完了状態: 番号キーの `Record` が削除され、ラベルは定義配列から引ける
  - _Requirements: 2.1, 4.1, 4.2_

- [x] 1.3 順序ユーティリティと状態導出を slug 方式へ置換する
  - 配列位置から順序・次フェーズ・最終判定を導く関数を追加する
  - 論理状態判定を順序比較に、表示ラベル導出を slug ルックアップと最終判定に置換する（`phase === 6` 直書きを排除）
  - ルーティングのフェーズ引数を slug 化する
  - 完了状態: 論理状態・表示ラベルがリファクタ前と同値を返し、数値リテラル比較が残っていない
  - _Requirements: 2.2, 2.3, 3.1, 3.2, 3.3, 3.4, 4.3, 5.3_

- [x] 2. (P) FE 消費者の slug 追随
- [x] 2.1 トピック永続型を slug 化する
  - 永続表現の `phase` を slug 文字列にし、読み取りマッピングを追随させる（number/slug 両対応の後方互換は入れない）
  - 完了状態: トピックの `phase` が slug 型で扱われ、数値 phase の後方互換読み取りが存在しない
  - _Requirements: 6.1, 6.3_
  - _Boundary: FE consumers_
  - _Depends: 1.1_

- [x] 2.2 承認遷移と状態書き込みを slug 化する
  - 承認時に「定義配列の次フェーズ」へ前進させ、ジャンプ先番号の直書きを排除する（最終フェーズでは前進しない）
  - 状態書き込み・リセット・新規作成の初期フェーズを slug で行う（新規は先頭 slug）
  - 完了状態: 各フェーズ承認で次 slug に前進し、最終フェーズでは前進せず、新規トピックが先頭 slug で作成される
  - _Requirements: 5.1, 5.2, 6.2_
  - _Boundary: FE consumers_
  - _Depends: 1.3_

- [x] 2.3 各フェーズ画面と共通ナビを slug 追随させる
  - 各フェーズ画面の自己識別を slug 定数にし、承認後遷移を次フェーズ導出経由にする
  - ステップナビ・レイアウト・一覧の順序判定を配列順序比較に置換する
  - 完了状態: 全フェーズ画面とナビが slug で動作し、進行順序・活性制御がリファクタ前と一致する
  - _Requirements: 1.3, 5.1_
  - _Boundary: FE consumers_
  - _Depends: 1.3_

- [x] 3. (P) BE のフェーズ slug 化
- [x] 3.1 BE 側のフェーズ型と確定・状態遷移を slug 化する
  - BE にフェーズ slug 型（生成確定を持つ部分集合を含む）を定義し、確定・状態遷移ヘルパーを slug で受け取るようにする
  - フェーズ確定の冪等・running 限定ガードは現行条件のまま slug 等価比較にする
  - 完了状態: フェーズ確定ヘルパーが slug 引数で動作し、確定条件がリファクタ前と同値
  - _Requirements: 7.1, 7.3_
  - _Boundary: BE phase ops_

- [x] 3.2 API・完了判定・ライフサイクルの slug 化
  - 各生成 API と取材完了判定の確定呼び出しを対応 slug にする
  - 討論・編集ライフサイクルのフェーズ書き込みと判定を slug（`debate`/`editing`）にする
  - 完了状態: 生成 API・討論・編集の各フェーズ確定/判定が slug で動作し、数値リテラル比較が残っていない
  - _Requirements: 7.1, 7.2_
  - _Boundary: BE phase ops_
  - _Depends: 3.1_

- [x] 4. テストと挙動不変の検証
- [x] 4.1 FE の同値・スナップショット検証を追加する
  - フェーズ slug 集合と定義配列順序を正準リストのリテラル期待値に対して self-check する
  - 論理状態判定を、リファクタ前の数値ケースを 1:1 変換した表駆動テストで同値検証する
  - 定義配列の順序と各状態別ラベル文言をスナップショットとしてリテラル固定する
  - 完了状態: slug 集合・順序・ラベルの意図しない変化がテストで検出され、論理状態が現行と完全一致する
  - _Requirements: 8.1, 8.2, 8.4_
  - _Boundary: FE consumers_

- [x] 4.2 (P) BE の slug 検証を追加する
  - BE のフェーズ slug 集合・生成確定部分集合を正準リストに対して self-check する
  - 確定ヘルパーと討論・編集ライフサイクル判定の slug 版を検証する
  - 完了状態: BE の slug 集合が正準リストと一致し、確定/ライフサイクル判定がリファクタ前と同値
  - _Requirements: 7.1, 7.2, 8.4_
  - _Boundary: BE phase ops_
  - _Depends: 3.2_

- [x] 4.3 既存テストの slug 化と全体通過・旧データのリセット
  - `phase: N` を直書きする既存テストを対応 slug に機械置換し、意図を変えない
  - FE/BE 双方のフル lint とテストを通過させ、進行順序・ゲート・ラベルの差分ゼロを確認する
  - デプロイ前に、数値 phase を持つ旧トピックを手動削除する（破壊的・本番直結のためユーザー承認のうえ実施、削除→デプロイの順を厳守）
  - 完了状態: FE/BE の全テストと lint が通過し、旧トピックが除去されて slug のみの状態になっている
  - _Requirements: 6.4, 8.1, 8.2, 8.3, 8.4_
  - _Depends: 2.1, 2.2, 2.3, 3.1, 3.2, 4.1, 4.2_
