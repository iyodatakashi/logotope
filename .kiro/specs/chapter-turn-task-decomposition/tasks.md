# Implementation Plan

- [x] 1. Foundation: 型定義と進捗データモデル
- [x] 1.1 ターン追記・ステップ・進捗の型を定義する
  - 追記結果の判別共用体（committed / rejected: index_mismatch | generation_mismatch | debate_inactive）を定義する
  - 追記入力に `expectedTurnIndex` と `progressPatch`（`chapterEndCount`・`discussionPointStatuses`）を加える
  - ステップ種別（open/turn/summary/closing/comments）・ステップペイロード（topicId/chapterIndex/runId/stepKind/expectedTurnIndex/singleChapterMode）・次ステップ判定結果・章進捗（chapterEndCount/discussionPointStatuses）の型を定義する
  - chapter doc に `chapterEndCount`（任意・未設定=0）を持たせる型を反映する
  - 完了状態: 上記型が型チェックを通り、後続タスクから参照可能になっている
  - _Requirements: 2.1, 4.1_

- [x] 2. Phase1 止血: 冪等トランザクション追記
- [x] 2.1 ターン追記を条件付きトランザクション追記に置き換える
  - topic doc（runId 読取）と chapter doc（turns・chapterEndCount・discussionPointStatuses 読取/書込）を単一トランザクションで処理する
  - 章ローカル `turns.length === expectedTurnIndex` かつ runId 一致のときだけ1ターン追記し、同一トランザクションで `progressPatch` を反映する
  - 不一致時はトランザクション本体で sentinel（rejected）を返して例外を投げず正常コミットし、副作用を残さない
  - runId がペイロードまたは topic doc に無い場合は世代照合をスキップする（後方互換）
  - 完了状態: 同一 `expectedTurnIndex` への二重追記が1件に収束し、関数が committed/rejected を返す
  - _Requirements: 2.2, 2.3, 2.4, 3.1, 6.1, 6.2, 6.3, 7.1, 7.2_
  - _Boundary: Turn Writer_

- [x] 2.2 追記ヘルパと既存ループを期待位置・rejected 伝播に対応させる
  - ファシリテーター/ペルソナ/介入の各追記ヘルパが `expectedTurnIndex` を受け取り追記結果を呼び出し元へ伝播する
  - 既存のチャプターループが章ローカル長を期待位置として供給し、rejected を受けたら当該チャプター処理を例外なく打ち切る
  - 完了状態: 既存ループ構造のまま、並走・重複実行による二重生成が発生しなくなる（止血が成立）
  - _Requirements: 2.1, 3.2, 3.3, 4.2_
  - _Depends: 2.1_

- [x] 2.3 冪等追記のユニットテストを追加する
  - index 一致で committed、不一致で index_mismatch、runId 不一致で generation_mismatch、runId 欠如で照合スキップを検証する
  - 順次実行では正当なターンが脱落しないこと（誤検知なし）を検証する
  - 完了状態: 上記ケースのテストがグリーン
  - _Requirements: 2.2, 2.3, 6.3, 7.1, 7.2_
  - _Depends: 2.1_

- [x] 3. Phase2: 状態再構築と進捗永続化
- [x] 3.1 (P) 章進捗を永続データから再構築する処理を追加する
  - `chapterEndCount`（未設定=0）と論点ステータス（未設定は章の論点から未着手初期化）を復元する
  - 復元結果を再構築済み討論状態へ注入し、ループ版と等価な状態を得る
  - 同一入力から同一出力になる決定論を保つ
  - 完了状態: ステップ起動時に永続データのみから章進捗を含む状態が復元できる
  - _Requirements: 1.2, 1.3_
  - _Boundary: State Reconstruction_
  - _Depends: 1.1_

- [x] 3.2 章終了カウンタを追記トランザクションで前進更新しリセット可能にする
  - ターン生成時の継続シグナル（高意欲者の有無）から `chapterEndCount` を 0 リセット/加算し、追記と同一トランザクションで書き込む
  - 早期終了判定でカバレッジ評価により継続する場合は `chapterEndCount` を 0 に戻す
  - チャプター再起動時に `chapterEndCount` を削除（リセット）する
  - 完了状態: 連続低意欲ターン数がターンと整合して永続化され、二重カウントが起きない
  - _Requirements: 4.1, 5.1_
  - _Depends: 2.1_

- [x] 4. Phase2: ステップ判定・冪等 enqueue・ステップ実行
- [x] 4.1 次ステップ判定を永続状態の純関数として実装する
  - 章継続・章終了・次章遷移・終端のいずれに進むかを、cap・早期終了進捗・カバレッジ消化から判定する
  - 章終了でも未応答指名が残る場合は最終応答ターンを1回挟む意味論を再現する
  - 完了済み章には次ステップを投入しないようにする
  - 引数（永続状態）のみに依存し、乱数・時刻・外部 I/O を判定に持ち込まない
  - 完了状態: 同一状態から常に同一の次ステップ種別・期待位置を返す
  - _Requirements: 4.1, 4.3, 5.1, 5.2_
  - _Boundary: decideNextStep_
  - _Depends: 1.1, 3.2_

- [x] 4.2 (P) ステップ enqueue を deterministic id で冪等化する
  - runId・chapterId・投入先期待位置（終端は種別）からタスク id を決定論的にハッシュ生成する
  - 同一 id の重複作成エラーを成功扱いにして多重投入を1本へ収束させる
  - runId を id の鍵に含め、再起動時の id 予約衝突を避ける
  - 完了状態: 同一 (runId, chapterId, 期待位置) は同一 id になり、重複 enqueue が dedup される
  - _Requirements: 1.4, 3.3_
  - _Boundary: Task Layer_
  - _Depends: 1.1_

- [x] 4.3 1ステップを処理する再入可能ディスパッチャを実装する
  - 停止ゲート→状態再構築→期待位置一致なら1ターン生成（既存の正準1ターンロジックを再利用）→単一トランザクション追記、を行う
  - 期待位置が不一致、または追記が rejected の場合は生成せず、最新状態から次ステップを再導出して冪等 enqueue（resume）し正常終了する
  - 例外時のみ throw し、停止・resume・no-op では throw しない
  - 完了状態: frontier の唯一勝者だけがターンを生成し、敗者・リトライは resume でチェーンを途切れさせない
  - _Requirements: 1.1, 1.3, 1.4, 3.1, 3.2, 5.3_
  - _Boundary: advanceDebate_
  - _Depends: 2.1, 3.1, 4.1, 4.2_

- [x] 4.4 章開始・章遷移・終端ステップを冪等に実装する
  - 章開始（オープニング/導入）と章まとめ・クロージングのファシリテーターターンを期待位置照合で追記する
  - 事後コメント生成と完了遷移を、実行中状態のときだけ進める条件付きトランザクションにする
  - 完了済み章への終端処理・次タスク投入を二重に行わない
  - 完了状態: クロージング・事後コメント・完了遷移が重複生成されない
  - _Requirements: 4.2, 4.3, 4.4_
  - _Depends: 4.3_

- [x] 5. Integration: per-turn タスクへの配線
- [x] 5.1 ターンステップタスクと開始/再起動の起点を切り替える
  - チャプタータスクハンドラをターンステップハンドラに置き換え、ペイロードから runId を引き回す
  - 討論開始・再起動が最初の章開始ステップを enqueue するようにする
  - 最終リトライ失敗時の討論停止をステップ単位で維持する
  - 完了状態: 討論開始から終端までがターン単位タスクのチェーンで進行し、各ターンが1件だけ永続化される
  - _Requirements: 1.1, 1.4, 3.2, 6.1_
  - _Depends: 4.3, 4.4_

- [x] 6. Validation: 冪等性・liveness・行動等価性
- [x] 6.1 冪等性と liveness の統合テストを追加する
  - 同一期待位置で2回処理してターンが1件のみ・2回目は生成せず resume することを検証する
  - 「追記コミット済みだが次 enqueue 前」を再現し、リトライ/重複タスクが resume で後続を投入しチェーンが復活することを検証する
  - 終端ステップを2回実行しても事後コメント重複・状態二重遷移が起きないことを検証する
  - 完了状態: 重複・並走・部分失敗の各シナリオでターン数と終端が一意になる
  - _Requirements: 2.4, 3.1, 3.3, 4.4_
  - _Depends: 5.1_

- [x] 6.2 行動等価性ハーネスで旧ループと新チェーンの一致を検証する
  - LLM 生成・エンゲージメント評価・ファシリテーター系をスクリプト化したモックに差し替える
  - 同一スクリプトで旧ループ版と新チェーン版を実行し、ターン列（話者・モード・指名・キュー・順序）の一致を検証する
  - 介入・章終了カウント・最終応答ターンのシナリオで等価性を確認する
  - 完了状態: 代表シナリオで両版のターン列が一致する
  - _Requirements: 5.1, 5.2, 5.3_
  - _Depends: 5.1_

- [x] 6.3 ステップ判定・状態再構築・冪等 enqueue のユニットテストを追加する
  - 次ステップ判定の継続/cap到達/早期終了（消化・未消化）/最終章クロージング/最終応答の各分岐を検証する
  - 章進捗復元のデフォルト・決定論を検証する
  - 同一鍵が同一 id を生成し重複作成を成功扱いにすることを検証する
  - 完了状態: 上記ユニットテストがグリーン
  - _Requirements: 1.2, 1.4, 4.1, 4.3, 5.2_
  - _Depends: 4.1, 3.1, 4.2_

- [x] 7. Cleanup: 旧チャプターループの撤去
- [x] 7.1 旧チャプター一括処理を撤去し単一経路へ収束させる
  - 旧チャプターループ・旧タスクハンドラ・旧 enqueue を撤去する
  - 再起動時の章進捗リセットと起点投入が新経路のみを通ることを確認する
  - 完了状態: 討論処理経路がターンステップチェーンの一本に収束し、旧経路の二重実行余地がなくなる
  - _Requirements: 1.1, 6.2_
  - _Depends: 6.2_
