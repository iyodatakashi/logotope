# Gap Analysis: awareness-position-change-enforcement

## 1. 現状調査

### 気づきの生成から消費までの経路

| 段階 | 場所 | 内容 |
|---|---|---|
| 検出 | `agents/persona-agent.ts` `evaluateEngagement` | `awarenessDetectionNote`（573字）＋ `engagementSchema.awareness`。意欲評価と同一呼び出しに相乗り |
| 採否 | 同 `resolvedAwareness`（IIFE） | 空内容 / 話者自身 / `sourceTurnId` 不一致で drop。`onAwarenessDropped` で理由を通知（実装済み） |
| 永続 | `pipeline/debate/awareness.ts` `appendAwareness` | `arrayUnion` で append-only。in-memory 参照も同時更新 |
| 巻き戻し | 同 `rollbackAwarenessesForRemovedTurns` | 破棄ターンに紐づく気づきを除去 |
| 整形 | `utils/prompt-formatters.ts` `formatAwarenessSection` | 「信念（不変の主軸）は変えず、立場を反転させない範囲で…発言してください」を含む |

### 気づきの消費先（4系統）

1. **発言生成** — `persona-agent.ts:310` `awarenessNote`
2. **傾聴（意欲評価）の文脈** — `persona-agent.ts:462` `awarenessSection`（cached-prefix パートとして送出）
3. **所感生成** — `persona-agent.ts:614` `awarenessLines`（気づきを軸に2〜4文を書かせる）
4. **ダイジェスト → 導入・締め** — `debate-digest.ts:53` が `beliefShifts` として集約し、`intro-outro-agent.ts:89` が「討論で得た気づき: …」として使用

### 要件検討時に想定していなかった依存（重要）

- **公開ページに表示される** — `src/lib/features/public/article-detail/PublishedTurnItem.svelte` がターンごとの気づき件数をバッジ表示し、`PublishedAwarenessDialog.svelte` で全文を出す。**気づきは読者が直接見る成果物**であり、件数の減少はそのまま公開物の変化になる
- **章編集でターンを保護している** — `pipeline/editing/editing-step.ts` `computeProtectedTurnIds` が、気づきの `triggeredByTurnId` に一致する原本ターンを「除外禁止」にする。**気づきが減ると保護されるターンが減り、章編集が切れるターンが増える**

### 規約・パターン

- 検証ハーネスは本番と同一エンジンを呼ぶ（`verify-engagement-model.ts` が `--compare` で変数を1つに絞る形を確立済み）
- 意味判断をコードの突合に落とす手口が先行 spec で成功している（`sourceTurnId` 突合、実測で誤 drop は90回中1件）
- 仕組みの有効性検証は変数を1つに絞る（`conventions.md`）

## 2. 要件の実現可能性

| 要件 | 技術的な必要物 | 判定 |
|---|---|---|
| 1: 記録対象を受容・新たな認識に限定 | `awarenessDetectionNote` の書き換え。除外条件（補強・他者観察）の明示 | プロンプト変更のみ。ただし**効果は保証されない**（実測で文言の締めが効かなかった実績あり） |
| 2: 置き換えモデルを外す | 同上。「別の場所に動いた」「立場を変える」の撤去 | 同上 |
| 3: 発言時の非反転制約を撤回 | `formatAwarenessSection` の文言変更。呼び出しごとの言い分けが必要 | **要設計判断**（下記 3 節） |
| 4: 記録しなかった件数の可視化 | `onAwarenessDropped` は実装済み。理由の追加と集計手段が要る | 実装済み基盤の拡張で足りる |
| 5: 既存保証との非干渉 | 突合・ガード・append-only・永続互換の維持 | 変更が `resolvedAwareness` と文言に閉じるなら自然に満たす |
| 6: 中身の読み取りによる検証 | `inspect-awareness.ts`（実装済み）で前後比較 | 追加実装不要 |

### Research Needed

- **要件1の「補強を記録しない」を、プロンプト以外のどこで担保するか。** 現時点で機械判定の手段が特定できていない。要件6.4 は「第一段階で効かなければ独立した判定工程を検討」としており、第一段階の設計では担保をプロンプトに置かざるを得ない。この不確実性を design で明示する必要がある
- **公開ページの表示への影響をどう扱うか。** 気づき件数が2〜3割減ると、読者が見るバッジの数が変わる。仕様上の劣化ではないが、事前に合意しておくべき変化

## 3. 実装アプローチの選択肢

### 論点A: `formatAwarenessSection` の言い分け（要件3.3）

現状、同じ整形結果が「発言生成」と「傾聴」の両方に渡っており、発言のための指示（「…踏まえて発言してください」）が検出の呼び出しにも入っている。

| 案 | 内容 | トレードオフ |
|---|---|---|
| A-1 | `formatAwarenessSection` に用途引数を足し、発言用・傾聴用で末尾の一文を切り替える | ✅ 変更が1関数に閉じる / ❌ 引数で分岐する整形関数になる |
| A-2 | 気づき本体の整形（列挙）と、用途ごとの指示文を分離し、呼び出し側で組む | ✅ 整形関数が単一責務に戻る / ❌ 2箇所の呼び出し側に文言が散る（`writing-style` 集約の方針と要相談） |
| A-3 | 指示文をすべて削り、気づきの列挙だけを渡す | ✅ 最小・混入が構造的に消える / ❌ 発言時に気づきをどう扱うかの指針が失われる |

**注意**: 傾聴側の気づき節は現在 cached-prefix のキャッシュ区切りに載っている（`perf: 意欲評価の気づき節をキャッシュ側に移して単価を下げる`）。文言を用途で変えるとキャッシュのプレフィックスも変わるため、**キャッシュ設計と整合を取る必要がある**（発言用と傾聴用で別プレフィックスになる）。

### 論点B: 除外条件をどこに置くか（要件1.3・1.4）

| 案 | 内容 | トレードオフ |
|---|---|---|
| B-1 | プロンプトの記述のみ（第一段階） | ✅ 呼び出し増ゼロ・要件5.5 を満たす / ❌ 効果は不確実。実測で文言の締めが効かなかった実績がある |
| B-2 | スキーマに項目を足し、破綻をコードで検出 | ❌ **要件フェーズで否定済み**。補強でも before/after は自然に埋まることを実データで確認した |
| B-3 | 独立した判定呼び出し（インライン） | ✅ 意味判断を意味を扱えるものに任せる / ❌ 呼び出し +3.7回/ターン・約 +$1.1/トピック。要件5.5 により第一段階では採らない |

要件は B-1 を第一段階とし、効かなければ B-3 を検討する順序を定めている。design ではこの分岐を明示し、**B-1 の効果測定の方法**（何をもって「効かなかった」と判断するか）を決める必要がある。

### 論点C: 既存テストの扱い

現行の振る舞いを固定しているテストが3件あり、本仕様で意図的に破る。

| テスト | 固定している内容 | 本仕様での扱い |
|---|---|---|
| `persona-agent.test.ts:341-344` | 検出プロンプトが「結論・立場」「再確認」「改めて/やはり」を含む | **書き換え**（置き換えモデルと言い回し禁止の撤去に伴う） |
| `persona-agent.test.ts:1093` | 発言生成に「立場反転しない旨」を注入する | **書き換え**（要件3.1） |
| `prompt-formatters.test.ts:162` | 気づき節が「信念」を含む | 要確認（初期信念の固定は維持するため、文言次第では維持可） |

これらは `belief-awareness-remodel` の Requirement 2.5 を守るために書かれたテストであり、本仕様がその一部を意図的に撤回する。**テストを消すのではなく、新しい意図を固定するテストへ置き換える**のが筋。

## 4. 影響範囲のまとめ

**変更が確実に必要**
- `agents/persona-agent.ts` — `awarenessDetectionNote`、`resolvedAwareness` の drop 理由
- `utils/prompt-formatters.ts` — `formatAwarenessSection` の文言・用途分け
- 上記3件のテスト

**変更の可能性**
- キャッシュ区切りの構成（論点A の選択次第）

**変更しないが影響を受ける**
- 公開ページの気づきバッジ（件数が減る）
- 章編集の保護ターン（保護対象が減る）
- 所感・導入/締め（入力の気づきが減る）

**変更しない**
- `awareness.ts`（append-only・巻き戻し）、`engagementSchema` の他項目、話者選択・キュー・章継続判定

## 5. design フェーズで決めるべきこと

1. `formatAwarenessSection` の言い分け方式（論点A の A-1 / A-2 / A-3）とキャッシュ構成への影響
2. 検出プロンプトの新しい記述（置き換えモデルの撤去、除外条件の書き方）
3. 「効かなかった」の判定基準 — 何件・どの読み取りで B-3 へ進むと決めるか
4. 差し替えるテストが固定すべき新しい意図
5. 公開表示・章編集の保護に対する件数減少の影響を許容するかの確認
