# Implementation Plan

- [x] 1. グラウンディング検証スパイク
- [x] 1.1 gemini-3.1-pro-preview のグラウンディングメタデータ取得を確認
  - `gemini-3.1-pro-preview` に `google.tools.googleSearch` を付与したテキスト生成を1回実行する最小スクリプトを用意する
  - 応答の `providerMetadata.google.groundingMetadata` に `groundingChunks`（uri・title）と `webSearchQueries` が含まれることを確認する
  - 観察可能な完了条件: 実行ログに実際の参照URL・タイトルとGoogle検索クエリが出力され、メタデータ取得方法が確定する
  - メタデータが返らない場合は、その事実と代替（既存Tavilyツール）の必要性を記録して停止判断する
  - 応答時間を計測し、3フェーズ直列実行が Functions タイムアウト内に収まるか見積もる
  - _Requirements: 2.3, 6.3_

- [x] 2. ドラフト信念生成フェーズ
- [x] 2.1 ペルソナ情報のみからドラフト信念を生成する
  - ペルソナ属性（氏名・年齢・職業・立場・背景・関心事）とテーマタイトル、`topicContext` のみを入力に、検索を一切行わずドラフト信念を生成する
  - 信念6項目（立場と根拠・核心的主張・懸念事項・価値観・妥協点・変化の可能性）を構造化フィールドとして保持する
  - 観察可能な完了条件: 検索ツールなしで6項目構造化ドラフトが返り、生成失敗時はエラー結果を返して後続を実行しない
  - _Requirements: 1.1, 1.2, 1.3, 1.4_

- [x] 3. 批判的検証フェーズ
- [x] 3.1 グラウンディングでドラフトを反証的に検証する
  - ドラフト各項目について「誤り・実態との相違を優先的に探す」反証起点のプロンプトでグラウンディング検索を実行する
  - 検証結果を固定Markdown書式（一致点／相違点／新発見の3区分、各ギャップに根拠URL併記）のテキストとして出力する
  - ドラフトを書き換えず、検証レポートを独立した中間データとして保持する
  - 観察可能な完了条件: 3区分の検証レポートテキストが返り、ドラフトは不変のまま保持される
  - グラウンディング結果が無い（チャンク空）またはグラウンディング不可の場合はエラーを返し、未検証ドラフトを通さない
  - _Requirements: 2.1, 2.2, 2.4, 2.5, 3.1, 3.2, 3.3, 6.1_
- [x] 3.2 グラウンディングメタデータを参照元情報に変換する
  - グラウンディングメタデータの参照チャンクをタイトル・URLの組に変換し、URL重複を排除する
  - 実行されたGoogle検索クエリ群と検証サマリーを併せて、1つの集約参照元エントリにまとめる
  - 観察可能な完了条件: 重複のない参照URL一覧を持つ集約参照元が生成され、チャンクが空のときは空となり呼び出し元がエラー判定できる
  - _Requirements: 2.3, 5.2, 5.3_

- [x] 4. 最終信念・取材記録生成フェーズ
- [x] 4.1 ドラフトと検証レポートから最終成果をゼロ生成する
  - ドラフト信念と検証レポートを参照情報として渡し、最終信念ドキュメントをドラフト構造に依存せずゼロから生成する
  - ステレオタイプの一般論ではなく、ペルソナ固有の経験・葛藤・価値観を反映した内容にする
  - 最終信念に基づき1000字以上の仮想取材記録を生成する
  - 観察可能な完了条件: ドラフトを「比較参照」として扱った最終信念と1000字以上の取材記録が返る
  - _Requirements: 4.1, 4.2, 4.3, 4.4_

- [x] 5. パイプライン統合と呼び出し元接続
- [x] 5.1 3フェーズを直列実行し結果を集約する
  - ドラフト生成→批判的検証→最終生成を順次実行し、いずれか失敗時は即エラー結果を返す（fail-fast）
  - 既存の出力形（取材記録・初期信念・参照元一覧）を維持し、リサーチサマリーは出力しない
  - 戻り値を例外送出ではなく成否を表す結果型に変更し、エラーは再試行可能として正規化する
  - 旧実装（Tavilyツール・調査評価ツール・シングルコール）を削除する
  - 観察可能な完了条件: 全フェーズ成功で参照元が非空の出力が返り、検証フェーズ失敗時は全体がエラー結果になる
  - _Requirements: 5.1, 5.4, 6.1, 6.2_
- [x] 5.2 取材APIを結果型に対応させ未使用シークレットを除去する
  - 取材実行のonCallハンドラを、成否結果型を受けて失敗時にHTTPエラーへ変換する形に更新する
  - 取材フローで未使用となった検索APIキーのシークレット指定を除去する
  - 観察可能な完了条件: 取材APIがエラー結果時にHTTPエラーを返し、不要なシークレット指定が外れる
  - _Requirements: 6.2_
  - _Depends: 5.1_

- [x] 6. テスト
- [x] 6.1 各フェーズとパイプラインのユニットテストを更新する
  - ドラフト生成が検索ツールなしで6項目を返すこと、失敗時にエラー結果になることを検証する
  - 検証フェーズがグラウンディングツール付きで呼ばれ、チャンク空のときエラーを返すことを検証する
  - 参照元変換がURL重複を排除し検索クエリを集約することを検証する
  - 最終生成がドラフトと検証レポートをプロンプトに含めて成果を返すことを検証する
  - パイプライン全体が全フェーズ成功時に参照元非空の出力を返し、検証失敗時に全体エラーになること、テーマ詳細の後方互換を検証する
  - 観察可能な完了条件: 既存テストが新パイプライン構成に更新され、全ユニットテストがパスする
  - _Requirements: 1.1, 1.4, 2.5, 3.1, 4.1, 5.1, 5.4, 6.1_
- [x] 6.2 取材APIの結果型ハンドリングを検証する
  - 取材APIがエラー結果でHTTPエラーを投げ、成功結果でそのまま返すことを検証する
  - 観察可能な完了条件: 取材APIのエラー変換と正常返却のテストがパスする
  - _Requirements: 6.2_
  - _Depends: 5.2_
