# Implementation Plan

- [x] 1. 公開記事の読み取り型を定義する
  - `PublishedArticle` と構成要素 `PublishedChapter` / `PublishedTurn` / `PublishedAwareness` / `PublishedImpression` / `PublishedNarration` を、Admin 型・`*ForFirestore` から分離した読み取り専用の最小射影として定義する（型と型ガードのみ）
  - 発話の型は本文・話者名・役割・気づき配列のみを持ち、診断注釈（factCheck・engagementScore・speechMode 等）を含めない
  - 記事要素（導入・締め）は本文文字列、無い場合は article 側で null を持てる形にする
  - 完了条件: 公開経路が依存する型一式が用意され、Admin 型・ストアへの依存を含まない
  - _Requirements: 1.6, 2.2, 2.6, 3.1_
  - _Boundary: PublishedArticle types_

- [x] 2. 公開記事の取得・射影を実装する
- [x] 2.1 公開判定と取得結果の写像を実装する
  - `publicDb` で対象トピックを一回取得し、`published` が true かつ公開日を持つ場合のみ記事化を続行する
  - 不在・未公開・`permission-denied` は「記事なし」を表す null を返し、それ以外の取得失敗のみ例外として送出する
  - 完了条件: 未公開・不在・拒否のトピックで null が返り、公開済みトピックでのみ後続の射影に進む
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 6.1, 6.2_
  - _Boundary: fetchPublishedArticle_
- [x] 2.2 記事本文を読み物へ射影・join する
  - 導入・締め・所感を統合記事要素から読み、各要素は編集後があれば編集後、無ければ原本を採用し、どちらも無い要素は省く。所感は並び順で整列する
  - 章は章の並び順で編集後章と原本章を対応づけ、編集後が完了状態のときのみ編集後発話を、それ以外は原本発話を採用する
  - 各発話に話者（ペルソナ名・役割、無ければファシリテーター）を解決し、気づきを発話の由来ターン（編集後は連結元すべて、原本は自ターン）から集約して発話へ焼き込む
  - 完了条件: 公開済みトピックから、導入・章（発話・話者・気づき付き）・締め・所感を備えた記事データが得られ、未編集章は原本にフォールバックする
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 2.1, 2.4, 2.5, 2.6, 3.2_
  - _Boundary: fetchPublishedArticle_
  - _Depends: 2.1_

- [x] 3. 記事表示部品を実装する
- [x] 3.1 (P) 導入・締めの表示部品を実装する
  - 本文とラベル（導入／締め）を受けて散文表示する共通部品を用意する
  - 完了条件: 導入・締めがそれぞれラベル付きで読み物として描画される
  - _Requirements: 1.2_
  - _Boundary: ArticleNarration_
- [x] 3.2 (P) ペルソナ所感の表示部品を実装する
  - 話者（名前・役割）と所感本文を表示する
  - 完了条件: 所感が話者情報付きで描画される
  - _Requirements: 1.2, 1.5_
  - _Boundary: ArticleImpression_
- [x] 3.3 (P) 気づきダイアログの独立部品を実装する
  - 開閉状態を親から受け取り、開のとき気づき一覧を「ペルソナ名: 内容」で表示し、閉じる操作で親へ通知する制御コンポーネントにする
  - 完了条件: 開指定で気づき一覧が表示され、閉じる操作で閉じられる
  - _Requirements: 3.3, 3.5_
  - _Boundary: AwarenessDialog_
- [x] 3.4 (P) 目次と現在地強調の部品を実装する
  - 章一覧を左ペインに固定表示し、各項目から該当章へアンカー移動できるようにする
  - ブラウザ限定で章セクションの可視状態を監視し、現在表示中の章の項目を状態クラス＋スタイルで強調する（要素差し替えは使わない）。狭幅時は固定を解除し折りたたみ等へ適応する
  - 完了条件: スクロールに応じて現在章の目次項目が強調され、項目クリックで該当章へ移動する
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 10.2_
  - _Boundary: ArticleToc_
- [x] 3.5 発話の表示部品を実装する
  - 話者（ペルソナ名・役割、またはファシリテーター）と本文を表示し、気づきが1件以上ある発話にのみアイコン＋件数のアフォーダンスを出す
  - アフォーダンス操作で開閉状態を立て、気づきダイアログへ一覧と開閉を渡す（本文には気づきを展開しない）
  - 完了条件: 気づき0件の発話にアフォーダンスが出ず、1件以上でアフォーダンス操作によりダイアログが開く
  - _Requirements: 2.2, 2.3, 2.6, 3.1, 3.2, 3.3, 3.4_
  - _Boundary: ArticleSpeech_
  - _Depends: 3.3_
- [x] 3.6 章の表示部品を実装する
  - 章タイトルと発話列を発話順に描画し、目次からの移動先となるアンカー（安定な章の並び順に基づく）を持たせる
  - 完了条件: 章タイトルと発話が順序通り描画され、目次アンカーの対象になる
  - _Requirements: 1.4, 2.1_
  - _Boundary: ArticleChapter_
  - _Depends: 3.5_

- [x] 4. ルートを結線して記事ページを成立させる
- [x] 4.1 記事取得を SSR ロードに結線し状態を写像する
  - ルートのロードで記事取得を呼び、記事なしは 404、取得失敗は 500、成功は記事データとして返す。SSR で配信する
  - 完了条件: 公開記事は SSR で描画データが返り、不在・未公開は 404、取得失敗は 500 になる
  - _Requirements: 5.1, 5.2, 5.3, 6.1, 6.3_
  - _Boundary: +page.ts load_
  - _Depends: 2.2_
- [x] 4.2 不在・取得失敗の提示画面を実装する
  - 404 は「記事が見つかりません」、それ以外は「取得に失敗しました」を出し分け、インデックスへの導線を出す。記事本文前提のメタ情報は出さない
  - 完了条件: 不在・未公開で記事なしメッセージ、取得失敗で失敗メッセージが表示され、いずれもインデックスへ戻れる
  - _Requirements: 7.2, 7.3, 8.2, 9.1_
  - _Boundary: +error.svelte_
  - _Depends: 4.1_
- [x] 4.3 記事ページ本体を構成する
  - 目次ペインと記事ペインの2カラムで、見出し（タイトル・公開日）→導入→章列→締め→所感列の順に各表示部品を配置する
  - クライアント遷移中の読み込み表示、記事別のタイトル・説明・OGP、インデックスへの導線、管理機能への導線を出さないこと、画面幅に応じた2カラム↔単カラムのレスポンシブを満たす
  - 完了条件: 公開記事が規定の順序で1本の読み物として表示され、目次・メタ・導線・レスポンシブが機能する
  - _Requirements: 1.1, 1.2, 1.3, 1.6, 4.1, 6.4, 7.1, 8.1, 9.1, 10.1_
  - _Boundary: +page.svelte_
  - _Depends: 4.1, 3.1, 3.2, 3.4, 3.6_
