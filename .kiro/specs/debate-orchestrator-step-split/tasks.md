# Implementation Plan

> 本スペックは挙動保存リファクタリング。各タスクは「型チェック（tsc）と既存テスト3種が通る」状態を保ったまま進める。タスク1〜4は小さな抽出（各段階で緑）、タスク5で実行と次ステップ決定の分離（中核）、タスク6で等価性を最終検証する。

- [x] 1. 契約型を契約型モジュールへ集約する
  - 章ドキュメントのランタイム形（ChapterEntry）を契約型モジュールへ移し、ステップ実行コンテキスト（StepContext）と turn の実行結果型（TurnExecution）を新規に定義する
  - 既存の類似型（ChapterForFirestore）とは別物として併存させ、本スペックでは統一しない
  - 章ライフサイクル層およびステップ層の参照を、移動後の契約型モジュールへ向け直す（再エクスポートで温存しない）
  - 観測可能な完了条件: tsc が解決し、移動した型が契約型モジュールから参照され、型 import の循環が無い
  - _Requirements: 1.4, 6.2, 6.5_

- [x] 2. 論点状態モジュールを新設して論点ロジックを集約する
  - 論点（discussionPoint）の状態遷移（untouched 初期化・introduced・addressed）と永続化（statuses の保存・削除）を 1 つの新規モジュールに集約する。既存のキュー状態モジュール（状態遷移＋永続化を 1 箇所に持つ構成）と同じパターンに揃える
  - オープニング処理の論点 untouched 初期化と、ターン処理の addressed 更新を、ハンドラ内インラインからこのモジュールの関数呼び出しへ置き換える
  - 新規ファイルは kebab-case 命名・アロー関数・既存スタイルに合わせる
  - 観測可能な完了条件: 論点の初期化・introduced・addressed・保存・削除が新モジュールに集約され、ハンドラからインラインの論点遷移ロジックが消え、既存テスト3種が通る
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 1.5, 8.1_

- [x] 3. 章ステータス永続化ヘルパーを章ライフサイクル層へ移す
  - 章ステータス（running/completed 等）を書き込むヘルパーを、章ライフサイクル層へ移動する（同層の既存 db アクセスパターンを再利用し、重複定義を作らない）
  - ステップ層の参照を移動先へ向け直す
  - 観測可能な完了条件: 章ステータス更新が章ライフサイクル層に存在し、ステップ層から正しく参照され、テスト3種が通る
  - _Requirements: 1.3_

- [x] 4. ターン実行の重複後処理を共通化する
  - 1 ターン実行の freeze 分岐と通常分岐で重複している後処理（キュー消化→発言統計更新→信念変化の永続化）を、ステップ層内の単一の共通ヘルパーへ括り出す
  - 両分岐のコミット成功時に同一の共通ヘルパーを呼ぶ
  - 観測可能な完了条件: 後処理が 1 箇所に集約され、両分岐が同一ヘルパーを呼び、後処理の副作用が共通化前と同一でテスト3種が通る
  - _Requirements: 4.1, 4.2, 4.3, 1.5_

- [x] 5. 実行と次ステップ決定を分離し、チェーン駆動層を新設する
- [x] 5.1 各ステップ処理を「実行結果のみ返す」形へ変更する
  - 各ステップ処理から enqueue・次ステップ判定・再開の呼び出しを除去し、自分のステップの実行結果だけを返す形にする（turn は completed/conflict/advanced(quietStreak) の実行結果、その他は committed の真偽値）
  - ステップ処理は実行オプションを呼び出し側から引数で受け取り、オプション構築や次ステップ判定を import しない
  - ステップ層ファイルの冒頭コメントを「ステップ実行層」の責務に更新する
  - 観測可能な完了条件: 各ステップ処理が実行結果を返し、ステップ層が次ステップ判定・enqueue・コンテキスト再構築のいずれにも依存しない
  - _Requirements: 2.1, 2.4, 1.2, 1.6_

- [x] 5.2 チェーン駆動層を新設し、次ステップ決定と投入を集約する
  - 状態再構築・次ステップ判定・enqueue 系・再開・実行オプション・関連純ヘルパーを新規チェーン駆動モジュールへ配置する
  - 入口処理が、停止ゲート→コンテキスト再構築→オプション構築→ステップ処理の dispatch を行い、dispatch した stepKind と実行結果に基づいて次ステップを決定する（turn の通常前進時のみ次ステップ判定を呼ぶ）。投入は既存の enqueue 系ヘルパーを用い、各 step 分岐を吸収する中央ディスパッチャや新たな記述子型は導入しない
  - frontier（位置）算出はステップ処理が状態を更新した後に行い、算出式・実行順を分割前と同一に保つ
  - 新規ファイルは kebab-case 命名、冒頭にチェーン駆動の責務コメントを置く
  - 観測可能な完了条件: 入口処理と次ステップ決定・enqueue がチェーン駆動層に集約され、チェーン駆動層からステップ層への参照は dispatch のみ・逆向き参照が無い一方向構成になる
  - _Requirements: 1.1, 2.2, 2.3, 5.2, 5.5, 8.3, 1.6_

- [x] 5.3 移動した公開シンボルの参照 import を更新する
  - 入口処理（advanceDebate）と次ステップ判定（decideNextStep）の参照元（API ハンドラおよび該当テスト3ファイル）の import を、新しいチェーン駆動モジュールへ向け直す
  - 各ファイル間で相互に必要なシンボルの import を解決し、再エクスポートで旧パスを温存しない
  - 観測可能な完了条件: すべての参照が実際の定義ファイルを指し、tsc が解決して未解決 import が無い
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5_

- [x] 6. 等価性と一方向依存を検証する
  - 型チェック（tsc）を実行し、新規型エラー・型 import 循環が無いことを確認する
  - 既存テスト3種（パリティ／冪等性／次ステップ判定）を、アサーション・モックを変更せず import パス更新のみで全通過させる。パリティの snapshot が分割前と一致し、enqueue されるタスク・frontier・タスクキー・Firestore 副作用が不変であることを確認する
  - 依存方向が一方向（契約型 ← ライフサイクル/論点状態 ← チェーン駆動 → ステップ実行）で、ステップ層がチェーン駆動層を import しないことを確認する
  - 公開 API（advanceDebate/decideNextStep/DEFAULT_OPTIONS）のシグネチャ・値が不変であることを確認する
  - 観測可能な完了条件: tsc と既存テスト3種が全通過し、一方向依存・公開 API 不変・snapshot 一致が確認できる
  - _Requirements: 2.5, 5.1, 5.3, 5.4, 6.5, 7.1, 7.2, 7.3, 8.2, 8.4_
