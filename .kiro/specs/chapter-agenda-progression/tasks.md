# Implementation Plan

- [ ] 1. Foundation: 司会介入を「判定」と「行動」に分離する
- [x] 1.1 出尽くし判定を独立させる
  - アクティブなアジェンダ項目と直近の会話から「出尽くし／論点ずれ／継続」の3値を返す判定を、発言生成・項目選択・指名を伴わない純粋判定として実装する
  - 既存の融合介入（drift/stall）が持っていた判定ロジックを、判定のみへ抽出する
  - 完了条件: アクティブ項目と会話履歴を入力すると3値のいずれかが返り、content や項目選択を一切生成しない
  - _Requirements: 3.1, 3.2_
- [x] 1.2 介入行動（発言生成）を独立させる
  - 決定済み行動「次項目の投入／アクティブ項目への引き戻し／未発言の関連参加者の引き込み」について、司会発言・指名先・関連参加者を生成する
  - 投入は未提示リスト内の項目に限定し、選んだ項目そのものに正面から切り込む問いにする（折衷禁止・リスト外の論点を作らない）
  - 引き込みは未発言の関連参加者を指名し、アクティブ項目を維持する（項目投入・消化はしない）
  - 完了条件: 投入行動はリスト内 index と忠実な問いを返し、リストが空のときは投入発言を生成しない
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 2.2, 2.3, 3.3_

- [x] 2. Core: アジェンダ進行の編成と逐次消化
- [x] 2.1 進行編成を「ゲート→判定→行動」に再構成する
  - 既存の介入編成を、章アジェンダの前進を編成する責務として改名・再構成する（判定→必要なら行動）
  - 既存の保持対象挙動をゲート層として写像する: 立場カバレッジ未充足のときは投入・消化を封じ引き込みに限定、指名チェーン中は論点ずれのみ評価、強い発言意欲者が残るときは前進を抑止
  - 完了条件: 立場カバレッジ未充足時は引き込みのみ・前進が起きず、チェーン中は前進しない、という既存挙動が維持される
  - _Requirements: 3.3, 3.4_
- [x] 2.2 出尽くし判断からアジェンダ項目を逐次消化済みにする
  - アクティブ項目が出尽くしと判断され次項目へ前進するとき、前進元の項目を消化済みにしてから次項目を提示する
  - 未提示項目が残っていない（最後の項目）ときも、新項目を発明せずアクティブ項目を消化済みにする
  - 引き戻しや立場カバレッジ未充足のときは消化済みにしない
  - 消化済みステータスの変更を確実に永続する
  - 完了条件: 前進のたびに前進元が addressed になり永続される。引き戻し・カバレッジ未充足では addressed が付かない
  - _Requirements: 3.1, 3.2, 3.3_

- [x] 3. (P) Core: 全項目消化による章終了条件を追加する
  - 章の全アジェンダ項目が消化済みになったことを検知したら章を終了する分岐を、既存の上限判定の後段・早期終了と並列で追加する
  - 盛り上がり（発言意欲・静穏連続）の高低に関わらず成立させ、末尾に未応答の指名が残るときは最終応答ターンを1回挟む
  - アジェンダ項目を持たない章には適用せず、章ターン上限・討論全体上限をハード終了条件として引き続き尊重する
  - 完了条件: 全項目 addressed の状態を入力すると（上限未達・盛り上がり中でも）章終了を返し、未消化が残る状態では継続を返す
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 6.2, 6.3_
  - _Boundary: decideNextStep_

- [x] 4. Core: 一括カバレッジ評価を撤去し継続保護を非LLM化する
  - 早期終了間際の一括消化評価（消化判定LLM呼び出しと消化更新）を撤去し、消化済みは出尽くし判断由来に一本化する
  - 「未消化が残る間は早期終了を取り消して継続する」保護を、LLMを使わない状態チェックとして残す
  - 未使用化した消化評価関数とそのスキーマを除去する
  - 完了条件: 早期終了経路で消化判定LLMが呼ばれず、未消化が残る間は早期終了せず継続する
  - _Requirements: 5.1, 5.2, 6.1_

- [x] 5. Integration: 最終項目の消化から章終了までを配線する
  - 最後の項目で「発言を生成せず消化済みだけを立てた」場合に、その消化を永続し、余計なペルソナ発言を挟まずに次の終了判定へ渡す（committed-no-turn 方式）
  - 全項目消化の検知から章終了（必要なら最終応答ターン1回）までが、盛り上がり中でも一気通貫で成立する
  - 完了条件: 最後の項目が出尽くしになると、余分な発言なしに章がその場で終了へ向かう
  - _Depends: 2.2, 3_
  - _Requirements: 3.2, 4.1_

- [x] 6. Validation: 単体・統合・回帰テスト
- [x] 6.1 判定/行動/進行編成/終了/撤去の単体テスト
  - 判定（3値）、行動（投入はリスト内 index・忠実／引き戻し／引き込みは未発言関連参加者）を検証する
  - 進行編成（前進で前進元 addressed／最後の項目で addressed のみ／引き戻し・カバレッジ未充足では非更新／チェーン中は前進しない）を検証する
  - 終了判定（全消化→終了、未消化→継続、上限優先、項目なし章は不適用、最終応答+1）と、一括評価撤去後も未消化で早期終了しないことを検証する
  - 完了条件: 上記単体テストが全て通る
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 2.2, 2.3, 3.1, 3.2, 3.3, 3.4, 4.1, 4.2, 4.3, 4.4, 5.1, 5.2, 6.1, 6.2, 6.3_
- [x] 6.2 統合・回帰テスト
  - 全項目消化で章が終了する、未消化では早期終了が抑止される、を統合で検証する
  - アジェンダ外発明が起きない・引き込み（立場カバレッジ）が保持される・次項目投入が論点に忠実、を検証する
  - 既存の司会介入・進行・アジェンダ状態・オーケストレーションのテストが新契約に追随して通ることを確認する
  - 完了条件: 統合シナリオと既存回帰が全て緑
  - _Depends: 5_
  - _Requirements: 1.1, 2.1, 3.2, 4.1, 6.1_
