# Implementation Plan

## 1. 基盤: 型定義とフェーズモデル拡張

- [x] 1.1 (P) 編集成果物の型を定義する（バックエンド）
  - 編集後ターン（散文・発話者種別・ペルソナ・由来となる原本ターンID群・発話モード）、編集後章（章メタ＋編集後ターン列＋編集状態: 未処理/完了/失敗）、編集後コメントの永続型を定義する
  - 由来ターンID群は 1 件以上を必須とし、連結時は複数を許容する不変条件を型・型ガードで表現する
  - 型は Firestore 永続形と一致させ、変換関数は含めない
  - 完了状態: バックエンドがビルドを通り、編集成果物の永続型が参照可能になる
  - _Requirements: 5.3_
  - _Boundary: editorial.types_

- [x] 1.2 (P) 編集成果物の型を定義する（フロントエンド）
  - 表示に必要な編集後章・編集後ターン・編集後コメントの実行時型を、永続形をミラーして定義する
  - 章別の編集状態（完了/失敗/未生成）を表現できるようにする
  - 完了状態: フロントエンドがビルドを通り、表示層が編集成果物の型を参照可能になる
  - _Requirements: 5.3_
  - _Boundary: FE models editedChapter/editedTurn_

- [x] 1.3 (P) フェーズモデルを編集フェーズ（Phase 6）へ拡張する
  - フェーズ番号に 6 を追加し、スラッグ・フェーズ定義一覧・状態別ラベル（実行中/完了/未着手/停止）に編集フェーズを追加する
  - 最終フェーズの表示スタイル判定を編集フェーズに更新する
  - 完了状態: ビルドが通り、ナビゲーションにフェーズ定義一覧から編集タブが生成され、Phase 6 の論理状態が導出できる
  - _Requirements: 1.1_
  - _Boundary: phase model_

## 2. 基盤: 編集成果物の永続層

- [x] 2.1 編集成果物の読み書き・破棄を実装する
  - 編集後章の書き込み（完了/失敗の状態付き）、編集後コメントの書き込み、編集成果物一式（全章＋コメント）の破棄を提供する
  - 保存は生ディベートとは別のコレクションに行い、原本を一切変更しない
  - Firestore 設計原則（ドキュメント上限・課金・埋め込み判断）に従う
  - 完了状態: 編集後章・コメントが所定の別コレクションに書き込まれ、破棄操作で編集成果物のみが消える（原本は不変）
  - _Requirements: 5.1, 5.2, 5.5_
  - _Depends: 1.1_

## 3. コア: 編集者エージェント（LLM）

- [x] 3.1 章単位のリライトエージェントを実装する
  - 章の原本ターン列を入力に、冗長な繰り返し・不要な前置き・冗長な言い回しを除去し、読みやすい散文へリライトした編集後ターン列（各ターンに由来ターンID群を付与）を構造化出力する
  - システムプロンプトに不変条件（意味・立場・事実・帰属の保持、新主張・矛盾の禁止、ペルソナの個性維持、対象言語）を明示する
  - 冗長で新情報のないターンの除外と、除外で生じた同一話者の連続発言の自然な連結を行う
  - 保護対象ターン（信念変化・固有の事実的主張・ファクトチェック指摘を持つ）のID一覧を渡し、除外させない
  - 可読性向上を優先しつつ、意味保持・無矛盾と両立しない箇所のみ原文を維持する
  - 完了状態: LLM をモックした状態で、入力章に対し由来ID付きの編集後ターン列を返す
  - _Requirements: 2.1, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.8, 4.1, 4.2, 4.4, 4.5, 4.6, 4.7_
  - _Boundary: editor-agent_

- [x] 3.2 事後コメントのリライトを実装する
  - 事後コメントの本文を、意味を変えず読みやすくリライトし、由来コメントを保持した編集後コメントを返す
  - 完了状態: LLM をモックした状態で、入力コメント列に対し編集後コメント列を返す
  - _Requirements: 2.2_
  - _Boundary: editor-agent_

## 4. コア: 編集オーケストレーションと完了確定

- [x] 4.1 章編集ステップと構造検証・章別フォールバックを実装する
  - 状態を毎回 Firestore（原本＋世代識別子）から再構築し、対象章をリライトして編集後章を保存し、次章へ連鎖する
  - 構造的検証（由来IDが当該章の原本ターンを指す／保護対象ターンが除外されていない／連結ターンが同一話者・同一ペルソナ／時系列順序が原本と矛盾しない）を行う
  - 検証不合格の章は失敗状態で記録し、その章は原本にフォールバックさせつつ後続章の処理を継続する
  - 章をまたいだ発言の移動・連結、新規発言の追加、時系列順序の入れ替えを行わない
  - 完了状態: 複数章の原本に対し、各章の編集後章（完了/失敗）が保存され、失敗章があっても後続章が処理される
  - _Requirements: 2.3, 2.4, 2.5, 3.7, 4.3, 5.1, 5.2, 6.3_
  - _Depends: 2.1, 3.1_

- [x] 4.2 コメント編集ステップと完了確定を実装する
  - 全章の編集後にコメント編集を実行し編集後コメントを保存する
  - 全章の編集状態を集計し、全章成功なら編集フェーズを完了（generated）に、失敗章が残れば停止（stopped、再実行可）に、世代識別子一致・巻き戻し防止の冪等トランザクションで確定する
  - 完了状態: 全章成功時にフェーズが完了へ遷移し、一部失敗時は停止のまま残る
  - _Requirements: 1.5, 6.5_
  - _Depends: 4.1, 3.2_

- [x] 4.3 編集ランの開始（破棄＋実行中化）を実装する
  - 編集開始時に既存の編集成果物を即時破棄し、編集フェーズを実行中にして新しい世代識別子を発行する
  - 完了状態: 開始操作で旧成果物が消え、フェーズが実行中・新世代になる
  - _Requirements: 1.6, 1.7, 5.5_
  - _Depends: 2.1_

## 5. コア/統合: 編集フェーズの API

- [x] 5.1 編集の起動・再実行・タスク実行のエンドポイントを実装する
  - 認証必須の編集開始エンドポイント（既存成果物破棄→実行中化→最初の章ステップを投入）と、再実行/未実行化のためのリセットエンドポイントを提供する
  - 編集ステップをタスクとして実行する仕組み（LLM 用シークレット・リトライ・終端失敗時の停止化）を用意し、討論完了時に自動実行されないようにする
  - 完了状態: 開始操作で編集チェーンが動き出し、失敗はリトライ後に停止として記録され再実行できる
  - _Requirements: 1.3, 1.4, 1.6, 6.4_
  - _Depends: 4.1, 4.2, 4.3_

## 6. 統合: 討論→編集の遷移とリセット整合

- [x] 6.1 (P) 討論フェーズに編集へ進む承認を追加する
  - 討論が完了状態のときに「討論を確定して編集へ」を操作でき、編集フェーズ（未着手）へ前進させる
  - 討論が未完了の間は編集フェーズの開始操作へ到達できないようにする
  - 完了状態: 討論完了後に承認操作で編集フェーズへ遷移し、未完了時は遷移できない
  - _Requirements: 1.1, 1.2_
  - _Boundary: phase transition (createTopic, Phase5Debate)_

- [x] 6.2 (P) 編集の起動・再実行のフロント呼び出しを実装する
  - 編集開始・再実行の操作をバックエンドのエンドポイント呼び出しに接続する
  - 完了状態: 画面操作から編集開始・再実行が実行される
  - _Requirements: 1.3, 1.7_
  - _Boundary: createTopic editing methods_
  - _Depends: 5.1_

- [x] 6.3 (P) 討論のリセット/再開時に編集成果物を破棄する
  - 討論の全章リセット・指定章以降の再開で付随データを削除する既存処理に、編集成果物の破棄を加える
  - 完了状態: 討論を reset/restart すると編集成果物も必ず破棄され、原本再生成との不整合が残らない
  - _Requirements: 5.6_
  - _Boundary: debate-lifecycle discard_
  - _Depends: 2.1_

## 7. 統合: 編集成果物の表示

- [x] 7.1 (P) 編集成果物の購読ストアを実装する
  - 編集後章を章順に購読し、章別の編集状態（完了/失敗/未生成）を提供する
  - 完了状態: 編集後章の変更がリアルタイムに反映され、UI が章単位で表示切替を判定できる
  - _Requirements: 6.6, 6.7_
  - _Boundary: editedChapters store_
  - _Depends: 1.2_

- [x] 7.2 編集フェーズ画面とルートを実装する
  - 編集フェーズのルートと画面を追加し、編集開始・再実行ボタン、実行中の進行表示、編集状態の確認を提供する
  - 章別に、完了章は編集成果物を表示し、失敗章・未生成章はその章のみ原本にフォールバックする
  - 各章の編集状態（編集済み/原本表示(失敗)/未編集）を表示して部分失敗を管理者が把握できるようにする
  - 完了章の編集後ターンに対し、信念変化・ファクトチェック指摘を由来ターンID群経由で原本から結合表示する（連結ターンは由来注釈の和集合を表示、発話モードは全一致時のみ表示）
  - 完了状態: 討論確定→編集開始→進行表示→編集成果物表示までを画面で通しで操作でき、部分失敗時は章別に切替表示される
  - _Requirements: 1.1, 1.3, 1.4, 6.1, 6.2, 6.3, 6.4, 6.6, 6.7_
  - _Depends: 5.1, 6.2, 7.1_

## 8. 検証: テスト

- [x] 8.1 (P) 編集者エージェントのユニットテスト
  - LLM をモックし、構造化出力の検証・保護対象ターンの保持・連結ターンの話者整合を検証する
  - 完了状態: 保護対象を落とす/話者が食い違う出力を検出できるテストが通る
  - _Requirements: 3.7, 4.3, 4.4_
  - _Depends: 3.1_

- [x] 8.2 (P) 構造検証と章別フォールバックのユニットテスト
  - 由来ID妥当性・保護対象残存・話者整合・時系列の合否分岐と、不合格章の失敗記録＋後続章継続を検証する
  - 完了状態: 一部章が不合格でも後続章が処理され、失敗章が失敗として記録されるテストが通る
  - _Requirements: 2.4, 2.5, 3.7, 6.3_
  - _Depends: 4.1_

- [x] 8.3 (P) 完了確定のユニットテスト
  - 全章成功で完了、失敗章残存で停止、世代不一致・前進済みでの巻き戻し防止を検証する
  - 完了状態: 全章成功時のみ完了に遷移し、部分失敗時は停止に留まるテストが通る
  - _Requirements: 1.5, 6.5_
  - _Depends: 4.2_

- [x] 8.4 (P) 破棄処理とフェーズ論理状態のユニットテスト
  - 編集成果物の破棄（原本不変）と、編集フェーズを含む論理状態導出を検証する
  - 完了状態: 破棄後に編集成果物のみ消え、Phase 6 の論理状態が正しく導出されるテストが通る
  - _Requirements: 1.6, 1.1_
  - _Depends: 2.1, 1.3_

- [x] 8.5 編集チェーンとリセット整合の統合テスト
  - 編集開始→章チェーン→コメント→完了の通し、討論 reset/restart での編集成果物破棄、再実行時の旧成果物の即時破棄を検証する
  - 完了状態: 通し実行で完了に至り、リセット/再開/再実行で編集成果物が確実に破棄される統合テストが通る
  - _Requirements: 1.6, 1.7, 5.5, 5.6_
  - _Depends: 5.1, 6.3_

- [ ]* 8.6 編集フェーズ表示のE2Eテスト
  - 討論確定→編集開始→編集成果物表示の主要導線と、部分失敗時の章別ステータス表示・再実行を検証する（受入基準 6.4 を担保する補助的カバレッジ、MVP後に実施可）
  - 完了状態: 主要導線と部分失敗表示の E2E が通る
  - _Requirements: 6.1, 6.2, 6.4_
  - _Depends: 7.2_
