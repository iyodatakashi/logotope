# Implementation Plan

> 順序は design の Migration Strategy に従う：**1–3 でエンジンを本番未接続で構築 → 4 で 2.5 検証（ゲート）→ 通過後にのみ 5 で本番復旧・配線**。seeds は手動調整済みの確定アセット（git コミット済み）で、`build-avatar-seeds` は再実行しない。

## 1. Foundation: 定数・seed 分類・カタログ

- [ ] 1.1 効くパラメータを単一定義の定数にする
  - 256（正方）・0.92（縦占有・下端接地）・36（影しきい値）・顔高45（仮）を1箇所の定数として定義し、各値の測定元と根拠、顔高は「仮・境界定義後に再調整」をコメントで残す
  - 後処理・seed 選択・プロンプトがこの定数を参照できる状態にする（ピクセルにのみ存在する数値をゼロにする）
  - _Requirements: 1.2, 2.2, 2.3_

- [ ] 1.2 seed の分類と決定的選択・命名を実装する
  - 世代（child/young/middle/senior/elder）× 外見表現（masculine/feminine、androgynous は型に持つが seed バケットに含めない）を定義し、`{generation}_{presentation}_{index}` の発番後不変な命名で 40 枚を一意識別する
  - `age → 世代`、`genderPresentation → 外見表現` を写像し、`(personaId, attempt)` から決定的に seed を1枚選ぶ。適合 seed が無い外見表現（androgynous）は「seed 無し」を返す
  - 完了条件: 同一 `(personaId, attempt)` が常に同一 seed を返し、androgynous は seed 無しになる（単体テストで確認）
  - _Requirements: 2.6, 3.7, 6.6, 1.1_
  - _Depends: 1.1_

- [ ] 1.3 可変軸カタログと決定的導出を実装する
  - 髪型（世代×外見表現）・体型・ポーズ・アングル・メガネのカタログを、後から追記で拡張でき、要素数に依存する処理や全組み合わせ列挙を持たない形で定義する
  - `(personaId, attempt)` から各軸の値を決定的に選ぶ。初回（attempt=0）は同一 persona で常に同一、再生成は attempt を変えて別の軸を引く
  - 完了条件: 同一 `(personaId, attempt)` が常に同一の軸集合を返し、カタログに1件追記しても既存挙動が壊れない（単体テストで確認）
  - _Requirements: 3.2, 3.5, 3.6_
  - _Depends: 1.2_

- [ ] 1.4 seed 生成スクリプトを整合した「記録」にする（再実行しない）
  - 元素材の参照をプロジェクトルート `avatar-materials/` に向け、外見表現を masculine/feminine に、正規化値を単一定義の定数参照に直し、4分割→縦占有0.92・下端接地・横中央・256正方・横はみ出し・規定外は失敗報告、という初期導出手順が読める記録にする
  - 完了条件: スクリプトが型的に整合して読める記録になり、かつ手動調整済み seeds を上書きしないよう「再実行しない」と明記される（実行はしない）
  - _Requirements: 2.1, 2.4, 2.5, 2.6_
  - _Depends: 1.1_

## 2. Core: 生成部品

- [ ] 2.1 (P) 編集ベースの生成プロンプトを実装する
  - 添付 seed を編集の元画像として別個体を作る指示を組み立てる。様式は seed 準拠（黒基調＋襟・ボタン等の線描・白髪は筋ストローク、顔の内側だけ白抜き・輪郭線は seed 準拠、背景純白・影なし・バストアップ・アイコン的単純化・真剣な表情）
  - ズーム・目線・顔高45%・下端接地のみを固定し、体型・髪型・ポーズ・アングル・メガネは指定値で振る。年齢は皺・灰色でなくシルエットで表す
  - 完了条件: 与えた軸値どおりの指示文が決定的に生成され、黒ベタ強制や輪郭線禁止など seed と矛盾する句を含まない（スナップショットテストで確認）
  - _Requirements: 3.1, 3.3, 3.4, 4.1, 4.2, 4.3, 4.4, 5.1, 5.2, 5.3, 5.4, 5.6, 5.7_
  - _Boundary: avatar-prompt_
  - _Depends: 1.3_

- [ ] 2.2 (P) 後処理を流用し定数配線とゴールデン担保をする
  - 既存の後処理（輝度→アルファ・影しきい値除去・bbox クロップ・高さ基準スケール・下端接地・256 の RGB=黒アルファ透過 PNG）を、自前定数でなく単一定義の定数を参照する形に配線する。白髪・明るい衣服は透明に落とさず薄いアルファ階調として残す
  - 完了条件: 同一入力に決定的に同一 PNG を返し、`postprocess.py` とのゴールデン等価テストが通る。出力はシルエット色/背景色を再生成なしで独立指定できるアルファ形態になる
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5_
  - _Boundary: avatar-postprocess_
  - _Depends: 1.1_

- [ ] 2.3 (P) 画像モデルクライアントを実装する
  - `gemini-2.5-flash-image` を TEXT+IMAGE モダリティ明示で呼び、seed 画像を file パートで添付する。一時失敗・画像未返却は数回リトライし、使い切ると失敗として返す
  - 完了条件: プロンプト＋seed から画像バイト列を返し、画像未返却時はリトライ後に失敗を返す（モックで確認）
  - _Requirements: 7.4_
  - _Boundary: avatar-image-client_
  - _Depends: 1.1_

## 3. Core: 共有エンジン統合

- [ ] 3.1 唯一の生成実装（共有エンジン）を組み立てる
  - 入力（personaId・attempt・age・genderPresentation・occupation。gender は渡さない）から、seed 選択→可変軸導出→プロンプト→モデル呼び出し→後処理を束ね、256 透過 PNG を返す。適合 seed 無し（androgynous）と生成失敗を判別できる戻り値にする（throw しない）
  - Firestore/Storage には触れない純粋生成にする（本番と検証の双方がこの実装だけを呼べる）
  - 完了条件: 正常時はアセットバイト列、androgynous は「seed 無し」、失敗は「生成失敗」を返す
  - _Requirements: 1.1, 1.4, 3.1_
  - _Depends: 2.1, 2.2, 2.3_

- [ ] 3.2 エンジンと選択ロジックの単体・結線テストを書く
  - seed 選択・可変軸導出の決定性と分散、世代境界（12/13・29/30・49/50・69/70）、androgynous の seed 無し経路、エンジンをクライアントモックで通した結線を検証する
  - 完了条件: 上記テストが緑になる
  - _Requirements: 1.1, 1.4, 3.6, 3.7_
  - _Depends: 3.1_

## 4. Validation Gate: 2.5 検証（通過するまで 5 に進まない）

- [ ] 4.1 検証ハーネスをエンジン経由・2.5 に整える
  - 検証ハーネスが共有エンジンを呼ぶ形にし、モデルを 2.5 にする。全10バケット（＋同一バケット内の散り）を網羅するケースで、生成物を検証専用の出力先（入力 seed とは別ディレクトリ）へ保存し、枠（正方・縦占有0.92・下端接地）を実測する
  - 完了条件: 2.5 で一連の生成物と枠の実測値が出力され、入力（seeds）と出力（生成結果）が別ディレクトリに分かれている
  - _Requirements: 7.1, 7.2, 7.4, 1.3, 1.4_
  - _Depends: 3.1_

- [ ] 4.2 2.5 で実生成し合否・再現性を記録する（成立ゲート）
  - 実生成を行い、機械判定できる枠と、機械判定できない項目（様式・顔の非描写・指定軸への適合）を合格例/不合格例基準で人が判定する。同一指示の合格率を記録し、顔高45%の適否と「顔」の測定境界をここで詰める。逸脱は指示改善案として記録する
  - 完了条件: スタイル基準を全項目満たす合格物が複数バケットで得られ、合否・再現性・顔高の確定値が記録される。**満たすまでプロンプトを反復し、5 に進まない**
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.7, 7.1, 7.3, 7.4, 7.5_
  - _Depends: 4.1_

## 5. Integration: 本番復旧・配線（4.2 通過後のみ）

- [ ] 5.1 本番生成経路を共有エンジンで再実装する
  - ペルソナを読み、開始時に生成時刻を即時削除し、共有エンジン（初回 attempt=0）で生成→後処理済みアセットを既存の Storage 配置（`topics/{topicId}/avatars/{personaId}`）へ保存→生成時刻を記録する。androgynous（seed 無し）と生成失敗は生成時刻を未設定のまま残し、失敗を握りつぶして討論生成を止めない
  - 完了条件: 1ペルソナのアバターが生成・保存・記録され、androgynous と失敗は未生成として観測できる
  - _Requirements: 1.1, 1.4, 3.7, 6.4_
  - _Depends: 4.2_

- [ ] 5.2 個別再生成（onCall）を共有エンジンで実装する
  - 認証のうえ再生成を実行し、開始時に旧アバターの生成時刻を即時削除する。再生成は attempt を変えて別の seed／軸を引く
  - 完了条件: 再生成を繰り返すと別の seed／軸のアバターに置き換わる
  - _Requirements: 1.1_
  - _Depends: 5.1_

- [ ] 5.3 パイプライン配線・export・モデル定数を復旧しビルドを通す
  - ペルソナ生成チェーンの avatar ステップと Functions の export を新しい本番生成経路へ再配線し、アバター用画像モデル定数を 2.5 にする。検証済みエンジンを本番に反映して確定コードとする
  - 完了条件: functions が型的に整合してビルドが通り、パイプラインからアバター生成が呼ばれる
  - _Requirements: 1.4, 1.5_
  - _Depends: 5.1_

- [ ] 5.4 既存ペルソナのバックフィルを整合させ統合テストを書く
  - 既存ペルソナのアバター生成を新しい本番経路へ通す。runtime を Firestore/Storage/エンジンのモックで通し、成功時の生成時刻記録・androgynous と失敗時の未設定・例外握りつぶしを検証する
  - 完了条件: バックフィルが新経路で動き、上記の runtime 分岐がテストで緑になる
  - _Requirements: 1.4, 2.6_
  - _Depends: 5.3_
