# Implementation Plan

> フィジビリ主眼。最大リスク（2色独立着色の描画成立）を先頭で実証してから、生成・後処理・検証へ進む。全カタログ量産とペルソナ割り当ては対象外。

- [x] 1. デリスク: 2色独立着色の描画を実証する
- [x] 1.1 既存サンプル1枚を手作業でアルファ透過PNGへ変換する
  - 既存サンプル画像1枚を「被写体=不透明・顔の内側と外側背景=透明」のモノクロ透過PNGに変換する（後処理レシピの手動先行版）
  - 観察可能な完了条件: 顔の内側と背景が透明、被写体だけが不透明な256×256pxのPNGが1枚存在する
  - _Requirements: 5.3, 6.1_

- [x] 1.2 アバター表示を背景色・シルエット色の独立指定に作り替える
  - 表示コンポーネントを、画像・シルエット色・背景色を受け取り、アルファをマスクにした単色塗り＋背景色の2層で描画する方式に変更する
  - `mix-blend-mode` による乗算結合を撤去し、2色が縁で濁らないアルファ合成にする
  - 既存の引数なし呼び出し箇所が壊れないことを確認する
  - 観察可能な完了条件: 同一アセットに別々の色トークンを与えると、シルエットと背景（顔の内側含む）が独立した2色で表示され、縁が濁らない
  - _Requirements: 5.1, 5.2, 5.3, 6.2_
  - _Depends: 1.1_

- [x]* 1.3 表示コンポーネントの色指定反映を最小テストで確認する
  - 3つの色・画像指定が対応する描画変数へ反映されることを確認する
  - 観察可能な完了条件: シルエット色・背景色・画像の指定が反映されることを検証するテストが通る
  - _Requirements: 5.1_

- [x] 2. 生成仕様・指示・受け入れ基準を確立する
- [x] 2.1 バリエーション仕様と髪型カタログを機械可読な定義に落とす
  - 軸（年齢帯・性別・髪型・アングル・ポーズ・服装・メガネ）と各区分値、(年齢帯×性別)別の髪型カタログを参照可能な定義にする
  - serial は発番後不変の通し番号とし、serial↔髪型 の対応表（カタログ順に依存しない）を用意する
  - 観察可能な完了条件: 指定した軸の組合せと安定 serial から、対象バケットの生成対象が一意に定まる
  - _Requirements: 2.1, 2.2, 2.3, 2.4_

- [x] 2.2 (P) スタイル基準と軸適合の受け入れチェックリストを定義する
  - 背景の一様性・被写体の暗さ（マスク抽出可能性）・顔の非描写・バストアップ構図・2色分離可能なネガティブスペース・線/塗り様式を合否判定項目として列挙する
  - 判断が割れる項目には合格例/不合格例の対を添える
  - 観察可能な完了条件: 任意の生成物に対し、各項目で合否を機械的に判定できるチェックリストが存在する
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 4.1, 4.2, 4.3_
  - _Boundary: Acceptance Checklist_

- [x] 2.3 スタイル固定の規範プロンプトと参照画像アンカーを定義する
  - スタイル固定文（無地白背景・顔なし・黒基調・バストアップ・単純化された髪と衣服）を常に含め、各軸の値を明示的に埋め込む指示テンプレートを作る
  - 既存サンプルを参照画像（最大3枚）としてスタイルアンカーに使う方針を組み込む
  - 観察可能な完了条件: あるバリエーション仕様から、同一の規範プロンプトと参照画像の組が再現的に得られる
  - _Requirements: 3.1_
  - _Depends: 2.1_

- [x] 3. オフライン生成・後処理ツールを用意する
- [x] 3.1 指示駆動の生成スクリプトを用意する
  - バリエーション仕様から規範プロンプトと参照画像を組み立て、画像生成モデルを呼んで白背景の候補画像を取得・保存する
  - バリエーションはモデル裁量任せにせず、指定した軸の値で出し分ける
  - 観察可能な完了条件: 指定した仕様に対して、白背景の候補画像がファイルとして生成・保存される
  - _Requirements: 2.2, 3.1, 3.2_
  - _Depends: 2.1, 2.3_

- [x] 3.2 (P) 白背景画像を正規アセットへ変換する後処理を用意する
  - 白背景の候補を、輝度→アルファ（黒=不透明・白=透明・中間=半透明）変換＋正方トリミング＋256×256pxリサイズで、色を持たない透過PNGに確定変換する
  - フォーマット・寸法が利用条件を満たさない入力に対する後処理（トリミング・リサイズ・透過化）を含める
  - 観察可能な完了条件: 白背景画像を入力すると、決定的に同一の256×256pxアルファ透過アセットが得られる
  - _Requirements: 4.2, 5.3, 5.4, 6.1, 6.3_
  - _Boundary: Postprocess_

- [x] 4. 試験生成で実現可能性を検証する
- [x] 4.1 代表バリエーションを複数生成し合否を記録する
  - 軸の値を指定した複数の組合せを生成し、(a)スタイル基準 (b)指定バリエーション（年齢帯・性別・アングル・メガネ有無・表情）の両面でチェックリスト判定して合否を記録する
  - 観察可能な完了条件: 複数バリエーションの生成物ごとに、スタイルと軸適合の合否が記録される
  - _Requirements: 3.2, 3.3_
  - _Depends: 3.1, 2.2_

- [x] 4.2 同一指示の再現性を測り指示を改善する
  - 同一指示を複数回実行し合格率を記録する。逸脱時は逸脱項目（スタイル項目か、どの軸か）を特定し指示改善案として記録する
  - 観察可能な完了条件: 同一指示の合格率と、逸脱項目に対する指示改善メモが残る
  - _Requirements: 3.4, 3.5_
  - _Depends: 4.1_

- [x] 4.3 合格物を後処理し実証アセットとして表示確認する
  - 合格した複数区分の候補を後処理して命名規則で配置し、2色独立着色の表示に載せて意図どおりのバリエーションが出ることを確認する
  - 観察可能な完了条件: 少数の実証アセットが命名規則で配置され、2色独立で正しく表示される
  - _Requirements: 3.6, 5.2, 6.1_
  - _Depends: 3.2, 4.1, 1.2_

- [x] 4.4 量産可否（Go/No-Go）の結論をまとめる
  - スタイル再現性・網羅可能性・受け入れ品質・独立着色の成立を踏まえて量産可否を提示する。不成立なら代替アプローチを挙げ、量産に進む場合の残作業（用意すべきパターン総数・後処理・命名整備）を列挙する
  - 観察可能な完了条件: 合格率と各観点の判断を伴う Go/No-Go 結論と残作業リストが残る
  - _Requirements: 7.1, 7.2, 7.3_
  - _Depends: 4.2, 4.3_

- [ ] 5. 本番表示へ最小反映する
- [ ] 5.1 公開記事の発言表示を新しい色指定呼び出しへ更新する
  - 公開記事の発言表示から、色トークンと実証アセットを渡す新しい呼び出しへ最小更新する（割り当てロジックは持ち込まない）
  - 観察可能な完了条件: 公開記事の発言に、2色独立着色のアバターが表示される
  - _Requirements: 5.1, 6.2_
  - _Depends: 1.2, 4.3_
