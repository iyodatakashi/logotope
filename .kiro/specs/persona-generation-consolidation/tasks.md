# Implementation Plan

## 前提・順序の要点

- **Functions 変更は本番デプロイを伴う**（エミュレータ未使用）。BE のチェーン実装（タスク3・4）は一括で仕上げてからデプロイ・検証する。
- **既存トピックは移行しない**（削除前提）。廃止フィールド（`stakeholders.selected` / `persona.approved`）は型から即削除し、型エラーを漏れ検出に使う。
- 依存の背骨: フェーズ型の統合（タスク1）→ データ型の置換（タスク2）→ BE 連鎖（タスク3）→ 完了判定・下流フィルタ（タスク4）→ FE 再構成（タスク5）→ 統合配線（タスク6）→ 非退行・検証（タスク7）。

---

- [x] 1. Foundation: フェーズ定義を6値へ統合する
- [x] 1.1 FE/BE の `PhaseSlug` から `stakeholders` / `interviews` を削除し6値へ揃える
  - フロントとFunctionsの永続フェーズ集合を `theme` / `fact-research` / `personas` / `chapters` / `debate` / `editing` の6値・同一順序にする
  - Functions の生成確定フェーズ集合から `stakeholders` / `interviews` を除き `personas` を残す
  - 「正準リスト」の型網羅テストを6値へ更新し、緑になることを確認する
  - 完了条件: FE/BE の型チェックが通り、正準リストテストが6値で一致して緑
  - _Requirements: 1.1, 1.2, 1.3_

- [x] 1.2 フェーズ定義の状態ラベルとステップナビを1フェーズへ更新する
  - `personas` フェーズの状態ラベルを一気通貫全体（未着手・実行中・完了・停止）を表す文言へ更新する
  - ステップナビの「ペルソナ生成」ステップを単一フェーズ `personas` に対応させる（3フェーズ束ねを解く）
  - `personas` の `phaseStatus` は全体1軸（段階別ステータスを持たせない）で扱う方針をラベルに反映する
  - 完了条件: ステップナビが `personas` を1ステップとして解決し、既存のステップナビ仕様テストが緑
  - _Requirements: 1.3, 1.4, 1.5_

- [x] 1.3 ルートを `/personas` に一本化し旧ルートを廃止する
  - `/stakeholders` と `/interviews` のルートを削除し、ペルソナ生成画面のルートを `/personas` 1本にする
  - 未到達フェーズのリダイレクトガードが6値フェーズで正しく動くことを確認する
  - 完了条件: `/personas` が正となり、`/stakeholders` `/interviews` が存在しない
  - _Requirements: 1.6_

- [x] 2. データ型の採用選択への置換（承認フラグ廃止）
- [x] 2.1 ペルソナの `approved` を廃し `selected` を新設する
  - ペルソナの永続型から承認フラグを削除し、採用選択フラグを追加する
  - ペルソナ生成の永続時に採用を既定 ON（`selected: true`）で焼き込む（生成エージェントの構築値も追随。生成の意味は不変）
  - 未設定時は既定 ON として扱う方針を型・境界で担保する
  - 承認フラグに付随する型・付与経路をコード・型から残さず撤去する
  - 完了条件: ペルソナ生成で作られる各ペルソナが `selected: true` を持ち、承認フラグがコードベースに残らない
  - _Requirements: 4.1, 4.2, 4.5, 4.8, 8.5_

- [x] 2.2 ステークホルダーの `selected`（採用チェック）を撤去する
  - ステークホルダーの永続型・ストアから採用選択を削除し、既定 ON 解決ロジックも除去する
  - ステークホルダーストアを表示専用にし、採用トグルの書き込み経路を撤去する
  - 完了条件: ステークホルダーに採用の概念が残らず、全ステークホルダーがペルソナ生成対象になる
  - _Requirements: 3.2, 3.3, 3.4, 3.5_

- [x] 3. Core: ペルソナ生成の一気通貫チェーン（BE・Cloud Tasks）
- [x] 3.1 取材本体を共有可能なコア関数へ抽出する
  - 現行の取材 onCall から取材実行の中身を、HTTP 非依存のコア関数として切り出す
  - 既存の取材 onCall（再取材用）がコア関数を呼ぶ形へ置き換え、挙動が変わらないことを確認する
  - 完了条件: 単一ペルソナ取材のコア関数が存在し、既存 onCall 経由の取材が現行どおり動く
  - _Requirements: 5.3, 7.1, 7.2_
  - _Boundary: interviews pipeline_

- [x] 3.2 決定的タスク識別子と投入層を用意する
  - ペルソナ連鎖用のステップ投入層を、討論・編集と同型（決定的 task id・ALREADY_EXISTS 収束）で用意する
  - task id の鍵に runId と段階（および取材段はペルソナ id）を含め、二重投入が1本へ収束することを担保する
  - 完了条件: 同一段の再投入が二重実行にならず1本へ収束する投入層が存在する
  - _Requirements: 8.1, 8.3_
  - _Boundary: personas pipeline_
  - _Depends: 3.1_

- [x] 3.3 段階連鎖の本体（ステークホルダー→ペルソナ→取材）を実装する
  - 単一のタスクディスパッチャで段階を判別し、各段完了で次段を投入する自己連鎖を実装する
  - ステークホルダー段は生成物を永続し次段を投入、ペルソナ段は全ステークホルダーを対象に生成して各ペルソナへ採用既定 ON を焼き、ペルソナごとに取材段を投入する
  - 取材段はペルソナ単位でコア関数を実行し結果を永続する（取材失敗は当該ペルソナに `error` として記録する）
  - 各ペルソナに由来ステークホルダーの安定 id 対応を付与し続ける
  - **中間段（ステークホルダー・ペルソナ）は完了確定を書かない**（確定は取材段の完了判定のみ。早期 generated 遷移を防ぐ）
  - 各段の生成物を生成され次第 Firestore に永続し、画面が逐次表示できる状態にする
  - 完了条件: 1回の起動でステークホルダー→ペルソナ→全ペルソナ取材が順に永続され、段階の生成物が逐次現れる
  - _Requirements: 2.1, 2.3, 2.4, 2.7, 7.3, 7.5, 8.2, 8.4_
  - _Boundary: personas pipeline_
  - _Depends: 3.2_

- [x] 3.4 連鎖の起動 API と実行中・停止の状態管理を実装する
  - 連鎖起動 API を、フェーズを実行中にし runId を発行して最初の段を投入するだけの短時間 onCall として実装する（在席非依存でサーバ完結）
  - 各段の終端失敗（最終リトライ）でフェーズを停止にする
  - 完了条件: 起動 API 呼び出し後、クライアントが離脱してもサーバ側で連鎖が最後まで進み、途中失敗ではフェーズが停止になる
  - _Requirements: 2.1, 2.2, 2.5, 5.1_
  - _Boundary: personas pipeline, API Layer_
  - _Depends: 3.3_

- [x] 4. 完了判定（採用基準）と下流フィルタの置換
- [x] 4.1 完了確定を `personas` フェーズ・採用基準へ変更する
  - 取材完了集約の確定先を `personas` フェーズに変更する
  - 完了判定を採用（`selected`）ペルソナ基準にする — 採用ペルソナが1件以上あり全員取材完了のときのみ確定する
  - 採用0件では確定しないガードを入れる（不採用ペルソナの取材状態は判定に含めない）
  - 完了条件: 採用ペルソナ全員が取材完了で `personas` が完了確定し、不採用の失敗ペルソナが残っていても確定を妨げない
  - _Requirements: 2.6, 4.9, 4.10, 5.4_
  - _Boundary: interviews pipeline_
  - _Depends: 3.1_

- [x] 4.2 章立て・討論・編集の参加者フィルタを採用基準へ置換する
  - 章立て・討論・編集の各所で参加ペルソナの判定を承認基準から採用基準（`selected`）へ置換する
  - 討論ダイジェストの変数名など、承認前提の名残を採用基準の語へ揃える
  - 編集画面の所感対象フィルタも採用基準へ置換する（フェーズ論理状態の `approved` 判定は対象外・混同しない）
  - 完了条件: 章立て・討論・編集の参加者が採用ペルソナに限定され、承認フラグ参照がコードベースに残らない
  - _Requirements: 4.6_
  - _Boundary: chapters pipeline, debate pipeline, editing pipeline, EditingPage_
  - _Depends: 2.1_

- [x] 5. Core: ペルソナ生成画面の再構成
- [x] 5.1 操作ペインを単一スロット（実行／再生成）へ再構成する
  - 操作ペインの実行操作を1つにし、状態で表示を入れ替える（未生成=実行 / 実行中=実行中表示 / 生成済み=最初から再生成）
  - ステークホルダー生成・ペルソナ生成・取材開始の独立操作を撤去する
  - 「最初から再生成」は確認ダイアログを表示し、承諾時のみ下流（章立て・討論・編集）を現行の破棄範囲どおり破棄してから一気通貫を最初から実行する
  - 一気通貫の進行段階（ステークホルダー生成中・ペルソナ生成中・取材中）を、生成物の存在と取材状態から導出して表示する
  - 暫定的にコメントアウトされたマークアップを残さない
  - 完了条件: 画面の実行操作が1つになり、状態に応じて実行／再生成が切り替わり、実行中は進行段階が表示される
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.6, 6.8, 7.4_
  - _Boundary: GeneratePersonaPage_
  - _Depends: 3.4_

- [x] 5.2 (P) ステークホルダー表示を中間生成物化する
  - ステークホルダーの採用チェックボックスを外し、表示専用にする
  - 各ステークホルダーと、そこから生成されたペルソナの対応関係を表示し続ける
  - 完了条件: ステークホルダーが採用操作なしの中間生成物として表示され、対応ペルソナとの関係が見える
  - _Requirements: 3.1, 3.6_
  - _Boundary: StakeholderItem, StakeholderPersonaRow_
  - _Depends: 2.2_

- [x] 5.3 (P) ペルソナに採用チェックボックスと再取材ボタンを追加する
  - 各ペルソナに採用/不採用のチェックボックスを設け、安定 id をキーに採用選択を永続する（リロード後も保持）
  - 各ペルソナに再取材ボタンを取材の成否に関わらず常時設け、単一ペルソナの取材を実行する
  - 再取材中は当該ペルソナを取材中として表示し、取材状態（取材中・完了・失敗）を表示する
  - 取材全体の一括やり直し・フェーズ単位の一括再開は設けない
  - 完了条件: ペルソナ単位で採用トグルと再取材ができ、採用選択が永続し取材状態が表示される
  - _Requirements: 4.3, 4.4, 4.7, 5.2, 5.3, 5.5, 5.6, 6.7_
  - _Boundary: PersonaItem, personasStore_
  - _Depends: 3.1, 2.1_

- [x] 6. Integration: 起動・前進・採用ゲートの配線
- [x] 6.1 起動・再取材・再生成をモデル／ストア経由で画面に配線する
  - 画面の実行操作を連鎖起動 API に、再取材を単一ペルソナ取材に、再生成を下流破棄＋起動に配線する
  - 撤去する承認系メソッド（ペルソナ承認・段階別承認）とバッチ取材メソッド、および付随する型・テストを残さず取り除く
  - 完了条件: 画面から1操作で一気通貫が起動し、ペルソナ単位の再取材と最初からの再生成が動作し、承認系・バッチ系のメソッドが残らない
  - _Requirements: 2.1, 5.3, 6.4, 6.5, 8.5_
  - _Boundary: GeneratePersonaPage, personasStore, createTopic model_
  - _Depends: 3.4, 5.1, 5.3_

- [x] 6.2 採用ゲートと `personas`→`chapters` 前進を実装する
  - `personas` から `chapters` へ前進させるドメインメソッドを新設する（撤去する承認系メソッドと名が衝突しない名前）
  - 前進の前提条件「採用ペルソナ1件以上」を本仕様の所有物として定義し、採用0件では前進不可・その旨を画面で示す
  - 完了条件: 採用が1件以上あるときのみ次フェーズへ前進でき、採用0件では前進が止まりその旨が表示される
  - _Requirements: 4.10_
  - _Boundary: GeneratePersonaPage, createTopic model_
  - _Depends: 5.3, 6.1_

- [ ] 7. Validation: 非退行と統合検証
- [x] 7.1 フェーズ統合・採用置換に伴う既存テストを更新する
  - フェーズ順・フェーズ集合を検証するテストを6値へ更新する（事実リサーチの次フェーズが `personas` になること等）
  - 承認フラグ・旧フェーズ slug・旧ボタン文言に依存する既存テスト（ペルソナ画面・ストア・型・関連ページ）を新仕様へ更新する
  - 完了条件: 既存のユニット／コンポーネントテスト群が新仕様で緑
  - _Requirements: 1.1, 1.2, 4.1_
  - _Depends: 1.1, 2.1_

- [x] 7.2 完了判定と採用選択の非退行をテストする
  - 完了判定が採用基準で動くこと（採用全員完了で確定、不採用の失敗は妨げない、採用0件で未確定）を検証する
  - 採用トグルが安定 id で当該ペルソナのみ更新し、不採用にしても取材結果が破棄されないこと、再採用で再取材不要なことを検証する
  - 章立て・討論・編集が採用ペルソナのみを参加者にすることを検証する
  - 完了条件: 上記の完了判定・採用選択・下流フィルタの単体テストが緑
  - _Requirements: 2.6, 4.6, 4.9, 4.10, 5.4_
  - _Depends: 4.1, 4.2, 5.3_

- [ ] 7.3 一気通貫と停止回復を実環境で検証する
  - 本番 Functions へデプロイし、1操作でステークホルダー→ペルソナ→全ペルソナ取材が進み `personas` が完了確定することを確認する
  - 取材1件失敗→停止→当該ペルソナ再取材→完了確定（停止からの回復）を確認する
  - 起動後にクライアントを離脱させても連鎖がサーバ側で完了することを確認する
  - 生成ロジック（プロンプト・モデル・事実基盤の受け渡し）と取材結果・信念の永続構造が現行どおりであることを確認する
  - 完了条件: 実環境で一気通貫・停止回復・在席非依存が動作し、生成の中身と永続構造が非退行
  - _Requirements: 2.1, 2.2, 2.6, 5.1, 5.4, 7.1, 7.2, 7.3, 7.4, 7.5_
  - _Depends: 3.4, 4.1, 6.1_
