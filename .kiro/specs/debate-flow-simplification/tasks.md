# Implementation Plan

> 進め方の原則: 「純粋な整理（振る舞い不変）」と「確定した振る舞い変更（BC1: B クールダウン除去 / BC2: 指名優先 / BC3: 毎ターン評価）」をコミット単位で分離する。各タスク境界で Vitest をグリーンに保ち、変更対象テストのみ期待値を更新する。

- [x] 1. 基盤: フロー制御定数と高意欲述語の単一化
- [x] 1.1 制御定数を単一定義に集約する
  - 失効ターン数の二重定義を解消し、単一の定義元から全箇所が参照する状態にする
  - 発言意欲の高意欲境界・連続直接質問上限・クールダウン既定・章ターン関連の比率/上限・活性シグナル窓を意味の分かる名前付き定数に集約する
  - キュー追加（境界以上）とキュー選択（境界未満）が同一境界を逆向きに使うことを、単一定数と比較方向の表現で固定する
  - 観測可能な完了条件: 失効ターン数・各閾値の定義が1箇所のみになり、既存の純関数テストがグリーンのまま（振る舞い不変）
  - _Requirements: 6.1, 6.2, 6.4_
- [x] 1.2 「高意欲」判定述語を新設し活性シグナル判定を寄せる
  - 単一ペルソナ用と集合用の高意欲述語を純関数として定義し、高意欲境界定数から導出する
  - 活性シグナル判定をこの述語と活性強スコア定数で表現し直す（散在した境界ハードコードを除去）
  - 観測可能な完了条件: 活性シグナルの単体テストが述語ベースでグリーン、後続の B ゲート・キュー選択が同述語を参照できる状態
  - _Requirements: 6.3_

- [x] 2. 評価ステップの抽出と毎ターン全員評価への統一（BC3）
- [x] 2.1 全員評価・可視化保存・キュー保守を毎ターンの単一ステップに抽出する
  - 巨大メソッドから「全員（直前話者除く）の発言意欲評価・評価結果の可視化保存・活性シグナルの記録・意図キューの失効」を独立した評価ステップへ切り出す
  - この評価ステップを停止ゲート通過後の毎ターンに実行し、指名・直接質問・論点ずれのターンでもスキップしないようにする
  - 活性シグナルは1ターンにつき必ず1回だけ記録する
  - 意図キューは論点ずれをまたいでも失効上限内は破棄せず保持する
  - キュー追加（非選択かつ高意欲者）はこのステップに含めず、話者決定後に行う分離を保つ
  - 観測可能な完了条件: 指名・直接質問・論点ずれのターンでも可視化保存が実行され、可視化の穴が無くなる
  - _Requirements: 4.1, 5.1, 5.4, 5.5_

- [x] 3. 介入(A/B)と話者決定の優先順位整理（BC1・BC2）
- [x] 3.1 出尽くし介入(B)を独立処理に抽出しクールダウン依存を外す
  - 巨大メソッドから出尽くし介入の判定・介入発言保存・指名解決を独立した処理へ切り出す（論点ずれ介入とは別処理として保つ）
  - 発火条件を「高意欲者が残っていない」のみとし、クールダウンを参照しない（バグ修正）
  - 高意欲の有無は新設の高意欲述語で判定する
  - 観測可能な完了条件: クールダウン未経過でも高意欲者がいなければ出尽くし介入が発火するテストが通る
  - _Requirements: 3.1, 3.4, 3.6_
- [x] 3.2 次話者決定の純関数をキューとスコアの2段に縮退する
  - 招き入れ（出尽くし介入の指名）分岐を純関数から除去し、キュー選択ゲートを高意欲述語で表現する
  - 残る分岐を「キュー→スコア」の2段に整理し、欠番のない採番にする
  - 直前話者の連続発言回避と不正IDフォールバックの現行規則を維持する
  - 観測可能な完了条件: 招き入れ引数を持たない純関数がキュー/スコアの2段で次話者を返し、単体テストがグリーン
  - _Requirements: 2.2, 2.3, 2.4_
- [x] 3.3 論点ずれ介入(A)を指名なし時のみ評価する整理にする
  - 論点ずれ介入を毎ターン先行評価する現行を廃し、保留中の指名・直接質問が無いときにのみ評価するよう整理する
  - クールダウンは論点ずれ介入の発火条件としてのみ用いる
  - 保留中の指名・直接質問を介入で上書き・破棄しない
  - 観測可能な完了条件: 保留指名があるターンで論点ずれ・出尽くし介入が評価されず指名が消化されるテストが通る
  - _Requirements: 3.2, 3.3, 3.5_
- [x] 3.4 ターンループを優先順位合成に再構成し状態更新を一元化する
  - 1ターンを「停止ゲート → 全員評価 → 話者決定 → 発言パラメータ取得 → 発言生成・保存 → 状態更新 → 章終了判定」の単一の流れに整える
  - 話者決定を「指名・直接質問 ＞ 論点ずれ介入 ＞ 出尽くし介入 ＞ キュー ＞ スコア」の優先順位として合成する
  - 連続直接質問カウントを単一規則（直接質問消化で加算、その他決定とファシリテーター発言保存で 0、復元時 0 開始）で更新し、複数分岐に散らさない
  - キュー追加と沈黙・発言数・直前話者の更新を話者決定後の状態更新に集約する
  - 観測可能な完了条件: 優先順位どおりに話者が決まり、指名破棄が起きないことを結合テストで確認できる
  - _Requirements: 1.1, 2.1, 5.2, 5.3, 5.4_
- [x] 3.5 発言パラメータ取得を評価結果中心に整え章末リプライを共通化する
  - 選ばれた話者の発言パラメータを当ターンの全員評価結果から取得する経路を主とし、評価対象外（直前話者の指名など）のときのみ単独評価のフォールバックにする
  - 役割が分かる名前へ改名する（発言パラメータ決定であることを示す）
  - 章末の未応答リプライ生成をターンループ本体と同じ評価・発言生成の処理単位で行い、別実装の重複を解消する
  - 観測可能な完了条件: 評価二経路が解消し、未応答リプライが本体と同じ流れで生成される
  - _Requirements: 4.2, 4.3, 4.4_

- [x] 4. ドキュメント整合とメソッドの責務・命名整理
- [x] 4.1 docstring・コメントを実装と一致させ正準フローへ対応づける
  - 並列/逐次の取り違えなど docstring の記述を実装の挙動と一致させる
  - コメント中の分岐採番を実装に一致させ欠番・実在しない分岐参照を除去する
  - クールダウン判定を論点ずれ介入専用と明確化（命名・コメント）する
  - 主要メソッドのコメントから設計の正準フロー（System Flows）の対応箇所を辿れるようにする
  - 観測可能な完了条件: 主要メソッドの記述が実装と一致し、正準フローの各ステップへ辿れる
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 3.2, 7.1, 7.2, 7.3_
- [x] 4.2 メソッドの責務分界と命名を最終整理する
  - 各メソッドが単一の明確な責務を持つよう分界を確認し、複数責務が残るものを分割する
  - 過度な分割（1箇所しか呼ばない極小メソッドの乱立・見通しを損なう細分化）を避ける
  - 各メソッド名を役割に対応したシンプルな名前に統一し、処理と一致しない名前を残さない
  - 公開メソッド（章立て生成・章タスク実行）の呼び出し契約を変更しない
  - 観測可能な完了条件: メソッド構成が正準フローの各ステップと対応し、公開契約が不変のまま全体ビルドが通る
  - _Requirements: 1.1, 9.1, 9.2, 9.3, 9.4, 9.5_

- [x] 5. 検証: テスト更新と回帰確認
- [x] 5.1 (P) フロー純関数の単体テストを更新する
  - 次話者決定（キュー/スコアの2段・直前話者回避・不正IDフォールバック）の期待値を新仕様へ更新する
  - 高意欲述語（境界での真偽・B ゲート/キュー選択/活性シグナルの共有）のテストを追加する
  - 制御定数の単一参照（失効ターン数の二重定義解消）の回帰を確認する
  - 観測可能な完了条件: フロー純関数の単体テストがグリーン
  - _Requirements: 2.2, 2.3, 2.4, 6.1, 6.3, 8.4_
  - _Boundary: flow pure functions_
  - _Depends: 1.1, 1.2, 3.2_
- [x] 5.2 オーケストレーターのテストを確定変更に合わせ更新し回帰を守る
  - 確定変更に対応するケースの期待値を更新する（出尽くし介入のクールダウン非依存、指名/直接質問の優先と非破棄、毎ターン全員評価による可視化保存・評価呼び出し回数）
  - 上記以外の話者決定・章遷移・終了判定は回帰ガードとしてグリーンを維持する
  - 論点ずれをまたいだ意図キューの保持を確認する
  - 観測可能な完了条件: 確定変更3点を検証するテストが通り、それ以外のオーケストレーターテストが回帰なくグリーン
  - _Requirements: 3.1, 3.4, 3.5, 4.1, 5.1, 5.4, 5.5, 8.1, 8.4, 8.5_
  - _Boundary: DebateOrchestratorService tests_
  - _Depends: 3.1, 3.3, 3.4, 3.5_
- [x] 5.3 停止・冪等・状態復元の決定性を回帰確認する
  - 停止ゲートによる中断（停止中は新規発言を生成・保存しない）が維持されることを確認する
  - 章の冪等性（処理済み章スキップ）と章ターン上限・全体ターン上限による打ち切りが維持されることを確認する
  - 保存済みターンと永続化キューから同一入力に対し同一状態を復元する性質を確認する
  - 観測可能な完了条件: 停止・冪等・状態復元の回帰テストがグリーン
  - _Requirements: 5.6, 8.2, 8.3_
  - _Depends: 3.4_
