# Implementation Plan

## 1. フェーズ状態モデルの型と導出（Foundation）

- [x] 1.1 進行状態の型とフェーズ定義を整備する
  - トピックの進行状況を「現在のフェーズ」と「そのフェーズの状態（`not_started`/`running`/`generated`）」の2軸で表す型を定義する
  - 表示用の論理状態（4状態 `not_started`/`running`/`generated`/`approved` ＋ フェーズ5のみ `stopped`）を定義する
  - フェーズごとの操作設定（生成/承認/再生成のラベル、承認の有無、停止可否、再開可否）を宣言する設定テーブルを用意する
  - トピックの旧 `status` 単一enumを廃し、session 専用のステータス型に分離する（フロント/Functions 双方の型）
  - 完了条件: 既存コードが新しい型を参照できる状態になり、型チェックが通る
  - _Requirements: 1.1, 1.2, 6.1, 7.1, 7.5_

- [x] 1.2 状態導出・旧データ互換・一覧ラベルの純粋関数を実装する
  - 「現在のフェーズとその状態」＋対象フェーズから表示状態を導出する（現在より前=承認済み、後=未生成、フェーズ5は session 終端から `stopped`/`generated` を再調整、クライアント権威フェーズの中断 `running` は `not_started` に再調整）
  - 旧 `status` を持つ既存トピックから新2軸を導出する互換関数を実装する
  - ダッシュボード一覧バッジ用のラベル/スタイルキーを2軸から導出する関数を実装する
  - 完了条件: 各分岐（approved/not_started/running/generated/stopped/中断再調整）を網羅する単体テストが緑になる
  - _Requirements: 1.2, 1.3, 7.2, 7.3, 7.6_

## 2. Functions のフェーズ状態確定（Backend）

- [x] 2.1 (P) トピックのフェーズ状態を更新する Functions 基盤を整える
  - トピックの2軸（フェーズ・状態）を更新する共通ヘルパーを追加する
  - Functions 側のステータス型を session 専用に整理する
  - 完了条件: 任意のフェーズ・状態でトピックドキュメントの新フィールドが更新できる
  - _Requirements: 7.4_
  - _Depends: 1.1_
  - _Boundary: Functions phase書込_

- [x] 2.2 討論の開始・章立て生成・完了のフェーズ状態書き込みを移行する
  - 討論開始時にトピックを「フェーズ5・実行中」に更新する
  - 討論完了時にトピックを「フェーズ5・生成完了」に確定する
  - 章立て生成 Functions からトピック状態の書き込みを撤去し、セッション作成のみ残す（章立てはクライアント権威）
  - 完了条件: 討論の開始→完了でトピックの状態が実行中→生成完了に永続遷移する
  - _Requirements: 2.4, 7.4_
  - _Boundary: Functions phase書込_

- [x] 2.3 討論の章単位再開（restart）専用処理を実装する
  - 停止時に進行中だった章の途中ターンを破棄し、その派生変化（信念バージョン・エンゲージメント）を巻き戻す
  - クリーン化した当該章を頭から再実行するようタスクを投入し、トピックを「フェーズ5・実行中」に戻す
  - 完了条件: 停止後に再開すると、途中ターンが重複せず現在章の頭から討論が続行する
  - _Requirements: 7.6_
  - _Boundary: Functions phase書込_

## 3. トピック・ストアのフェーズ状態書き込み（Core）

- [x] 3.1 (P) トピック操作のフェーズ状態遷移と下流削除を統一する
  - 生成・承認の各操作で2軸（フェーズ・状態）を明示的に更新する（生成開始で実行中、成功で生成完了、承認で次フェーズの未生成へ前進）
  - 再生成を「対象フェーズ以降の生成済みデータを実際に削除してから対象フェーズを生成完了に戻す」統一規則にする（ステータスのみ戻して生成済みデータが残る状態を作らない）
  - 下流削除のタイミングを全フェーズで「生成成功を前提に削除」に揃え、進行中討論があれば削除前に停止する
  - 完了条件: 中間フェーズの再生成で以降の生成済みデータが消え、対象フェーズが生成完了・以降が未生成として扱われる
  - _Requirements: 2.4, 3.2, 4.2, 4.3, 4.4, 4.5, 4.6, 7.4_
  - _Boundary: topic store_

- [x] 3.2 (P) ペルソナ生成・取材の集約状態を新モデルに移行する
  - ペルソナの承認・再生成を新2軸の書き込みに更新する
  - 取材は per-persona の進捗を永続化せず、全件完了をフロントで検知した時点で「フェーズ3・生成完了」を1回だけ書く
  - 完了条件: 全ペルソナの取材完了後にフェーズ3が生成完了状態になり、リロード後も取材記録の有無から完了が再構築できる
  - _Requirements: 2.4, 3.2, 7.4_
  - _Boundary: personas store_
  - _Depends: 1.1_

- [x] 3.3 (P) 新規トピック作成時に初期フェーズ状態を設定する
  - トピック作成時に「フェーズ1・未生成」を明示初期化する（互換導出に頼らせない）
  - 完了条件: 新規作成したトピックが新2軸フィールドを持って作られる
  - _Requirements: 7.4_
  - _Boundary: topics store_
  - _Depends: 1.1_

## 4. 共通操作コントローラ（Core）

- [x] 4.1 フェーズ共通の状態導出と生成・承認操作を提供するコントローラを実装する
  - 対象フェーズの論理状態を2軸（とフェーズ5の session 終端）から導出して公開する
  - 生成操作（成功で生成完了、失敗で永続状態を変えず一時エラーを設定）と承認操作（成功で次フェーズへ画面遷移、失敗で遷移せず一時エラー）を提供する
  - 一時エラーは永続化せず、リロードでクリアされる扱いにする
  - 完了条件: 生成成功/失敗・承認成功/失敗のそれぞれで状態とエラーが規定どおり変化する単体テストが緑になる
  - _Requirements: 1.4, 1.5, 2.1, 2.2, 2.3, 3.1, 3.2, 3.3, 3.4_
  - _Depends: 1.2, 3.1, 3.2_

- [x] 4.2 再生成とフェーズ5固有操作（停止・再開）をコントローラに追加する
  - 再生成操作（下流削除を伴う）と、設定で許可されたフェーズのみ提供する停止・再開操作を実装する
  - 設定に操作が無いフェーズでは対応操作を提供しない（呼び出し不能）
  - 実行中は停止以外の操作を受け付けないガードを設ける
  - 完了条件: フェーズ5で停止→停止状態→再開/再生成が選べ、フェーズ1〜4では停止・再開が提供されないことをテストで確認できる
  - _Requirements: 4.1, 4.2, 4.5, 4.6, 5.1, 5.2, 7.6_
  - _Depends: 4.1, 2.3_

## 5. 共通UIパネル（Core）

- [x] 5.1 状態とフェーズ設定だけでUIを描画する共有パネルを実装する
  - 論理状態×フェーズ設定に基づく状態×ボタンマトリクス（未生成=生成のみ／実行中=インジケータと停止のみ／停止=再開と最初からやり直し／生成完了=承認と再生成／承認済み=再生成のみ／エラー=停止表示）を描画する
  - 進行中インジケータとエラー表示を全フェーズ統一スタイルにし、進捗併記用の差し込みを設ける
  - 再生成・最初からやり直しは確認ダイアログ確定後に実行、再開は確認なしで実行する
  - フェーズ固有のボタン分岐を持たず、設定（承認の有無・停止可否・再開可否）だけで出し分ける
  - 完了条件: 各論理状態でマトリクスどおりのボタン構成と統一表示が出る
  - _Requirements: 1.5, 2.5, 3.1, 5.1, 5.2, 5.3, 6.1, 6.2, 6.3, 6.4_
  - _Depends: 1.1, 4.1, 4.2_

## 6. 各フェーズ画面の統合（Integration）

- [x] 6.1 (P) ステークホルダー・ペルソナ・章立て画面を共有パネルに移行する
  - 各画面の個別状態判定・アクションバー・エラー表示・確認ダイアログを撤去し、共有パネルとコントローラに委譲する
  - 一覧などフェーズ固有のコンテンツのみ差し込みで残す
  - 完了条件: 3画面が統一UIで生成→承認→次フェーズ／再生成を実行できる
  - _Requirements: 6.1, 6.2, 6.4_
  - _Depends: 5.1_
  - _Boundary: Phase1/2/4 components_

- [x] 6.2 (P) 取材画面を共有パネルに移行する
  - 共有パネルへ委譲しつつ、per-persona の進捗・個別エラー・リトライは取材画面のコンテンツ内に閉じる
  - 全件完了で生成完了となり承認できる
  - 完了条件: 並列取材の進捗表示・リトライが従来どおり動き、全完了後に統一UIで承認できる
  - _Requirements: 6.4, 5.1, 5.2_
  - _Depends: 5.1, 3.2_
  - _Boundary: Phase3 component_

- [x] 6.3 (P) 討論画面を共有パネルに移行する
  - 共有パネルへ委譲し、討論ターン・章一覧表示はコンテンツ内に残す
  - 開始・停止・再開・最初からやり直しが状態に応じて表示される
  - 完了条件: 開始→停止→再開（章頭から）→完了、および停止→最初からやり直しが統一UIで操作できる
  - _Requirements: 5.1, 5.2, 5.3, 6.4_
  - _Depends: 5.1, 4.2_
  - _Boundary: Phase5 component_

## 7. ルーティングと一覧の統合（Integration）

- [x] 7.1 フェーズ判定とリダイレクトを新モデルに移行する
  - レイアウト・リダイレクトのフェーズ判定を旧 `status` 変換から新2軸（互換導出経由）に置換する
  - 互換導出に必要なストアの読み込み完了までリダイレクト判定を保留し、閲覧中ページからの誤遷移を防ぐ

  - _Requirements: 1.6_
  - _Depends: 1.2_

- [x] 7.2 (P) ダッシュボード一覧のステータス表示を新モデルに移行する
  - 一覧のステータスバッジを旧enumマップから2軸由来のラベル/スタイルへ置換する
  - 完了条件: 一覧で各トピックの現在フェーズと状態がバッジ表示される
  - _Requirements: 6.1, 7.1_
  - _Depends: 1.2_
  - _Boundary: TopicListPage_
