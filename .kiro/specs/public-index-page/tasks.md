# Implementation Plan

## 1. 基盤: 公開 SSR 用の Firestore 初期化を分離

- [x] 1.1 firebase 設定リテラルを副作用のない共有モジュールへ切り出す
  - `firebaseConfig` を、SDK 初期化の副作用を持たない独立モジュールへ切り出す
  - 既存の firebase 初期化がその共有 config を参照するよう変更する（Auth/Functions 込みの既存の役割は変えない）
  - 観測可能な完了: 既存の admin・一般経路が従来どおり動作し、型チェックが通る
  - _Requirements: 2.1_

- [x] 1.2 公開用に Firestore 専用初期化を新設する
  - 共有 config を用いて Firestore ハンドルのみを公開する（`getApps` ガードで単一 app を共有）
  - Auth・Functions は import も初期化もしない
  - 観測可能な完了: 公開ハンドル経由で Firestore を読み取れ、モジュール読み込み時に Auth 初期化が走らない
  - _Requirements: 2.1_
  - _Depends: 1.1_

## 2. コア: 公開読み取りモデルと取得

- [x] 2.1 公開トピックの最小読み取りモデルを定義する
  - id・title・publishedAt のみを持つ読み取り専用の公開型を定義する
  - `published`・`personaCount` などの Admin 由来フィールドは持たない
  - 観測可能な完了: 公開型が定義され、公開経路がこの型のみを参照できる（Admin 型・管理ストアに非依存）
  - _Requirements: 1.3_

- [x] 2.2 公開済みトピックの取得と射影を実装する
  - `published` が true のトピックのみを取得する（未認証でルール適合となる限定クエリ）
  - 永続日時をアプリ層の日時へ変換し、公開日時の新しい順に並べて返す
  - Admin 型・管理ストア・Auth 込み初期化を参照せず、Firestore 専用ハンドルのみ使用する
  - 観測可能な完了: 公開済みのみが公開日時降順で得られ、非公開・`published` 未設定は含まれない
  - _Requirements: 1.1, 1.2, 1.5, 2.2_
  - _Boundary: fetchPublishedTopics_
  - _Depends: 1.2, 2.1_

## 3. コア: SSR ロードと実行検証（UI 前ゲート）

- [x] 3.1 公開インデックスの SSR ロードを実装する
  - ページ表示時に公開一覧を取得してページへ受け渡す（未認証で実行できる）
  - 取得失敗を捕捉し、全体エラーページにせず失敗状態として受け渡す
  - 観測可能な完了: ページロードが公開一覧、または失敗状態を返す
  - _Requirements: 2.1, 3.3_
  - _Depends: 2.2_

- [x] 3.2 SSR 実行可否を検証する（UI 実装前ゲート）
  - サーバ生成 HTML に公開一覧が含まれること（firebase の SSR 実行が成立すること）を確認する
  - 未認証で公開済みのみが返ることを確認する
  - 観測可能な完了: SSR 出力に一覧が含まれることを確認でき、これが通ってから UI 実装に進む（不成立なら設計見直し）
  - _Requirements: 2.1, 2.2_
  - _Depends: 3.1_

## 4. コア: 公開インデックス UI

- [x] 4.1 公開一覧項目コンポーネントを実装する
  - タイトルと公開日を表示し、記事ページ（`/articles/[topicId]`）への遷移リンクを持たせる
  - prop は公開読み取りモデルのみとする（Admin 型・管理ストアに非依存）
  - 観測可能な完了: 1件分の項目がタイトル・公開日・正しいリンク先で表示される
  - _Requirements: 1.3, 1.4, 5.1_
  - _Boundary: PublishedTopicItem_
  - _Depends: 2.1_

- [x] 4.2 公開トップページを公開データ駆動に刷新する
  - ロード結果から一覧を項目コンポーネントで描画し、管理ストア・旧一覧項目への依存を除去する
  - 0件表示・取得失敗表示・読み込み中表示（SSR 初回はデータ込み、クライアント遷移時はナビ状態）を用意する
  - サービス名のみの最小ヘッダーとし、サービス説明文と管理（admin）導線は置かない
  - メタ情報（タイトル・説明・OGP）を付与し、モバイル/デスクトップ両対応のレイアウトにする
  - 観測可能な完了: 未認証で公開一覧が表示され、0件・取得失敗・レスポンシブが機能し、説明文・admin 導線が無い
  - _Requirements: 1.3, 1.4, 2.3, 3.1, 3.2, 3.3, 4.1, 4.2, 5.1_
  - _Depends: 3.1, 4.1_

## 5. 統合: 旧一覧項目の撤去

- [x] 5.1 管理型依存の旧一覧項目とそのテストを撤去する
  - 公開トップが新しい項目コンポーネントへ置換済みであることを確認し、旧 `TopicListItem` とその spec を削除する
  - 観測可能な完了: 旧 `TopicListItem` への参照が残らず、型チェックと既存テストが通る
  - _Requirements: 1.3_
  - _Depends: 4.2_

## 6. 検証

- [x] 6.1 (P) 取得ロジックのユニットテスト
  - 限定クエリ（`published` true）・公開日時降順・最小射影（`published`/`personaCount` を含まない）・日時変換を検証する（Firestore をモック）
  - 観測可能な完了: 上記ケースが通る
  - _Requirements: 1.1, 1.2, 1.5, 2.2_
  - _Boundary: fetchPublishedTopics_
  - _Depends: 2.2_

- [x] 6.2 (P) 一覧項目コンポーネントの spec
  - タイトル・公開日の表示と、リンク先が `/articles/[topicId]` になることを検証する
  - 観測可能な完了: 表示とリンク先のケースが通る
  - _Requirements: 1.3, 1.4_
  - _Boundary: PublishedTopicItem_
  - _Depends: 4.1_

- [x] 6.3 (P) 未認証取得の統合確認
  - エミュレータの rules 下で、未認証が公開済みのみを取得し、非公開・`published` 未設定が出ないことを確認する
  - 観測可能な完了: 公開済みのみ表示され、非公開が遮断される
  - _Requirements: 1.5, 2.1, 2.2_
  - _Depends: 3.1_
  - 検証方法: エミュ非依存（[[project-no-emulator]]）のため、3.2 ゲートで本番デプロイ済み rules に対し実証。未認証 `where(published==true)` は公開済みのみ返し（every published===true）、非フィルタ `topics` クエリは permission-denied で遮断されることを確認済み。
