# Implementation Plan

- [x] 1. 論点状態の型拡張と永続化（Foundation）
  - `DiscussionPointState` に「発言済みペルソナ」「関連参加者」の2集合（任意配列）を追加する
  - `saveDiscussionPointStatuses` の書き出しに両集合を含め、ランタイム型＝Firestore永続型を保つ（永続されないランタイム専用フィールドを作らない）
  - resume 復元・読み出しで両集合が欠損する既存データを空集合として扱い、エラーを起こさない
  - 観測可能な完了条件: 章ドキュメントの `discussionPointStatuses` に2集合が保存・復元され、欠損データでも例外なく動作する
  - _Requirements: 1.1, 1.6, 1.7_

- [x] 2. 論点カバレッジの状態操作（Core）
- [x] 2.1 論点投入時の関連参加者記録と発言済み初期化
  - 論点を introduced 化する単一経路で、関連参加者を当該論点に記録し、発言済みペルソナ集合を空で開始する
  - 記録する関連参加者は参加者リストの有効IDへフィルタする
  - 観測可能な完了条件: 新たに introduced された論点が、与えられた関連参加者集合と空の発言済み集合を持つ
  - _Requirements: 1.3, 1.4_
  - _Boundary: discussion-points_
  - _Depends: 1_
- [x] 2.2 発言者記録と未発言の関連参加者の導出
  - 現アクティブ論点の発言済みペルソナ集合へ話者を冪等に追加する（重複させない）
  - 「関連参加者 − 発言済み」から未発言の関連参加者を導出する純関数を用意し、アクティブ論点不在・関連参加者空のときは空を返す
  - 観測可能な完了条件: 同一話者を複数回記録しても集合が重複せず、未発言の関連参加者が正しく算出される
  - _Requirements: 1.2, 1.3, 1.5, 5.3_
  - _Boundary: discussion-points_
  - _Depends: 1_

- [x] 3. (P) ファシリテーターの関連判定・二軸判定・引き込み・チェーン解釈（Core）
- [x] 3.1 論点投入時に関連参加者を返す契約拡張
  - オープニングおよび介入による論点投入のファシリテーター返却に、その論点で立場を聞くべき関連参加者を含める（全参加者を一律に含めない）
  - 介入評価時に、立場を加えうる未登録の参加者を関連集合へ追加のみ可能とし、削除はしない
  - 観測可能な完了条件: 論点投入の返却に関連参加者が含まれ、全員一律ではない部分集合になりうる
  - _Requirements: 1.2, 5.1, 5.2_
  - _Boundary: facilitator-agent_
  - _Depends: 1_
- [x] 3.2 出尽くし判定の二軸化と未発言者の引き込みプロンプト
  - 出尽くし評価を「直近応酬の新規性」と「立場カバレッジ」の独立2軸で行い、新規性のなさのみを根拠に前進させない
  - 未発言の関連参加者が残るときは、同論点を維持してその中の1人を名前で指名し立場を問う介入文面を生成する（新論点を投入しない）
  - 観測可能な完了条件: 未発言の関連参加者がいる文脈では、論点投入ではなく同論点の引き込み文面が生成される
  - _Requirements: 2.1, 2.4, 3.1, 3.2, 3.3_
  - _Boundary: facilitator-agent_
  - _Depends: 1_
- [x] 3.3 連続指名チェーン長シグナルの解釈是正
  - チェーン長を「まず未発言者を同論点へ引き込むことを検討すべきシグナル」として扱い、出尽くしの即断材料にしない
  - 未発言の関連参加者が残る間は引き込みを優先し、全員表明済みのときに限り出尽くし＝前進を許す文面方針にする
  - 観測可能な完了条件: チェーンが長くても未発言者が残る限り引き込み方向の判断になる
  - _Requirements: 4.1, 4.2, 4.3_
  - _Boundary: facilitator-agent_
  - _Depends: 1_

- [x] 4. 介入評価のカバレッジ・ゲート（Integration）
- [x] 4.1 候補 withhold と index-drop による前進阻止
  - 介入評価前に現アクティブ論点の未発言の関連参加者を算出する
  - 未発言の関連参加者が残る間は未提示論点候補を渡さず（誘導）、かつ論点投入の index をコードで無効化して前進を確実に阻止する（強制）
  - アクティブ論点が存在しない場合はゲートを適用せず、エラーなく評価を完了する
  - 観測可能な完了条件: 未発言の関連参加者が残る状態では、ファシリテーターが論点投入を返しても次論点が introduced 化されない
  - _Requirements: 1.8, 2.2, 2.3, 2.5_
  - _Boundary: intervention_
  - _Depends: 2.2, 3.2_
- [x] 4.2 未発言者・チェーン長の注入と引き込み先の検証
  - 立場カバレッジ（発言済み／未発言の関連参加者）と連続指名チェーン長を介入評価へ渡す
  - 未発言の関連参加者が残る状況で採用する同論点介入は、指名先が未発言の関連参加者に属することを検証し、属さなければ採用しない
  - 観測可能な完了条件: 引き込み介入の指名先が必ず未発言の関連参加者になり、非該当時は介入せず通常フローへ戻る
  - _Requirements: 1.5, 3.4, 4.1_
  - _Boundary: intervention_
  - _Depends: 2.2, 3.1_

- [x] 5. (P) 発言者記録と論点投入の配線（Integration）
- [x] 5.1 通常ターンの発言者記録と永続化
  - ターンがコミットされた後に、現アクティブ論点へ話者を記録し、永続型からそのまま書く既存手段で永続化する（Partial転送形を介さない）
  - 観測可能な完了条件: ペルソナ発言ごとに当該話者が現アクティブ論点の発言済み集合へ反映され、永続化・resume 後も保持される
  - _Requirements: 1.2, 1.4, 5.3_
  - _Boundary: step_
  - _Depends: 2.2_
- [x] 5.2 論点投入時の関連参加者記録の配線
  - オープニング・章導入・介入による論点投入で、ファシリテーター返却の関連参加者を introduced 化と同時に記録する（`markIntroduced` の既存挙動は維持）
  - 観測可能な完了条件: 各論点投入で関連参加者が論点状態に記録・永続化される
  - _Requirements: 1.2, 1.3, 6.4_
  - _Boundary: step_
  - _Depends: 2.1, 3.1_

- [x] 6. テストと回帰確認（Validation）
- [x] 6.1 カバレッジ状態操作のユニットテスト
  - 発言者記録の冪等性、未発言者導出、関連参加者記録と発言済み初期化、2集合の永続化と欠損後方互換を検証する
  - 観測可能な完了条件: 上記純関数・永続化のユニットテストが緑になる
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.7, 5.3_
  - _Depends: 2.1, 2.2, 5.1_
- [x] 6.2 ゲートと順序保証の結合テスト
  - 未発言の関連参加者が残る状態で次論点が introduced 化されないこと、全員表明済みで前進が起こりうること、引き込み介入がファシリテーターターンのみ保存し応答は次ターンになること、resume で発言済み集合が二重化しないことを検証する
  - 観測可能な完了条件: ゲート・引き込み・順序保証・resume の結合テストが緑になる
  - _Requirements: 2.2, 2.3, 3.5, 6.5_
  - _Depends: 4.1, 4.2, 5.1, 5.2_
- [x] 6.3 既存挙動の回帰確認
  - 介入クールダウン値、アクティブ論点追跡（最新 introduced）、アクティブ論点不在時の title フォールバック（ゲート不適用）、章強制終了上限による終了保証が不変であることを確認する
  - 観測可能な完了条件: 既存の討論結合テスト（parity / idempotency 等）が緑のまま維持される
  - _Requirements: 5.4, 6.1, 6.2, 6.3_
  - _Depends: 4.1, 4.2, 5.1, 5.2_
