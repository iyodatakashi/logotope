# Implementation Plan

## 1. 依存の取り込みと実行環境の整備

- [x] 1.1 モジュールをローカル参照で取り込み、peer 依存を満たす版へ引き上げる
  - `@14ch/svelte-firebase-auth` を pnpm のローカル参照で依存に加える（実装中の往復のための手段であり、到達点ではない）
  - `@sveltejs/kit` を 2.63 以上、`firebase` を 12.18 以上、`@14ch/svelte-ui` を 0.0.61 以上へ引き上げる
  - `pnpm-workspace.yaml` の公開直後の版を除外する一覧に、引き上げた版を追加する
  - 型検査と既存のテストが引き上げの前と同じ結果で通る
  - _Requirements: 1.6, 1.7_

- [x] 1.2 事前バンドルの設定を加え、既存の描画が壊れていないことを確かめる
  - モジュールと標準 UI ライブラリを事前バンドルの対象から外し、`svelte` の実体を1つに揃える
  - 対象から外したことで変換されなくなる CJS の依存を、pnpm の非フラットな配置でも解決できる記法で戻す
  - 開発サーバーと本番ビルドの両方で、既存の管理画面と公開ページが従来どおり描画される
  - _Requirements: 1.8_

- [x] 1.3 確認・再設定の完了後の戻り先に使うオリジンを、環境変数として供給する
  - 開発と本番のそれぞれにアプリのオリジンを与える。本番はビルド時に解決される形にする
  - 戻り先そのものは設定側で管理画面のサインインの経路を足して組み立てる（オリジンだけを変数に持たせる）
  - 開発・本番の両方のビルドで変数が解決され、未定義のまま埋め込まれない
  - _Requirements: 2.5_

- [x] 1.4 Firebase 側の設定を、画面の設定と揃える
  - 自由登録の API を塞ぐ。画面の入口を閉じるだけでは登録そのものを止められない
  - 戻り先のオリジンを承認済みドメインに加える。加えていないと再設定メールの送信が失敗する
  - 管理者アカウントの作成をコンソールでの操作として運用に位置づける
  - 塞いだ状態では登録の試行がモジュールの `registration-disabled` として扱われる（logotope は登録の経路を持たないため画面からは到達しない）
  - 再設定メールの送信が承認済みドメインの不備で失敗しないことを、後続の疎通確認で確かめられる状態になる
  - _Requirements: 2.6, 7.2, 7.3, 7.4_

## 2. 認証の設定と受け渡し

- [x] 2.1 (P) モジュールへ渡す設定の確定値を1か所に定義する
  - 自由登録とメールアドレスの確認を、いずれも求めない確定値として持つ。実行時に切り替える余地を作らない
  - 認証の4経路と、認証を終えた管理者の既定の行き先を、URL に現れるとおりの経路として与える
  - 既定の行き先は実在するトピック一覧にする（管理画面の根には画面が無い）
  - 登録の経路は実在させず、サインインの経路と同じ値を重ねる。実在させると未サインインの訪問者に登録フォームが出る
  - 確認待ちの経路は実在させる。到達しないのは設定の帰結にすぎず、設定を反転すれば到達する
  - 経路の全項目が管理画面の配下を指し、到達の制御の適用範囲から外れる値を含まない
  - _Requirements: 2.4, 3.1, 3.2, 3.4, 3.5, 7.1, 8.1_
  - _Boundary: AdminAuthConfig_

- [x] 2.2 (P) 認証ストアを管理画面の配下へ配る受け渡し層を作る
  - 登録と取得の2つだけを公開し、共有の仕組みのキーをこの層の外に出さない
  - 状態も操作も持たない。認証の判断（段階の解釈・遷移・失敗の扱い）を一切含めない
  - 登録されていない階層から取得したときは例外を投げ、呼び出し側に分岐を作らせない
  - 管理画面の配下のどのコンポーネントからも、同一のインスタンスが取得できる
  - _Requirements: 2.1_
  - _Boundary: AdminAuthAccessor_

## 3. 到達の制御と画面の差し替え

- [x] 3.1 管理画面の階層で認証ストアを生成し、到達の制御で子を包む
  - 既存の初期化が持つ認証インスタンスと確定値から、認証ストアを1つ生成して受け渡し層に登録する
  - 購読の開始と後始末を対にする。開始しないと判定が完了しないままになる
  - 到達の制御で子を包み、判定が済むまでの表示を渡す。遷移と描画の抑止を自前で組み立てない
  - 段階を見た条件式（判定の完了・利用者の有無）をこの階層に一切書かない
  - 管理画面の配下をクライアントサイドで動かす既存の設定を維持する
  - 公開ページはこの階層を通らず、到達の制御の対象にならない
  - 未サインインで管理画面の経路を開くとサインインへ振り替わり、判定の完了前は管理画面の内容が描画されない
  - _Requirements: 1.1, 2.2, 2.3, 2.7, 4.1, 4.2, 4.3, 4.4, 4.7, 4.8_

- [x] 3.2 管理データの購読の寿命を、到達の制御の内側へ移す
  - 到達を許された間だけ存在する薄い包みを、到達の制御の内側に置く
  - トピック一覧の購読の開始と停止を、その包みの寿命に一致させる。条件式を持たせない
  - 認証の状態を一切参照しない（段階・サインインの有無・受け渡し層のいずれにも触れない）
  - サインアウトすると包みごと破棄され、購読が停止する
  - _Requirements: 4.7, 6.4_
  - _Depends: 3.1_

- [x] 3.3 (P) サインインの画面をモジュールのものへ差し替える
  - 自前のログインフォームのマークアップを撤去し、モジュールのサインイン画面を差し込む
  - 経路のファイルは画面コンポーネントを1つ差し込むだけの最小のラッパーにし、実体を feature 側に置く
  - logotope の名乗りを画面の上部へ差し込む。文言の差し替えは logotope 固有の呼称に限る
  - 完了や遷移のコールバックを渡さない。画面どうしの行き来はモジュールが行う
  - 失敗を例外として扱う処理を書かない。案内は画面が戻り値から引く
  - サインインに成功すると、到達の制御によって元の経路または既定の行き先へ進む
  - _Requirements: 3.3, 3.6, 3.7, 3.8, 3.9, 9.6_
  - _Boundary: AdminSignInPage_
  - _Depends: 2.1, 2.2_

- [x] 3.4 (P) パスワード再設定の画面を置く
  - 設定した再設定の経路に、モジュールの再設定画面を最小のラッパー越しに置く
  - サインインの画面から再設定へ到達でき、再設定からサインインへ戻れる（導線はモジュールが持つ）
  - 要求が受け付けられたとき、そのメールアドレスが登録済みかどうかを区別して示さない
  - _Requirements: 3.3, 9.1, 9.2_
  - _Boundary: AdminPasswordResetPage_
  - _Depends: 2.1, 2.2_

- [x] 3.5 (P) パスワード変更の画面と、そこへの導線を置く
  - 認証の経路に含まれない場所に画面を置く。含めるとサインイン済みの管理者が追い出される
  - 管理画面の共通の枠から到達できる導線を与える
  - 独立した経路に置く（画面が完了時に自ら遷移するため、ダイアログの中では噛み合わない）
  - 現在のパスワードによる再認証に失敗したときは変更が行われず、案内が表示される
  - サインイン済みの管理者がパスワードを変更でき、完了後に既定の行き先へ戻る
  - _Requirements: 3.3, 9.3, 9.4, 9.5_
  - _Boundary: AdminAccountPage_
  - _Depends: 2.1, 2.2_

- [x] 3.6 (P) 確認待ちの画面を置く
  - 設定した確認待ちの経路に、モジュールの確認待ち画面を最小のラッパー越しに置く
  - 確認を求めない設定のため、この画面には到達しない。設定を反転したときに何も足さずに済む状態にする
  - 確認を求めない設定のもとで、確認待ちへの振り替えが起きない
  - _Requirements: 3.3, 8.2_
  - _Boundary: AdminVerifyEmailPage_
  - _Depends: 2.1, 2.2_

- [x] 3.7 (P) 共通の枠のサインアウトを、モジュールの操作へ差し替える
  - 認証ストアの参照を受け渡し層からの取得に変え、サインアウトでモジュールの操作を呼ぶ
  - サインアウトの後に遷移を書かない。段階の変化に応じて到達の制御が振り替える
  - 子の出し分け（サインイン済みかどうかで中身を描くかを決める処理）を撤去する。到達の制御が同じことを担う
  - サインインしている間だけサインアウトの操作が表示され、実行すると管理画面の内容が描画されなくなる
  - _Requirements: 4.7, 6.1, 6.2, 6.3_
  - _Boundary: AdminTemplate_
  - _Depends: 2.2_

## 4. 自前実装の撤去

- [x] 4.1 認証ストアと復帰先の検証を削除する
  - 自前の認証ストアを削除する。参照が解決できなくなることで取りこぼしが型検査に現れる
  - 復帰先の検証とその単体テストを削除する。同じ役割はモジュールが持つ
  - 認証の操作 API を直接呼ぶ箇所を残さない。認証インスタンスの初期化は logotope 側に残す
  - 参照の無い ID トークンの取得を、移行先を設けずに廃止する
  - クエリによる復帰先の受け渡しを行う箇所が残らない
  - 型検査が通り、削除した資産への参照がリポジトリに存在しない
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 5.3_

- [x] 4.2 既存のコンポーネント spec の差し替え先を更新する
  - 自前の認証ストアを差し替えていた spec を、受け渡し層を差し替える形へ書き換える
  - spec を削除せず、いずれも通る状態に戻す
  - _Requirements: 10.4_
  - _Depends: 2.2, 4.1_

## 5. 検査の更新と追加

- [x] 5.1 (P) 設定の確定値を検査する
  - 経路の全項目が管理画面の配下を指すこと
  - 自由登録とメールアドレスの確認が、いずれも求めない値であること
  - 戻り先が管理画面のサインインの経路で終わること（公開の根を指していないこと）
  - _Requirements: 2.4, 2.5, 3.1, 3.5, 7.1, 8.1_
  - _Boundary: AdminAuthConfig_

- [x] 5.2 (P) 受け渡し層を検査する
  - 登録したインスタンスがそのまま取得できること
  - 登録していない階層で取得したときに例外を投げること
  - _Requirements: 2.1_
  - _Boundary: AdminAuthAccessor_

- [x] 5.3 (P) 公開面の非回帰検査に、認証の混入の禁止を追加する
  - 公開の経路のソースに、モジュールと到達の制御が現れないことを禁止のパターンに加える
  - 既存の禁止（認証ライブラリ・管理用ストア・管理用コンポーネント）はそのまま維持する
  - 公開ページの経路が認証のコードを読み込まないことが、検査として固定される
  - _Requirements: 10.3_
  - _Boundary: TestSuite_

- [x] 5.4 (P) 配置と撤去をソースの走査で固定する
  - 到達の制御が管理画面の階層にのみ現れ、公開側のレイアウトに混入していないこと
  - 管理画面の階層に段階を見た条件式が無いこと
  - 管理データの購読の包みに認証への参照が無いこと
  - 登録の経路が実在しないこと
  - 削除した認証ストア・復帰先の検証・クエリによる復帰先の受け渡しへの参照が残っていないこと
  - アクセス制御が緩められていないこと（セキュリティルールがサインイン済みを条件とし、確認済みを条件に加えていないこと。呼び出し元の認証の検証が維持されていること）
  - _Requirements: 1.2, 1.3, 4.1, 4.2, 4.7, 5.3, 7.1, 8.4, 10.1, 10.2_
  - _Boundary: TestSuite_

- [x]* 5.5 (P) 共通の枠のサインアウトを検査する
  - サインインしている間だけサインアウトの操作が表示されること（受け入れ基準 6.1）
  - 実行するとモジュールの操作を呼び、遷移を行わないこと（受け入れ基準 6.2, 6.3）
  - _Requirements: 6.1, 6.2, 6.3_
  - _Boundary: AdminTemplate_

## 6. 疎通の確認と公開版への切り替え

- [ ] 6.1 エミュレータで通しの動作を確認する
  - 未サインインで管理画面の深い経路を開き、サインインへ振り替わったうえで、サインイン後にその経路へ戻ること
  - 判定の完了前に管理画面の内容が一瞬でも見えないこと
  - サインアウトでサインインへ戻り、管理画面の内容が描画されないこと
  - 公開ページが未サインインで表示されること
  - 再設定の要求が受け付けられ、リンクを開いた先が管理画面のサインインであること（公開の記事一覧でないこと）
  - パスワードを変更でき、完了後に既定の行き先へ戻ること
  - 既存の管理者アカウントが、確認の状態を理由とする移行を要さずそのままサインインできること
  - 差し替えの前後で、認証に依存する既存の画面（トピック一覧・トピック詳細の各フェーズ）の到達性が変わらないこと
  - _Requirements: 4.5, 4.6, 5.1, 5.2, 5.4, 5.5, 5.6, 8.3, 8.5, 10.5, 10.6_
  - _Depends: 1.4, 3.1, 3.2, 3.7, 4.1_

- [ ] 6.2 モジュールを公開し、公開版の依存へ切り替える
  - モジュールを公開レジストリへ公開する。ローカル参照のままでは本番のビルドが依存を解決できない
  - 依存を公開版へ切り替え、ロックファイルにローカルのパスが残っていないことを確かめる
  - 公開直後の版を除外する一覧に、公開した版を追加する
  - 本番と同じ手順のビルドが通り、管理画面と公開ページの両方が描画される
  - _Requirements: 1.6_
  - _Depends: 6.1_
