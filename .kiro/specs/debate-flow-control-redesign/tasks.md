- [x] 1.2 未使用メソッド・未使用オプションを削除する
  - ファシリテーターエージェントから呼び出されていない話者選択・章終了判定メソッドと関連型を削除する
  - 結果が使用されない参加バランス評価の呼び出しと関数本体を削除する
  - オーケストレーターオプションから未参照の値（沈黙閾値・ペルソナ最低ターン数）を削除する
  - 完了条件: 削除対象がコード・テストから消え、ビルドと既存テストが通る

- [x] 1.3 介入タイプ close を廃止し介入契約を3値に整理する
  - 介入評価のツールスキーマ・型定義から close を除去し、「topic_shift / invite / 介入不要」のみとする
  - 介入評価プロンプトを更新し、章終了の判断を求めない・議論が活発な間は介入不要を返すことを明示する
  - オーケストレーター側の close 無視分岐を削除する
  - 完了条件: 介入契約に close が現れず、エージェントの契約テストが通る
  - _Requirements: 2.10, 6.3, 6.4_

- [x] 2. フロー制御の純粋関数モジュール（Core）
- [x] 2.1 (P) 話者選択モジュールを実装する
  - ターン冒頭の確定判定（前ターン由来のファシリテーター指名・直接質問、連続直接交換3回上限、ファシリテーター指名は上限の対象外）を実装する
  - 評価後の決定（invite 指名 > 緊急リアクション > 全員低意欲時のキュー最古 > スコア降順・同点沈黙優先）を単一関数で実装する
  - 直前話者の連続回避（唯一の最高スコア時は例外）と不正 ID のスコア選択フォールバックを含める
  - キュー・指名由来の選択は full モード固定で意図要約を引き継ぐ
  - 完了条件: 優先順位 (1)〜(5)・境界ケースを網羅したユニットテストがすべて通る
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 5.3_
  - _Boundary: speaker-selection_

- [x] 2.2 (P) 章進行判定モジュールを実装する
  - 意欲評価結果から活性シグナル（0/1）を算出する規約を実装する（評価スキップターンは常に活性）
  - 早期終了判定（目標の75%消化かつ直近5シグナルすべて非活性、全ペルソナ発言は条件にしない）を実装する
  - 章の強制終了上限（目標の150%）の算出を実装する
  - 完了条件: 75%・5シグナル・150%の境界値テストと「シグナル5件未満は終了しない」テストが通る
  - _Requirements: 2.3, 2.4, 2.5, 2.6_
  - _Boundary: chapter-progress_

- [x] 2.3 (P) 介入ポリシーモジュールを実装する
  - 次話者未確定のターンで毎回介入評価を行う原則と、前回ファシリテーター発言からのクールダウン（2ペルソナ発言未満はスキップ）を実装する
  - 旧実装の間隔トリガー・沈黙トリガーは持ち込まない
  - 完了条件: クールダウン境界と次話者確定時スキップのユニットテストが通る
  - _Requirements: 6.1, 6.2_
  - _Boundary: intervention-policy_

- [x] 2.4 (P) 状態復元モジュールを実装する
  - 保存済みターン履歴から話者選択に必要な状態（発言数・沈黙数・最終ファシリテーターターン・直前話者・次ターン番号）を復元する単一ロジックを実装する
  - 永続化済みの意図キューを取り込み、トリガーから8ターン超過したエントリの失効を復元時に適用する
  - 完了条件: 同一入力から常に同一の状態が得られる決定性テストと、復元値・失効適用のユニットテストが通る
  - _Requirements: 5.2, 5.5, 8.2_
  - _Boundary: state-restore_

- [x] 3. エージェント・リポジトリの契約変更（Core）

- [x] 3.2 (P) リポジトリにキュー write-through とエラー終端を追加する

  - セッションをエラー状態にする関数を追加する
  - 完了条件: エミュレータテストでキューの全置換書き込みとエラー status 書き込みが検証できる

- [x] 4. オーケストレーターの再構成（Integration）
- [x] 4.1 章タスクの骨格と状態初期化を一本化する
  - 章タスク開始時にセッション検証（存在・非キャンセル）・処理済み章の冪等スキップを行い、保存済みターンと永続化キューから状態復元モジュールで状態を構築する
  - 第1章開始時の章立て生成・オープニング生成を組み込み、章立て生成失敗・章情報欠落はフォールバックせず例外を送出する
  - 完了条件: 章タスクがキュー込みの状態復元を経て開始し、章生成失敗時にエラーで中断する
  - _Depends: 2.4, 3.2_
  - _Requirements: 1.1, 1.5, 2.1, 2.2, 8.1, 8.2, 8.3, 8.4_

- [x] 4.2 ターンループを再構成する
  - ターンごとに「確定判定 →（並列: 全ペルソナ意欲評価＋介入評価）→ 評価保存 → 介入ターン保存 → 話者決定 → 発言生成 → ターン保存 → 状態更新」の固定順で進行させる
  - 意欲評価の失敗ペルソナは最低意欲として継続し、評価結果は毎ターン Firestore に保存する
  - キューの追加（score 5 で非選択）・消費（発言後に最古1件）を発生の都度 write-through で永続化する
  - 介入発言・ペルソナ発言を含むすべての保存ターンに章インデックスを付与し、活性シグナルをターンごとに必ず記録する
  - 信念変化の保存と以後のターンへの反映、討論全体のターン上限制御を維持する
  - 完了条件: 1ターンのフローが設計のシーケンス図と一致し、モックエージェントでのループテストが通る
  - _Depends: 2.1, 2.2, 2.3, 3.1_
  - _Requirements: 1.4, 2.5, 2.9, 3.1, 3.2, 3.3, 3.4, 4.1, 5.1, 5.4, 6.5, 6.6, 7.5_

- [x] 4.3 章終了・章遷移・討論終端を組み込む

  - 章遷移（現章まとめ＋次章導入の2ターン、導入は最初の発言者を指名）と、最終章後のクロージング・事後コメント・セッション完了を組み込む
  - 完了条件: 章が区切りの良いところで終了し、遷移2ターン・クロージング・事後コメントが正しい順序と章インデックスで保存される
