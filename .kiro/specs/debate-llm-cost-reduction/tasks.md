# Implementation Plan

- [x] 1. ペルソナ安定コンテキストのプロンプトキャッシュ適用
- [x] 1.1 傾聴・発言生成の安定コンテキストをキャッシュ再利用させる
  - anthropic(claude)経路のとき、ペルソナの安定コンテキスト（固定導入・スタイルガイド・プロフィール・事前取材レコード・初期信念）をキャッシュ対象の system ブロックとして送り、同一ペルソナの2回目以降の呼び出しで重複課金しないようにする
  - 適用対象は発言意欲評価と発言生成（draft/regen）。事後コメントは対象外とする（1回きり・別プレフィックスでキャッシュ書込の純増になるため）
  - gemini/gpt 経路と事後コメントは現行の呼び出しのまま変えず、発言・スコアの内容とスキーマ、各ペルソナの人格分離を一切変えない
  - 安定コンテキストが最小サイズ未満・キャッシュ非成立・期限切れ・上流の安定化が未確立のいずれでも、エラーなく従来課金で生成を完遂する（自動フォールバック）
  - 観測可能な完了: claude ペルソナの意欲評価・発言生成がキャッシュ対象の system で実行され、出力が改修前と同型のまま討論が完遂する
  - _Requirements: 1.1, 1.2, 1.3, 3.1, 3.2, 3.3_
  - _Boundary: persona-agent_

  - 出力スキーマ（発言本文/target、score/mode/awareness）が不変であることを検証する

- [x] 2. engagement評価の冗長削減
- [x] 2.1 (P) 章末の最終応答で指名者のみ評価する
  - 章末+1の最終応答（話者が指名で確定している分岐）で、全非話者の一括意欲評価を廃し、指名済み話者のみを評価する
  - 通常ターンの一括評価（話者選択・キュー・早期終了・気づき検出に必要）は変えない。非指名者の評価・気づき検出はこの最終ターンでは行わない
  - 観測可能な完了: 最終応答ターンで一括評価が実行されず指名者のみ評価され、討論が最後まで完遂する
  - _Requirements: 2.1, 1.4_
  - _Boundary: debate step_
- [x] 2.2 (P) 同一ターン状態の評価結果を再利用する
  - 当該ターンについて既に永続された意欲評価があるペルソナは、LLM 再評価をせず永続済みの score/mode を再利用する
  - 未永続（新規ターン状態）は従来どおり評価する。再利用時に気づきの再検出はしない（初回評価時に永続済み）。永続値が再利用に不十分なら当該ペルソナは従来評価にフォールバックする
  - 観測可能な完了: 同一ターン状態の再処理（ステップ再実行・リトライ）で意欲評価の LLM 呼び出しが発生せず、新規ターンでは評価される
  - _Requirements: 2.1, 2.2_
  - _Boundary: engagement_
- [x]* 2.3 冗長削減のユニットテスト
