# Implementation Plan

- [x] 1. Foundation: 論点追跡の型定義と定数を追加する
  - チャプター定義に論点リスト（3〜5件の文字列配列）を持たせる
  - 論点の進行状態を「未着手 / 着手 / 完了」の3ステータスで表す型を定義する
  - 討論の実行中状態に、各論点のステータスを保持する領域を追加する
  - ファシリテーターの応答に「投入した未完了論点のインデックス」を返す領域を追加する
  - 論点リストがある章のターン強制終了上限比率（既定より高い値）を定数として定義する
  - 完了条件: TypeScript strict でコンパイルが通り、論点リスト・3ステータス・投入インデックス・上限比率定数がすべて型レベルで利用可能になる
  - _Requirements: 1.4, 3.1, 3.2, 4.4, 5.3_

- [x] 2. (P) チャプター生成時に論点リストを生成・保存する
  - チャプター生成で、各章に「その章で押さえるべき論点」を3〜5件生成させる
  - 第1章の論点は専門知識のない人でも日常感覚で答えられる切り口に制約し、固有名詞・専門用語は第2章以降から導入する
  - 生成された論点を章データとともに Firestore のセッションに保存する
  - 論点生成に失敗した場合は空の論点リストとしてフォールバックし、チャプター生成自体はブロックしない
  - 完了条件: チャプター生成後、各章に論点リストが付与されて永続化され、生成失敗時も空リストで章が保存される
  - _Requirements: 1.1, 1.2, 1.3_
  - _Boundary: ChapterAgent_
  - _Depends: 1_

- [x] 3. (P) ファシリテーターエージェントを論点対応にする
  - _Boundary: FacilitatorAgent_
  - _Depends: 1_

- [x] 3.1 チャプター開幕で論点1を投げかける
  - 章に論点がある場合、開幕（および章導入）の問いかけを論点1を切り口として構成する
  - 章に論点がない場合は、既存のフォーカス問いベースの開幕ロジックを維持する
  - 開幕で投げかけた論点（論点1）のインデックスを応答として返す
  - 完了条件: 論点を持つ章で開幕発言が論点1に沿った問いかけになり、投入論点インデックスが返る。論点なしの章では従来どおりの開幕になる
  - _Requirements: 2.1, 2.2_

- [x] 3.2 A介入・B介入に未完了論点コンテキストを渡す
  - 論点ずれ介入（A）に未完了論点を渡し、「逸脱→引き戻し / 一段落→論点投入 / 流れが深まり中→介入しない」の三択判断と流れ最優先をプロンプトに明示する
  - 出尽くし介入（B）に未完了論点を渡し、流れ優先で落ち着いていれば未完了論点を投入するよう指示する
  - いずれの介入も1回につき投入する論点は1件に限定し、投入時はその論点インデックスを応答に含める
  - 未完了論点がない場合は、A・B とも既存の介入ロジックのまま動作する
  - 完了条件: A・B 介入がそれぞれ未完了論点を受け取り、投入時に対象論点のインデックスを返す。論点なし時は従来動作を維持する
  - _Requirements: 4.2, 4.3, 4.4, 4.6_

- [x] 3.3 論点消化を評価する関数を追加する
  - 当該章の全ターンと未完了論点リストを受け取り、各論点が実質的に議論されたかを AI で評価する
  - 消化済みと判定された論点を呼び出し元が特定できる形で返す
  - 評価に失敗した場合はエラーを返し、呼び出し元がフォールバックできるようにする
  - 完了条件: 章ターンと未完了論点を渡すと、消化済み論点が判別可能な結果として返り、失敗時はエラーが返る
  - _Requirements: 3.3, 3.4_

- [x] 4. オーケストレーターに論点ステータス管理と終了制御を統合する

- [x] 4.1 介入経路で未完了論点を渡し投入結果を伝播する
  - 介入評価の呼び出し時に、実行中状態から未完了論点（完了以外）を抽出して A・B 介入へ渡す
  - 既存の介入評価順序（A→B）とトリガー条件は変更しない
  - 介入が論点を投入した場合、その投入論点インデックスを呼び出し元（オーケストレーター）へ伝播する
  - 完了条件: 介入発火時に未完了論点が介入へ渡り、投入された論点インデックスがオーケストレーターまで届く。トリガー条件・評価順序は従来どおり
  - _Requirements: 4.1, 4.2_
  - _Boundary: Intervention_
  - _Depends: 1, 3.2_

- [x] 4.2 論点ステータスの初期化・更新と早期終了制御を実装する
  - チャプター開始時に、章の論点をすべて「未着手」で実行中状態に初期化する
  - 章に論点がある場合は高いターン上限比率を、ない場合は既存比率を用いてハードキャップを算出する
  - 開幕および介入で投入された論点を「着手」にマークする
  - 早期終了条件が成立したとき、未完了論点が残っていれば消化評価を呼び、消化済み論点を「完了」に更新する
  - 未完了論点が残る限り早期終了を抑止して章を継続し、全論点が完了すれば既存の早期終了条件で章を終える
  - 消化評価に失敗した場合は既存の早期終了ロジックにフォールバックする。論点がない章は既存ロジックのまま動作する
  - ハードキャップに達した場合はステータスに関わらず章を終了する
  - 完了条件: 論点を持つ章で「未着手→着手→完了」が遷移し、未完了が残る間は早期終了せず継続、全完了またはキャップ到達で終了する。論点なしの章は従来挙動を維持する
  - _Requirements: 2.3, 3.1, 3.5, 4.5, 5.1, 5.2, 5.4, 5.5_
  - _Boundary: DebateOrchestrator_
  - _Depends: 1, 3.1, 3.3, 4.1_

- [x] 5. テストを追加する

  - 論点ステータスが「開幕で論点1が着手 / 介入投入で着手 / 評価で完了」へ遷移するかを検証する

  - ハードキャップ比率が論点あり／なしで使い分けられることを検証する
