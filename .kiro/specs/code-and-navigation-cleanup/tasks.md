# Implementation Plan

- [x] 1. 不要コードの削除（挙動変更ゼロ）
- [x] 1.1 (P) フロントエンドの未使用コードを削除する
  - デモ用ルート一式（E2Eテスト・Playwright設定・`test:e2e` スクリプト・`@playwright/test` 依存を含む）を削除する
  - 参照ゼロの管理コンポーネント4種とそのテスト、旧REST APIクライアントとそのテスト、vitest サンプル一式、空のライブラリスタブを削除する
  - 削除前に各対象の未参照を検索で確認し、将来利用が明確なものが見つかった場合は削除せず根拠を記録する
  - 削除後に型チェックとビルドが警告なく通過し、削除対象への参照が検索でゼロ件であること
  - _Requirements: 1.1, 1.2, 1.3, 1.4_
  - _Boundary: Deleted Files（フロントエンド）_
- [x] 1.2 (P) Functions 側の廃止済み progress 参照の残骸を除去する
  - 討論オーケストレーターのテストから、存在しない progress-tracker への型参照と関連モックを除去する
  - フロントエンド・Functions 全体で progress コレクションへの読み書き・型参照がゼロ件であることを検索で検証する
  - 討論生成の進捗表示が正規データソース（セッションドキュメント）由来で従来どおり機能していることを確認する
  - Functions のビルドとユニットテストがすべて通過すること
  - _Requirements: 2.1, 2.2, 2.3, 2.4_
  - _Boundary: debate-orchestrator.test.ts_

- [x] 2. フェーズ判定ユーティリティを実装する
  - フェーズ定義（番号・スラッグ・表示名）と、討論ステータスからフェーズを求める変換、フェーズURLを生成する関数を単一モジュールとして実装する
  - 変換は全ステータスを被覆し、未知の値はフェーズ1にフォールバックする
  - 全ステータスの対応・フォールバック・URL生成を検証するユニットテストが通過すること
  - _Requirements: 4.1, 4.4_

- [x] 3. フェーズ別ルートへの再構築
- [x] 3.1 (P) ステップナビゲーションコンポーネントを作成する
  - UIライブラリの Tab コンポーネントをラップし、全フェーズと現在位置を表示する
  - 到達済みフェーズはリンクとして遷移可能、未到達フェーズは無効化されて表示されること
  - _Requirements: 3.3, 4.1, 4.2, 4.3_
  - _Boundary: StepNav_
- [x] 3.2 討論管理の共通レイアウトを新設する
  - トピックストアの生成・購読・停止をレイアウトに集約し、配下ページへ context で供給する
  - 読み込み中はローディング表示、トピック不存在時は not found 表示とダッシュボードへの導線を出し、配下ページを描画しない
  - 未到達フェーズのURLへのアクセスを現在フェーズへリダイレクトする（到達済みフェーズの閲覧では自動遷移しない）
  - ステップナビ・トピックタイトル・ダッシュボードへ戻るリンクが全フェーズページで共通表示されること
  - _Requirements: 4.2, 4.3, 4.4, 5.3, 5.4, 5.5_
  - _Depends: 2, 3.1_
- [x] 3.3 フェーズ別ページとリダイレクトページを作成する
  - 4フェーズそれぞれの個別URLページを作成し、context から取得した表示モードに応じて既存フェーズコンポーネントを描画する
  - 旧URL（トピック直下）へのアクセスは現在フェーズのURLへ置換リダイレクトする
  - テーマ作成から討論完了までの一巡で、フェーズ進行に応じてURLが変わり、ブラウザの戻る・進むでフェーズ間を移動できること
  - _Requirements: 4.1, 4.3, 4.7_

- [x] 4. 閲覧モードとリセット操作の分離
- [x] 4.1 (P) フェーズコンポーネントに閲覧モードを追加する
  - 4つのフェーズコンポーネントに readonly プロップを追加し、閲覧時は生成・承認・公開などのアクションUIを描画せず、アクション関数も渡さない
  - 「前のフェーズに戻る」ボタンと、それが呼んでいたリセット処理の呼び出しをコンポーネントから撤去する
  - 過去フェーズを開いたとき、承認済みデータが読み取り専用で表示され、いかなる操作でもデータが変化しないこと
  - _Requirements: 4.3, 4.5_
  - _Boundary: Phase1-4 コンポーネント_
- [x] 4.2 (P) リセットパネルを作成する
  - 「このフェーズからやり直す」ボタンと、破棄されるデータを列挙する確認ダイアログ（破壊的スタイル）を実装する
  - 承諾後にのみリセットを実行し、完了後に該当フェーズへ遷移する。実行中の二重実行を防止し、失敗時はエラーを表示して遷移しない
  - 確認ダイアログのキャンセルでは一切データが変化しないこと
  - _Requirements: 3.3, 4.5, 4.6_
  - _Boundary: PhaseResetPanel_
- [x] 4.3 リセットを統合し閲覧ページに配置する
  - 重複していた討論リセット関数をフェーズ3リセットに統合し、実行中討論のキャンセルが引き続き行われることを確認する
  - 閲覧モードのフェーズページ（1〜3）にのみリセットパネルを表示し、フェーズごとの破棄対象リストを定義する
  - 過去フェーズからのやり直しが「閲覧 → リセットボタン → 確認 → 該当フェーズが編集可能になる」の流れで完了すること
  - _Requirements: 3.1, 4.5, 4.6_
  - _Depends: 4.1, 4.2_
- [x]* 4.4 閲覧モードのレンダリングテストを追加する
  - readonly 指定時にアクションUIが描画されないことを既存のコンポーネントテストのパターンで検証する
  - 4.3（過去フェーズの非破壊閲覧）の受け入れ基準をテストで担保すること
  - _Requirements: 4.3_

- [x] 5. 認証ガード・遷移統一・重複統合
- [x] 5.1 認証ガードをリアクティブ化しログイン後復帰を実装する
  - ポーリングによる認証監視を廃止し、認証ストアの状態変化に反応するガードに置き換える
  - 未認証時は現在のパスをリダイレクトパラメータとしてログインページへ誘導し、ログイン成功後に元のページへ復帰する
  - リダイレクト先は管理画面配下の相対パスのみ許可し、不正値はダッシュボードへフォールバックする。認証済みユーザーのログインページアクセスはダッシュボードへ遷移する
  - 未認証で管理ページへ直リンク → ログイン → 元ページに戻る一連の流れが機能すること
  - _Requirements: 5.2_
- [x] 5.2 ページ個別の認証リスナーを撤去し遷移を統一する
  - ダッシュボードと討論管理ページが個別に張っていた認証リスナーを撤去し、ガード通過後にページが描画される保証に置き換える
  - フルページリロードを起こす遷移をクライアントサイドナビゲーションに置き換える
  - 管理画面内のすべての遷移がリロードなしで行われ、各ページのデータ購読が従前どおり開始されること
  - _Requirements: 3.1, 3.2, 5.6_
  - _Depends: 5.1_
- [x] 5.3 (P) 公開トップのデータ取得をストアへ集約する
  - 公開済みトピックを取得するストアを既存ストアと同じ構造で追加し、トップページのインラインクエリを置き換える
  - 公開トピックの絞り込みと公開日時降順ソートを検証するユニットテストが通過すること
  - トップページの表示内容・並び順が従前と同一であること
  - _Requirements: 3.1, 3.2_
  - _Boundary: topics store, 公開トップページ_

- [x] 6. 非回帰検証
- [x] 6.1 ビルド・型チェック・全テストのゲートを通過させる

  - 削除済みファイルへの参照が検索でゼロ件であることを最終確認する
  - _Requirements: 6.1, 6.2_
- [x] 6.2 主要フローの統合確認を行う

  - テーマ新規作成後に該当テーマの管理ページへ遷移すること、未認証直リンクからのログイン復帰、過去フェーズ閲覧とリセットの一連の流れを確認する
  - 公開画面（トップ・討論閲覧）がリファクタリング前と同一のコンテンツ・URLで閲覧できること
