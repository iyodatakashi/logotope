# Requirements Document

## Project Description (Input)
討論の発言を生成する際、必要に応じて検索ツールを使用し情報取得させたい。データアナリストがデータの質問を受けた際、データの裏付けなしに適当な反応をするなどの問題を回避したい。

## Introduction

本仕様は、logotope の討論生成パイプラインにおけるペルソナエージェントの発言生成時に、外部検索ツールを統合するための要件を定義する。データアナリスト等のデータ根拠を必要とするペルソナが、裏付けなしに不正確な回答をする問題を解消し、検索によって取得した事実情報に基づいた発言を生成できるようにする。

## Boundary Context

- **In scope**: ペルソナエージェントの発言生成時の検索ツール統合、検索結果の発言への反映、検索記録の Firestore 保存
- **Out of scope**: ファシリテーターエージェントへの検索ツール適用、フロントエンドからのリアルタイム検索、エンドユーザー向け検索 UI
- **Adjacent expectations**: 既存の `persona-agent.ts`・`debate-orchestrator.ts` の動作を維持しつつ機能を追加する。Firestore の `turns` 埋め込み構造は変更しない。

## Requirements

### Requirement 1: ペルソナエージェントへの検索ツール組み込み

**Objective:** As a 討論オーケストレーター, I want ペルソナエージェントが発言生成時に検索ツールを利用できること, so that 事実に基づいた正確な発言が生成される

#### Acceptance Criteria
1. The ペルソナエージェント shall Claude API の tool_use 機能を通じて、検索ツールが定義されたツールリストを受け取れる
2. When ペルソナエージェントが発言生成を開始するとき, the ペルソナエージェント shall 検索ツールを含むツールリストを付与して Claude API を呼び出せる
3. The ペルソナエージェント shall 複数回の tool_use ラウンドトリップ（multi-step tool call）をサポートし、必要に応じて繰り返し検索を実行できる
4. The ペルソナエージェント shall 検索ツールの有効/無効をペルソナ属性またはオーケストレーター設定により制御できる

### Requirement 2: 検索実行の自律判断

**Objective:** As a ペルソナ, I want 発言の生成にあたり必要と判断したときに自律的に検索を実行できること, so that 職種や質問の発信者に関わらず、根拠のない推測による発言を避けられる

#### Acceptance Criteria
1. The ペルソナエージェント shall 数値・統計・事実・最新動向など正確性が求められる情報を発言に含める場合は、推測や記憶に頼らず積極的に検索ツールを呼び出す
2. The ペルソナエージェント shall 検索実行の判断を職種・役割・発言の発信者によって制限されず、ペルソナ自身の判断に委ねる
3. The ペルソナエージェント shall 検索が不要と判断した場合はツールを呼び出さず、直接発言を生成できる
4. The ペルソナエージェント shall 検索クエリをペルソナの立場・背景・stanceDirection に沿った視点で構築する

### Requirement 3: 検索結果の発言への反映

**Objective:** As a 討論パイプライン, I want 検索で取得した情報を発言内容に組み込むこと, so that 発言の信頼性と具体性が向上する

#### Acceptance Criteria
1. When ペルソナエージェントが検索ツールの結果を受け取るとき, the ペルソナエージェント shall その情報を参照した上で発言を生成する
2. The ペルソナエージェント shall 検索結果のみに依存せず、ペルソナの background・beliefs・stanceDirection を維持した一貫性のある発言を生成する
3. If 検索結果がペルソナの既存の信念と矛盾するとき, the ペルソナエージェント shall ペルソナらしく矛盾を処理した発言（認識の更新、否定、解釈の差異など）を生成できる
4. The ペルソナエージェント shall 検索結果を適切に引用・参照する形で主張を構築し、根拠を発言内に組み込める

### Requirement 4: 検索失敗時のフォールバック動作

**Objective:** As a 討論パイプライン, I want 検索ツールが失敗または利用不可の場合でも討論を継続できること, so that 検索エラーが討論全体の停止を引き起こさない

#### Acceptance Criteria
1. If 検索ツールの呼び出しがエラーを返したとき, the ペルソナエージェント shall エラーを記録しつつ検索結果なしで発言を生成し続ける
2. If 検索結果が空または関連性が低いとき, the ペルソナエージェント shall ペルソナの background と既存の beliefs のみを使って発言を生成する
3. The ペルソナエージェント shall 検索の可用性に依存せず、常に有効な発言テキストを返せる
4. When 検索が失敗したとき, the 討論パイプライン shall 討論を中断せずに次のターンを継続できる

### Requirement 5: 検索利用の記録・トレーサビリティ

**Objective:** As a 管理者, I want 各発言ターンでどのような検索が行われたかを確認できること, so that 生成コンテンツの品質と AI 行動の透明性を担保できる

#### Acceptance Criteria
1. When ペルソナエージェントが検索ツールを呼び出したとき, the 討論パイプライン shall 検索クエリと結果のサマリーを Firestore のターンデータ（`turns` 配列の該当エントリ）に記録する
2. The 討論パイプライン shall 検索が実行されたかどうかを示すフラグ（`searchUsed: boolean`）をターンデータに含める
3. While 検索記録を保存するとき, the 討論パイプライン shall 既存の turns 埋め込み構造（`FieldValue.arrayUnion`）を使用し、Firestore 課金・パフォーマンスへの影響を最小化する
4. The 討論パイプライン shall 検索記録をターンデータの一部として保存し、新たなサブコレクションを追加しない
