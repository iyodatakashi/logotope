# Implementation Plan

> 既存ファクトチェック検出（`checkTurn`）の最終段に修正適否ジャッジ（共通フィルタ）を1段追加する。判定本体は新規 `fact-check-judge`、結線は `checkTurn`。検出（Phase1/2）・finding 型・FE・repository は変更しない。

- [x] 1. 判定用 LLM モデルの供給を追加
  - パイプラインモデル定義に判定用モデル（`factCheckJudge`、構造化フェーズと同等の Gemini flash 相当）を追加する
  - モデル選択処理に判定用の分岐を追加し、既存ファクトチェック系と同じく Gemini provider を返す（`GEMINI_API_KEY` 未設定時は claude へフォールバック）
  - 観測可能な完了条件: 判定タスク種別を指定するとモデルインスタンスが取得でき、未設定時はフォールバックする
  - _Requirements: 2.2_

- [x] 2. 修正適否ジャッジの実装
  - 発言本文・検出済み finding 群・討論文脈（テーマ/章/現在日時、**必須**）を入力に、各 finding を correct / skip / uncertain で判定する判定処理を実装する
  - 判定プロンプトは一般原則ベースにする: 「多様な立場が意見・提案・問いを交わす討論であり、事実として読者に誤って伝わる断定のみ修正対象」。問いの前提・問いから再構成した暗黙命題・当為/提案/規範（反実仮想含む）・提案の実現可能性への反論・代弁は skip。該当と判断できたら uncertain に逃げず skip し、真に判別不能なときのみ uncertain とする。個別事例はプロンプトに埋め込まない
  - finding を既存 id 付きで提示し、id をエコーさせて id で突合する。skip のみ除外し、correct / uncertain は残す
  - per-finding フェイルオープン: 判定が返らなかった id・未知 id の finding はその1件だけ unjudged として残す。LLM 呼び出し失敗・スキーマ不整合は全件 unjudged として残す。例外を呼び出し側へ伝播しない
  - 全 finding の判定（id・decision・reason）を構造化して返し、除外・未判定を理由付きでログ出力する。finding の内容は改変しない
  - 観測可能な完了条件: finding ありの入力に対し、skip を除いた kept（要素不変・順序保持）と件数一致の判定リストを返す
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 3.1, 3.2, 4.1, 4.2, 5.1, 5.2, 5.3, 5.4, 6.1, 6.2, 6.3, 7.1, 7.2_
  - _Boundary: fact-check-judge_

- [x] 3. (P) 修正適否ジャッジの評価・回帰テスト
  - 過検出抑制: 問いの前提2例（国連赤十字／インド・ブラジル）・当為提案3例（インドの役割／24時間報告／事前制裁）が kept から除外され、かつ判定が uncertain ではなく skip であること（uncertain 逃避の抑止）を確認する。これらは**テスト入力としてのみ使用**し、判定プロンプトには持ち込まない
  - 回帰: 断定された誤り（大会方式変更による試合数・現在日時基準の時間軸の断定）が kept に残ること、問い/提案形式でも内部の確定事実の誤りが残ること、uncertain が残ることを確認する
  - フェイルオープン: LLM 失敗・スキーマ不整合で全件 unjudged 温存、id 未返却で当該1件のみ温存することを確認する
  - 判定リストの件数一致と reason 付与を確認する
  - 観測可能な完了条件: 上記ケースを含む判定の単体テストがすべて green
  - _Requirements: 2.6, 3.1, 3.2, 4.1, 4.2, 5.1, 5.2, 5.3, 5.4, 6.1, 6.2, 7.1, 7.2_
  - _Boundary: fact-check-judge tests_
  - _Depends: 2_

- [x] 4. (P) 検出末尾への判定段の組み込み
  - 発言検出の finding 確定後・返却直前に修正適否ジャッジを通し、フィルタ済み finding を返すようにする。討論文脈は必須で渡す
  - finding が0件のときは判定を起動せずそのまま返す
  - 判定はあくまで finding を絞るのみで、検出の戻り値の型・finding 構造は変えない。判定段の失敗で検出全体を失敗させない
  - 観測可能な完了条件: finding ありの発言検出が判定を通したフィルタ済み finding を返し、0件時は判定を起動しない。後追い章検証は無変更でフィルタ済みを受け取る
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 7.3_
  - _Boundary: fact-check-runner_
  - _Depends: 2_

- [x] 5. ファクトチェック経路の結線テスト
  - 発言検出が判定を通してフィルタ済み finding を返すこと、finding 0件で判定が起動しないことを確認する（判定モックを結線に追加）
  - 章単位検証がフィルタ済み finding を集約することを確認する（後追い経路の結線）
  - 観測可能な完了条件: 検出・章検証の結線テストがすべて green
  - _Requirements: 1.1, 1.3, 1.4_
  - _Depends: 4_
