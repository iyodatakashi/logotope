# Implementation Plan

## 1. Foundation: ステークホルダー安定idの永続化

- [x] 1.1 ステークホルダー生成時にサーバが安定idを付番して永続する
  - ステークホルダー生成の結果を保存する際、各ステークホルダーへ配列位置に依存しない安定した識別子を付与する
  - バックエンドのステークホルダー永続型に識別子を持たせる
  - 観測可能な完了条件: 新規生成したステークホルダーがFirestoreにユニークなidをもって保存される
  - _Requirements: 4.3, 7.2_
  - _Boundary: stakeholders backend_

- [x] 1.2 (P) フロントがステークホルダーの永続idを採用する
  - ストアが識別子を配列インデックスから導出する現状を、永続された安定idを用いる形に変更する
  - 永続idを持たない旧データは配列位置による識別子でフォールバックする
  - フロントの永続型・ドメイン型に識別子を反映する
  - 観測可能な完了条件: 一覧の各ステークホルダーが永続idで一意に識別され、旧データも従来どおり表示される
  - _Requirements: 4.3, 7.2_
  - _Boundary: stakeholders store/types_

## 2. Core: 選択的ペルソナ生成（バックエンド）

- [x] 2.1 (P) ペルソナ生成が出力順に依存せず由来を解決できるようにする
  - ペルソナ生成へ渡す各立場に、由来を突き合わせるための短いエコー用タグを付す
  - 生成結果がそのタグを返すように出力構造を拡張する
  - 観測可能な完了条件: 生成結果からどのペルソナがどの立場由来かをタグで一意に対応づけられる
  - _Requirements: 4.1, 4.3_
  - _Boundary: persona-generator-agent_

- [x] 2.2 採用ステークホルダーのみを生成し由来キーを付与する
  - 生成要求で受け取った採用ステークホルダーの識別子集合に一致するものだけを対象に絞り込み、部分集合で生成する
  - 生成結果のエコー用タグから由来を解決し、各ペルソナへ由来ステークホルダーの識別子を付与して永続する（タグ欠落時は位置と役割名でフォールバック）
  - 採用集合が空、または実在しない識別子を含む場合は不正入力として拒否する
  - 未採用のステークホルダーに対応するペルソナは生成されない
  - バックエンドのペルソナ永続型に由来キーを持たせる
  - 観測可能な完了条件: 3件中2件を採用して生成すると、由来キー付きのペルソナが2件だけ永続され、未採用の1件には生成されない
  - _Requirements: 4.1, 4.2, 4.3_
  - _Depends: 1.1, 2.1_
  - _Boundary: personas backend_

## 3. (P) ペルソナ生成呼び出しに採用選択を渡す

- [x] 3. フロントのペルソナ生成入口に採用ステークホルダー識別子を渡す
  - ペルソナ生成のドメイン操作へ、採用ステークホルダーの識別子集合を引数として受け渡す
  - 観測可能な完了条件: 採用選択がバックエンドの生成要求まで到達し、選択に応じた生成が起動する
  - _Requirements: 4.1_
  - _Depends: 2.2_
  - _Boundary: topic model_

## 4. Core: フェーズナビゲーションの集約

- [x] 4.1 (P) 3フェーズを1つのナビステップに束ねる導出を追加する
  - ステークホルダー・ペルソナ・取材の3フェーズを1ステップ（ペルソナ準備）として扱うナビ・グループ定義を設ける
  - 現在フェーズが属するグループ、到達可否、遷移先を導出する
  - 観測可能な完了条件: 現在フェーズを与えると、集約後のナビ項目（ラベル・遷移先・活性可否）が導出される
  - _Requirements: 6.6, 7.1_
  - _Boundary: phase model_

- [x] 4.2 ステップナビが集約グループを1タブとして表示する
  - ナビ・グループ定義をタブへマップし、3フェーズのいずれのURLでも同一タブがアクティブになるよう判定する
  - 観測可能な完了条件: ステークホルダー/ペルソナ/取材のどのURLでも「ペルソナ準備」タブが1つだけ選択表示される
  - _Requirements: 6.6, 7.1_
  - _Depends: 4.1_
  - _Boundary: StepNav_

## 5. Core: 統合ワークスペースUI

- [x] 5.1 (P) ステークホルダーと対応ペルソナの左右セット行を表示する
  - 1行に採用チェックボックス＋ステークホルダー（左）と、対応ペルソナ（右）を並べる行部品を作る
  - 対応ペルソナがある場合は人物像と取材状態を右側に表示し、ない場合は右側を空白にする（プレースホルダーなし）
  - 採用トグルは自身で状態を持たず親へ通知する
  - 観測可能な完了条件: ペルソナ有無に応じて右側が人物像＋取材状態、または空白として描画される
  - _Requirements: 1.3, 1.4, 3.1, 4.3, 5.2_
  - _Boundary: StakeholderPersonaRow_

- [x] 5.2 ワークスペースの行縦並び・対応づけ・採用選択を構成する
  - 左右セット行を縦に並べて統合画面を構成する
  - ステークホルダーと生成ペルソナを安定idで対応づける（旧データは役割名でフォールバック）
  - 採用選択を安定id集合で保持し、新規に現れたidのみ既定ONでシードして既存の選択は保持する。対応ペルソナが既にあるものはONとして反映する。ステークホルダー総入れ替え時は新集合が全ONになる
  - 採用が0件のときはペルソナ生成を実行させず理由を提示する
  - フロントのペルソナ型に由来キーを反映する
  - 観測可能な完了条件: 一部の採用を外して並べ替え・再読込しても、採用状態と行の対応が安定idで正しく保たれる
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 3.2, 3.3, 3.4_
  - _Depends: 1.2, 5.1_
  - _Boundary: PersonaWorkspacePage_

- [x] 5.3 3操作の実行導線と状態機械を実装する
  - ステークホルダー調査の開始と、下流破棄を伴う再調査を提供する
  - ペルソナ生成／再生成を提供し、実行時にステークホルダーを承認済みへ暗黙的に前進させ、採用選択に一致するペルソナへ更新し、再生成時は下流成果物を破棄する
  - ペルソナ取材／再取材を提供し、実行時にペルソナを承認済み（採用フラグ付与を含む）へ暗黙的に前進させてから取材を実行する。取材進捗と部分失敗の再実行、ペルソナ0件時の抑止を扱う
  - 取材完了後に取材を承認して章立てフェーズへ前進させる導線を提供する
  - 各操作のボタン活性を現在の生成状況とフェーズ状態から導出し、押下直後の実行中表示を楽観的に反映する（承認は独立ボタンを設けない）
  - 観測可能な完了条件: 承認ボタンなしで「生成→取材→章立てへ進む」を通しで実行でき、各境界でフェーズが前進し取材完了ペルソナに承認フラグが立つ
  - _Requirements: 1.5, 2.1, 2.2, 2.3, 2.4, 2.5, 4.4, 4.5, 4.6, 4.7, 5.1, 5.3, 5.4, 5.5, 5.6, 6.1, 6.2, 6.3, 6.4, 6.5_
  - _Depends: 3, 5.2_
  - _Boundary: PersonaWorkspacePage_

## 6. Integration: ルート結線と旧画面撤去

- [x] 6.1 3つのフェーズルートを統合画面へ置き換える
  - ステークホルダー・ペルソナ・取材の各ルートが統合ワークスペースを描画するようにし、旧来の3つの個別フェーズ画面を撤去する
  - 進行途中のトピックを開いたとき、現在の進行状態に応じて次に実行すべき操作が提示される
  - 観測可能な完了条件: 3ルートのいずれを開いても同一の統合画面が表示され、旧個別画面は参照されない
  - _Requirements: 7.1, 7.3_
  - _Depends: 4.2, 5.3_
  - _Boundary: route pages_

## 7. Validation: テスト

- [x] 7.1 (P) 選択的生成と由来解決のバックエンドテスト
  - 採用集合による絞り込みと由来キー付与を検証する（3件中2件採用で2件・キー一致）
  - 生成結果のタグ順を入れ替えても由来解決が正しいことを検証する
  - 採用集合が空・未知識別子で不正入力として拒否されることを検証する
  - 観測可能な完了条件: 上記ケースのユニットテストが通過する
  - _Requirements: 4.1, 4.2, 4.3_
  - _Depends: 2.2_
  - _Boundary: personas backend tests_

- [x] 7.2 (P) ナビ集約と採用選択整合のユニットテスト
  - 3フェーズが1グループへ束ねられ、現在フェーズに応じて活性可否と遷移先が導出されることを検証する
  - 新規idのみ既定ONでシードされ既存選択が保持されること、対応ペルソナ保有分がON反映されること、総入れ替えで全ONになることを検証する
  - 観測可能な完了条件: ナビ導出と採用選択シードのユニットテストが通過する
  - _Requirements: 3.2, 3.3, 6.6, 7.1_
  - _Depends: 4.1, 5.2_
  - _Boundary: phase model tests, workspace selection tests_

- [x] 7.3 承認暗黙化と統合画面のE2E検証
  - 「生成→取材→章立てへ進む」で各境界のフェーズ前進と取材完了ペルソナの承認フラグを検証する
  - 一部ステークホルダーの採用を外して生成すると、未採用行の右側が空・採用行のみに対応ペルソナが表示されることを検証する
  - 3ルートのいずれでも同一の統合画面が表示され「ペルソナ準備」タブが1つだけアクティブになることを検証する
  - 観測可能な完了条件: 上記のE2E/統合シナリオが通過する
  - _Requirements: 4.2, 4.3, 5.1, 6.1, 6.3, 6.4, 7.1_
  - _Depends: 6.1_
