# Implementation Plan

設計の「実装順序」に従い、**公開読み取りモデルの正規化（第1段）を完了させてから外見の実装（第2段）に入る**。捨てる形の上に新機能を積まないため。

- [ ] 1. 前提の確認（モデルと保存基盤）

- [ ] 1.1 画像モデルのスタイル再現性を試験生成で確認する
  - 移行先モデルで、既存の規範プロンプトと参照画像を用いて代表バリエーションを試験生成する
  - 外見表現（男性的／女性的／中性的）× 代表的な年齢帯の組み合わせを対象にする
  - 生成物が既存アセットと同じスタイル基準（無地背景・顔なし・黒基調のバストアップ）を満たすか判定する
  - 満たさない場合はプロンプトの調整案を出し、以降のタスクで使う生成指示を確定させる
  - 完了条件: 代表バリエーションで合格する生成物が得られ、以降の実装で使う生成指示が確定している
  - _Requirements: 2.1_

- [ ] 1.2 アバター保存先のアクセス方針を確立し疎通を確認する
  - アバター配置パスの読み取りを公開、書き込みをサーバ側のみに制限する設定を入れる
  - 1枚をサーバ経由で保存し、パスから導出した URL でブラウザから取得できることを確認する
  - 未認証状態でも取得できること、およびクライアントから書き込めないことを確認する
  - 完了条件: 保存した画像が未認証のブラウザから URL で表示でき、クライアントからの書き込みが拒否される
  - _Requirements: 2.2, 5.1_

- [ ] 2. 公開読み取りモデルの正規化（第1段）

- [ ] 2.1 公開記事の射影を話者 id 参照へ作り替える
  - 発言・気づき・所感が話者を安定 id で参照する形にし、名前・肩書を各要素へ焼き込むのをやめる
  - ペルソナを記事あたり1回だけ id で引ける形で提供する（管理側の既存パターンに揃える）
  - 読み取り境界では既存の永続型を参照し、公開専用の型は必要な場合にのみ定義する
  - 完了条件: 同じ話者の情報が複数の要素へ重複して載らない状態になっている
  - _Requirements: 5.3_

- [ ] 2.2 公開表示を id からの解決に更新する
  - 発言・気づき・所感の各表示が、話者 id からペルソナを引いて名前・肩書を表示する形に変わる
  - この段では外見（アバター・配色）を足さない
  - 完了条件: 既存の公開記事の表示（話者名・肩書・気づき）に回帰がなく、既存テストが通る
  - _Requirements: 5.1, 5.3_

- [ ] 3. 外見データの基盤

- [ ] 3.1 ペルソナに外見と性のあり方のフィールドを追加する
  - 性自認・外見表現・配色キー・アバター生成時刻をペルソナのデータに追加する
  - フロントエンドとサーバ側の双方で、永続されている形と一致させる
  - 完了条件: 追加したフィールドを含む状態で型検査が通る
  - _Requirements: 1.1, 1.2_

- [ ] 3.2 (P) 配色の決定的な割り当てを実装する
  - トピックのペルソナ人数から、色相環順のパレット系統を等間隔に選ぶ
  - 系統数以下なら全員が相異なる色になり、超える分は再利用する
  - 乱数を使わず、同じ人数からは常に同じ割り当てになるようにする
  - 完了条件: 人数 1〜30 について重複の有無・分散・同一入力での再現性を確認する単体テストが通る
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 4.1_
  - _Boundary: Avatar Color Assigner_

- [ ] 3.3 (P) 生成画像の後処理を移植する
  - 白背景の生成画像を、規定の形式（アルファ透過・正方・下端接地）へ変換する処理をサーバ実行可能な形にする
  - 既存の参照実装が持つ定数と手順（影の除去しきい値・輝度からアルファへの変換・被写体の切り出し・縦占有比・接地）を厳密に再現する
  - 完了条件: 既存の候補画像を入力に、参照実装と出力が画素単位で一致することを確認するテストが通る
  - _Requirements: 2.1_
  - _Boundary: Avatar Post Processor_

- [ ] 4. ペルソナ生成への組み込み

- [ ] 4.1 ペルソナ生成で性自認と外見表現を付与する
  - 生成されるペルソナが性自認と外見表現を持つようにし、永続する
  - 原則として両者を一致させ、乖離させるのはその人物の背景がそれを必要とする場合のみとする
  - 完了条件: 新規に生成した全ペルソナに性自認と外見表現が永続されている
  - _Requirements: 1.1, 1.2, 1.3_

- [ ] 4.2 ペルソナ永続時に配色を割り当てる
  - ペルソナ一括生成の永続処理で、安定した並び順に沿って配色を付与する
  - 割り当ては生成時に1回だけ行い、以後は再計算しない
  - 完了条件: 生成された全ペルソナに配色が入り、同一トピック内で重複がなく、再表示しても変わらない
  - _Requirements: 3.1, 3.2, 3.3, 4.1, 4.2_

- [ ] 5. アバター画像の生成

- [ ] 5.1 アバター生成の本体を実装する
  - ペルソナの年齢・外見表現・職業から生成入力を構成する。性自認は見た目の情報ではないため生成に渡さない
  - 生成 → 後処理 → 保存 → 生成時刻の永続までを1回の呼び出しで完結させる
  - 開始時点で既存の生成時刻を消し、処理中であることが表示から分かるようにする
  - 一時的な失敗は数回やり直し、なお失敗する場合は生成時刻を未設定のまま終了して例外を外へ出さない
  - 完了条件: 1ペルソナに対して実行すると画像が保存され生成時刻が永続される。失敗させた場合も生成時刻は未設定のまま終了する
  - _Requirements: 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 4.3_
  - _Depends: 3.3_

- [ ] 5.2 ペルソナ生成の流れにアバター生成を組み込む
  - ペルソナ一括生成のあと、ペルソナごとにアバター生成を実行する段を追加する（取材と同じ階層。新しいフェーズは作らない）
  - この段は終端とし、フェーズの完了判定を待たせない
  - 完了条件: ペルソナ生成を通しで実行すると、全ペルソナのアバターが生成され、1件失敗しても後続の討論生成へ進める
  - _Requirements: 2.1, 2.2_

- [ ] 5.3 アバターの個別再生成を呼び出せるようにする
  - 1ペルソナだけをやり直す入口を用意し、生成本体を共有する（取材の再実行と同じ操作性）
  - 完了条件: 1ペルソナを指定して再生成でき、旧画像が処理開始時に消えて新しい画像に置き換わる
  - _Requirements: 2.3, 2.4_

- [ ] 6. 表示への反映

- [ ] 6.1 アバター表示部品がペルソナから外見を解決するようにする
  - 呼び出し側はペルソナを渡すだけにし、色や画像の組み立てを持たせない
  - 配色キーから濃淡を解決し、画像はパスから URL を組み立てる。再生成後に古い画像が表示されないようにする
  - 話者をペルソナに解決できない場合（ファシリテーター）は無彩色の既定で描画し、パレット系統を消費しない
  - 画像や配色が欠けている場合は既定の見た目へ縮退し、常に有効な表示になるようにする
  - 完了条件: ペルソナを渡すだけで固有の色と画像で描画され、欠落時やファシリテーターでも既定の見た目で描画される
  - _Requirements: 3.5, 5.1, 5.4, 6.1_
  - _Boundary: PersonaAvatar_

- [ ] 6.2 (P) 公開記事にアバターを表示する
  - 発言・気づき・所感の各表示で、話者 id から引いたペルソナをアバター表示部品へ渡す
  - 完了条件: 公開記事の各発言・気づき・所感に、話者ごとに異なる色とアバターが表示される
  - _Requirements: 5.1, 5.2_
  - _Boundary: 公開表示コンポーネント_

- [ ] 6.3 (P) 管理画面にアバターを表示する
  - 各発言とペルソナ一覧で、既存の id 解決の仕組みから引いたペルソナをアバター表示部品へ渡す
  - 完了条件: 管理画面の各発言とペルソナ一覧に、公開記事と同一の見た目でアバターが表示される
  - _Requirements: 5.1, 5.2_
  - _Boundary: 管理画面コンポーネント_

- [ ] 6.4 管理画面でアバター未生成を判別し再生成できるようにする
  - アバターが生成されていないペルソナを画面上で判別できるようにする
  - その場から個別再生成を実行できるようにする
  - 完了条件: 未生成のペルソナが一覧から判別でき、その場で再生成して表示が更新される
  - _Requirements: 2.3, 2.4, 6.1_
  - _Depends: 5.3_

- [ ] 7. 既存データの移行

- [ ] 7.1 既存ペルソナへ配色をバックフィルする
  - 既存の全トピックについて、ペルソナへ安定した並び順で配色を付与する
  - 配色が未設定のペルソナにのみ付与し、繰り返し実行しても既存の割り当てを変えない
  - 完了条件: 既存記事の全ペルソナが固有の配色を持ち、色によって話者を判別できる
  - _Requirements: 3.1, 4.1, 4.2, 6.1_

- [ ] 7.2 既存ペルソナへ性自認と外見表現をバックフィルする
  - 既存ペルソナの人物記述から性自認と外見表現を確定し、両者を一致させる
  - 記述から判別できないペルソナは機械的に決めず、管理画面から個別に設定できる状態にする
  - 完了条件: 既存ペルソナに両フィールドが入り、判別できず未設定のまま残ったものが把握できる
  - _Requirements: 1.1, 1.2_

- [ ] 7.3 既存ペルソナのアバター画像を生成する
  - 外見表現が揃った既存ペルソナに対し、新規と同じ経路でアバターを生成する
  - トピック単位・ペルソナ単位で段階的に実行し、失敗分は個別再生成で回収する
  - 完了条件: 既存記事の各話者にアバターが表示され、新規記事と同じ見た目の水準になる
  - _Requirements: 2.1, 2.2_
  - _Depends: 7.2_

- [ ] 8. 検証

- [ ] 8.1 公開・管理を通した表示の確認と回帰チェック
  - 公開記事の発言・気づき・所感、および管理画面の発言・ペルソナ一覧で、同じペルソナが同じ見た目になることを確認する
  - ペルソナの並び順が変わっても既存の見た目が変わらないこと、再訪問しても変わらないことを確認する
  - アバター未生成のペルソナが既定の見た目で表示され、配色によって判別できることを確認する
  - 完了条件: 上記が確認でき、既存の公開表示に回帰がない
  - _Requirements: 4.2, 5.1, 5.2, 5.4, 6.1_

- [ ]* 8.2 生成入力と表示解決の単体テストを補強する
  - 生成入力に年齢・外見表現・職業が反映され、性自認が画像生成入力へ混入しないことを確認する（受入基準 1.3, 1.4）
  - 配色キーの有無・アバターの有無・ファシリテーターの各場合で既定へ縮退することを確認する（受入基準 3.5, 5.4, 6.1）
  - 完了条件: 上記を対象とする単体テストが通る
  - _Requirements: 1.3, 1.4, 3.5, 5.4, 6.1_
