# Implementation Plan

- [x] 1. 進捗ステータスの型と永続形（両側一致）
- [x] 1.1 進捗ステータス型を定義し、記事要素の永続形に状態を持たせる
  - 進捗ステータス（生成待ち／生成中／整え中／完了）を functions・frontend 両側に定義し一致させる
  - 導入・締め・所感の永続形に進捗ステータスのフィールドを追加する（既存の draft/final は不変）
  - 生成待ちと失敗をデータ上で区別できる（両者は内容が空で、ステータスのみで区別する）
  - 完了状態: 両側の永続型が一致し、記事要素がステータスを持つ形になっている
  - _Requirements: 1.1, 1.2, 1.3_

- [x] 2. サーバ: 生成ライフサイクルでステータスを段階的に永続化
- [x] 2.1 初期化を生成待ちにし、段階書き込み用の部分上書きを用意する
  - 編集開始・やり直し時、導入・締めを生成待ちで初期化し、所感を空にする
  - ステータスのみ／ステータス＋原本を部分上書き（blind write）できる操作を用意する
  - 完了状態: 初期化直後、導入・締めが生成待ちとして永続化される
  - _Requirements: 2.1, 4.1_
- [x] 2.2 生成ビルドを段階書き込み化し、成否を内容で表す
  - 各要素の生成を「生成中 →（原本成功で）整え中 → 完了」の順にステータスを部分上書きする
  - 原本生成失敗は完了（内容空＝生成失敗）、整え失敗は完了（原本のみ＝編集失敗）、成功は完了（編集済み）にする
  - 所感生成の欠け（未書き込み）を廃し、失敗も完了として永続化する
  - 二重生成防止（スキップ判定）は原本の有無で行い、生成中（未完了）で止まった要素は再試行で再実行する
  - 完了状態: 生成の各段階が要素のステータスに反映され、途中クラッシュ要素がリトライで再実行される
  - _Requirements: 1.2, 2.2, 4.2, 6.1_
- [x] 2.3 終端スイープで未完了要素を確定する
  - ラン確定・停止時、生成待ち／生成中／整え中のまま残った要素を完了（内容空＝生成失敗）に確定する
  - 所感で未生成の承認ペルソナにも失敗エントリを materialize する
  - 既に完了の要素は変更しない（冪等）
  - 完了状態: 途中停止後に未完了要素が生成失敗へ確定し、生成待ち表示が固着しない
  - _Requirements: 4.3_

- [x] 3. サーバ: 個別再生成の状態反映
  - 再生成開始時に既存内容を破棄して生成中にし、段階を経て完了させる（再生成専用の状態は作らず生成中を再利用）
  - 生成できた場合（編集済み／編集失敗）は完了で更新し、生成失敗は完了（生成失敗）で確定して旧内容は保持しない
  - 完了状態: 再生成を実行すると即座に生成中表示になり、結果が要素のステータス・内容に反映される
  - _Requirements: 5.1, 5.2, 5.3_
  - _Depends: 2.1, 2.2_

- [x] 4. フロント: ストアの状態公開とフォールバック
  - editorialStore が導入・締め・所感を進捗ステータス付きで公開する（所感はペルソナ単位）
  - ステータス欠落の既存データを完了として正規化し、内容から編集済み／編集失敗／生成失敗を算出する。ドキュメント自体が無い場合は生成待ちを既定にする
  - 完了状態: 旧データでも破綻せず、各要素がステータスを持って公開される
  - _Requirements: 7.1, 7.2_
  - _Depends: 1.1_

- [x] 5. フロント: 表示を状態駆動に
- [x] 5.1 (P) 記事要素コンポーネントをステータス＋内容で表示する
  - 生成待ち／生成中／整え中は段階ラベル付きスケルトン、完了は内容から編集済み／編集失敗／生成失敗を表示する
  - 再生成ボタンは完了なら常に表示する（編集済みでも作り直せる）
  - ラン全体の完了フラグ（現状の isEditingFinished 相当）を表示判定に使わない
  - 完了状態: 各要素が自身のステータスと内容だけで表示され、isEditingFinished 依存が消える
  - _Requirements: 2.1, 2.2, 3.1, 3.2, 3.3, 3.4, 6.3_
  - _Boundary: NarrationSection, ImpressionSection_
  - _Depends: 4.1_
- [x] 5.2 (P) 所感の対応づけを状態ベースにする
  - 承認ペルソナに所感を対応づけ、エントリの無いペルソナは生成待ちとして扱う
  - 記事要素コンポーネントへの isEditingFinished の受け渡しを撤去する
  - 完了状態: 未生成ペルソナの所感が生成待ち（スケルトン）で表示される
  - _Requirements: 6.2_
  - _Boundary: EditingPage_
  - _Depends: 4.1_

- [x] 6. 検証
- [x] 6.1 (P) サーバのユニットテスト
  - 生成ビルドの段階書き込みと成否（生成失敗／編集失敗／編集済み）を検証する
  - 終端スイープ（未完了→生成失敗、完了は不変・冪等）を検証する
  - 個別再生成（開始時破棄・成功更新・失敗は生成失敗）を検証する
  - 完了状態: 上記のユニットテストが green
  - _Requirements: 2.2, 4.3, 5.1, 5.2, 5.3, 6.1_
  - _Boundary: element-builders, editing-lifecycle, regenerate-element_
- [x] 6.2 (P) フロントのテスト
  - ステータス backfill（欠落→完了）と内容による表示分岐を検証する
  - 生成待ち／生成中／整え中→スケルトン、完了→編集済み／編集失敗／生成失敗の分岐を検証する
  - 完了状態: 表示分岐のテストが green
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 7.1, 7.2_
  - _Boundary: editorialStore, NarrationSection, ImpressionSection_
- [x] 6.3 リポジトリ初期化・停止スイープの結合テスト（既存テスト更新）
  - 初期化が導入・締め＝生成待ち・所感空を書くことを検証する
  - 停止ランで未完了要素が生成失敗に確定することを検証する
  - 完了状態: 既存の editorial リポジトリテストを更新し green
  - _Requirements: 2.1, 4.3_
