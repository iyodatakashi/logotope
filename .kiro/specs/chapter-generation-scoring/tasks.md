# Implementation Plan

> 全実装は `functions/src/agents/chapter-agent.ts` に閉じる（呼び出し側 `chapter-generator.ts`・型ファイルは無改修）。実装タスクは同一ファイルを編集するため並列不可（`(P)` なし）。テストは `functions/src/tests/agents/chapter-agent.test.ts` に集約する。

- [x] 1. Foundation: 中間データ形状・スキーマ・定数の整備
  - スコアリング結果（論点テキスト・由来 general/persona・スコア・理由）と、章化中間表現（章タイトル・フォーカス問い・割り当て論点）の内部データ形状を定義する
  - 各AIステップの構造化出力用スキーマ（スコアリング結果配列・グループ化結果・章ごと論点配列）を index 突き合わせ前提で定義する
  - スコアリング/論点再構成用の最大トークン定数を追加（既存値の流用でも可）し、採用閾値（7）をモジュール内定数として定義する
  - 完了条件: 新ステップが参照する内部型・スキーマ・定数が `chapter-agent.ts` に存在し、型エラーなくビルドできる
  - _Requirements: 1.1, 1.2, 6.3_

- [x] 2. 論点の一括スコアリング
  - generalIssues と personaIssues を由来を保持したまま結合し、全論点を1回のAI呼び出しに渡して相対評価でスコアと理由を付与する
  - 評価軸（対立の生まれやすさ・一般人の関心・討論を深める価値）と、スコア分布の偏り対策（全論点を高得点にしない／低スコアを必ず含める）をプロンプトに明示する
  - 返却を index で入力論点に突き合わせ、欠落分はスコア0として扱う
  - 完了条件: 全入力論点に対し1対1でスコア・理由・由来が付与された結果が得られる（モックLLMで検証可能）
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_
  - _Boundary: IssueScorer_

- [x] 3. スコアによる論点の選別（純関数）
  - スコア7以上の論点を採用とし、7以上が0件の場合はスコア最上位を1件採用して採用ゼロを防ぐ
  - general 由来が採用に1件も含まれない場合、general 最高スコアの論点を1件追加採用する
  - 採用が少数に収束した場合はそのまま渡す（結果1章を許容）
  - 完了条件: AI呼び出しを行わない純関数として、各選別ルールがユニットテストで検証できる
  - _Requirements: 2.1, 2.2, 2.3_
  - _Boundary: IssueSelector_

- [x] 4. 採用論点のグループ化・章メタ生成
  - 採用論点を意味的近接でグループ化し、各グループを1章として章タイトル・フォーカス問いを生成し、採用論点を各章に割り当てる
  - 章数上限を5とし、超過時は近接グループを統合する。採用が収束すればグループ数1（1章）を許容する
  - 第1章には general 由来を割り当て固有名詞・専門用語を排し、章順は専門性・対立が段階的に増すよう整列する
  - 全採用論点がいずれかの章に割り当てられること（取りこぼしなし。割り当て漏れは最終章に寄せる）を保証する
  - 完了条件: 採用論点から1〜5章の中間表現（章メタ＋割り当て論点）が得られ、全論点が必ずどこかの章に属する
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 5.1, 5.2, 5.4_
  - _Boundary: ChapterComposer_

- [x] 5. 章ごとの論点再構成
  - 各章に割り当てられた採用論点を素材に discussionPoints を作り直し、意味的に重複する論点を統合する
  - 各章の discussionPoints を最終的に3〜5件に収める（素材不足はタイトル・フォーカス問いに沿って補い、過剰は統合・取捨する）
  - 再構成した論点を、特定のペルソナ名・発言を前提にしない汎用的な問いの形で生成する
  - 完了条件: 各章が3〜5件の汎用的 discussionPoints を持ち、id 付与・タイトル/フォーカス問いを引き継いだ最終チャプター表現が得られる
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 5.3_
  - _Boundary: ChapterPointAuthor_

- [x] 6. パイプライン統合とエラーハンドリング
  - 既存 `generateChapters` の単一章生成ステップを、スコアリング→選別→グループ化→論点再構成の連結に差し替える
  - 引数シグネチャと戻り値型（chapters・generalIssues・personaIssues）を変更せず、generalIssues/personaIssues は生成時のまま返す
  - 全AI呼び出しを単一 try/catch で囲み、失敗時に `AI_API_ERROR`（retryable: true）を返す。採用ゼロ・章ゼロ・再構成欠落章はフォールバックで処理する
  - 完了条件: `generateChapters` が論点内容に応じた1〜5章を返し、呼び出し側 `chapter-generator.ts` が無改修で動作する
  - _Requirements: 6.1, 6.2, 6.3, 6.4_
  - _Depends: 2.1, 3.1, 4.1, 5.1_
  - _Boundary: generateChapters_

- [x] 7. テスト整備
- [x] 7.1 各ステップのユニットテスト（モックLLM）
  - スコアリング: 全論点に1対1で結果が返る／index突き合わせ／欠落時のスコア0扱い
  - 選別: スコア7以上のみ採用／0件時の最上位1件採用／general0件時の追加採用／空入力
  - グループ化: 1〜5章に収まる／章0返却時の単一章フォールバック／割り当て漏れが最終章に寄る／全論点取りこぼしなし
  - 論点再構成: 各章3〜5件／章内重複の統合／返却章数不一致時の入力順マップと欠落章の素材流用／id付与とメタ引き継ぎ
  - 完了条件: 各ステップのテストが green
  - _Requirements: 1.1, 1.4, 2.1, 2.2, 2.3, 3.3, 4.2, 4.3_

- [x] 7.2 generateChapters 統合テストと既存テスト回帰
  - 全LLMモックで issue生成→スコア→選別→章化→論点再構成の連結が chapters を返すこと、エラー時に `AI_API_ERROR` を返すことを検証する
  - 戻り値型と generalIssues/personaIssues が生成時のまま保持されること（選別非依存）を検証する
  - 既存 `chapter-generator.test.ts` / `chapter-agent.test.ts` がインターフェース不変で通過することを確認する
  - 完了条件: 統合テストと既存テストがすべて green
  - _Requirements: 6.1, 6.2, 6.4_
  - _Depends: 6.1_
