# Implementation Plan

> すべてのタスクはファクトチェック検証ロジック（fact-check runner）の内部に閉じる。型・永続・FE・実行制御は変更しない（design.md「変更しないファイル」）。同一モジュールを編集するため順次実行（並行マーカーなし）。

- [x] 1. 検証コンテキストに現在日時を追加し時間軸検証を有効化
  - 章の検証コンテキストに「現在日時」を加え、各発言の検証プロンプトへ「本日は〜です。時間軸に関する主張はこの日付を基準に検証する」を注入する
  - 現在日時はファクトチェック実行開始時刻を基準とし、既存の本日文字列生成（`currentDateString()`）を再利用する
  - 観測可能な完了条件: 検証プロンプトに本日の日付が含まれ、「まだ1年以上ある」等の時間軸主張がその日付を基準に判定される
  - _Requirements: 3.5_
  - _Boundary: fact-check runner_

- [x] 2. 断定性の検証範囲を判定プロンプト（検証フェーズ）に組み込む
  - 事実として断定された主張のみを反証起点で厳密に検証し、問い・問いかけの前提・仮定/条件・他者認識の代弁は厳密検証の主対象としない方針を検証フェーズのプロンプトに明記する
  - 質問形式の発言でも、その中で確定事実（過去の出来事・既成の状態）として述べられた部分は検証対象に含める
  - 制度・規則の変更を伴う事実は最新の事実に照らして確認し、断定か非断定かが不確実な場合は断定として検証する
  - 発話者がペルソナでもファシリテーターでも同一基準で扱い、質問モードのシグナルは「問いかけである手掛かり」として渡すが、それ単独で発言内の全主張を一律に対象外としない
  - 観測可能な完了条件: 停戦の前提・「国連や赤十字が見るとして」等の仮定が厳密検証の主対象から外れ、質問内の確定事実・制度変更・時間軸の断定は検証される
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 2.2, 2.3, 2.4, 3.1, 3.3, 3.4, 3.6_
  - _Boundary: fact-check runner_

- [x] 3. 構造化フェーズを指摘生成の唯一の決定点として更新
  - 断定でない（問い・前提・仮定・代弁）と判断した主張は指摘（finding）を生成しないことを構造化フェーズのプロンプトに明記する（非断定の抑制判断はこのフェーズに一本化する）
  - 「意見・価値判断の対象外」と「非断定の事実言及」を別概念として扱い、断定か非断定かが不確実な場合は指摘を生成する（断定扱い）
  - 一つの発言に断定された事実主張と断定でない内容が混在する場合は、主張ごとに判定して断定された主張のみを指摘する
  - 断定された事実が誤っている場合は従来どおり誤り箇所・正しい事実・理由・出典を伴う指摘を生成する（指摘の形・判定値は変更しない）
  - 観測可能な完了条件: 非断定の主張に対する finding が生成されず、断定された誤りには従来どおりの指摘が残る
  - _Requirements: 1.6, 2.1, 3.2, 3.6_
  - _Boundary: fact-check runner_

- [x] 4. 判定の妥当性を検証するユニットテストを追加
  - 問いかけの前提・仮定として述べた事実主張は指摘されないことを確認する（停戦の前提、「国連や赤十字が見るとして」の仮定）
  - 質問文中でも確定事実として述べた主張は検証され、誤りなら指摘されることを確認する
  - 制度変更を伴う断定（大会方式変更による試合数）が最新事実で誤りと判定されることを確認する
  - 時間軸の断定（出来事までの残り期間）が与えられた現在日時を基準に判定されることを確認する
  - 質問モードの発言でも断定された誤りは検出されること、および既存挙動（出典0件は検証不能・引用の部分文字列照合）が不変であることを回帰確認する
  - 観測可能な完了条件: 上記ケースを含む runner のユニットテストがすべて green
  - _Requirements: 1.1, 1.4, 1.5, 2.1, 2.2, 2.3, 3.2, 3.3, 3.4, 3.5, 3.6_
  - _Boundary: fact-check runner tests_
