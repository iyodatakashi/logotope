# Implementation Plan

> 断定ゲート（Phase0）を Phase1 検索の前に新設し、非断定は grounding 検証に掛けない設計（design 再設計版）に追従するタスク。旧タスク2・3（Phase1/Phase2 プロンプトで非断定を抑制する旧方式）は本計画で置き換える。すべてファクトチェック検証ロジック（fact-check runner）とモデル登録に閉じ、型・永続・FE・実行制御は変更しない。同一モジュールを編集するため順次実行（並行マーカーなし）。

- [x] 1. 検証コンテキストに現在日時を追加し時間軸検証を有効化
  - 章の検証コンテキストに「現在日時」を加え、各発言の検証プロンプトへ「本日は〜です。時間軸に関する主張はこの日付を基準に検証する」を注入する（実装済み・再設計でも不変）
  - 現在日時はファクトチェック実行開始時刻を基準とし、既存の本日文字列生成（`currentDateString()`）を再利用する
  - 観測可能な完了条件: 検証プロンプトに本日の日付が含まれ、「まだ1年以上ある」等の時間軸主張がその日付を基準に判定される
  - _Requirements: 3.5_
  - _Boundary: fact-check runner_

- [x] 2. 断定ゲート用の軽量モデルを登録する
  - パイプラインモデル定義に断定ゲート用エントリ（grounding を使わない軽量モデル）を追加し、モデル取得関数の Gemini 系分岐に当該タスクを追加する
  - 既存の検証・構造化・修正適否の各モデル取得と同じ分岐パターンに揃える（新規の抽象化は作らない）
  - 観測可能な完了条件: 断定ゲート用タスク名でモデル取得関数が軽量モデルを返し、ビルド・型チェックが通る
  - _Requirements: 2.1_
  - _Boundary: fact-check runner_

- [x] 3. 断定ゲート（Phase0）を発言検証の先頭に新設する
  - 発言検証の冒頭で、grounding を使わない構造化呼び出しにより「事実として断定された、検証すべき事実主張」のみを発言から抽出する
  - 問い・問いかけの前提・仮定/条件・他者認識の代弁は抽出しない。質問形式でも、その中で確定事実（過去の出来事・既成の状態）として述べた部分は抽出する。断定か非断定か不確実なときは断定として抽出する（保守的デフォルト）
  - 発話者がペルソナでもファシリテーターでも同一基準で扱い、質問モードのシグナルは「問いかけである手掛かり」として渡すが、それ単独で発言内の全主張を一律に対象外としない
  - 抽出された主張は発言本文の部分文字列であることを照合し、ハルシネーション抽出を破棄する
  - 観測可能な完了条件: 停戦の前提・「国連や赤十字が見るとして」等の仮定・問いの中の偽の前提（loaded question）が抽出されず、質問内の確定事実・制度変更・時間軸の断定は抽出される
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 3.3, 3.6_
  - _Boundary: fact-check runner_

- [x] 4. 非断定のみの発言は検索検証を実行せず終える
  - 断定ゲートが断定主張をゼロ件と判定した発言は、grounding 検索（Phase1）・構造化（Phase2）を実行せず、指摘なし（空）で終える
  - 観測可能な完了条件: 純粋な問い・意見のみの発言で grounding 検証が呼ばれず、指摘が一切生成されない（検証も指摘もされない）
  - _Requirements: 2.1, 2.2, 2.3_
  - _Boundary: fact-check runner_

- [x] 5. 検索検証（Phase1）の対象を断定ゲート抽出の断定主張に限定する
  - 検索検証フェーズのプロンプトを「断定ゲートが抽出した断定主張のみを反証起点で検証する」に変更し、抽出された断定主張を検証対象として渡す。問い・前提・仮定の文言は検証対象に含めない
  - 制度・規則の変更を伴う事実は最新の事実に照らして確認する。混在発言では断定主張のみが検証対象になる
  - 観測可能な完了条件: 検証フェーズが断定ゲートの抽出結果のみを検証し、前提・仮定の文言が検索検証に渡らない
  - _Requirements: 2.4, 3.1, 3.3, 3.4_
  - _Boundary: fact-check runner_

- [x] 6. 構造化フェーズ（Phase2）を断定主張前提のバックストップに調整する
  - 断定主張のみが入力される前提で構造化フェーズのプロンプトを整理し、非断定抑制を二次的な安全網として残す。断定された事実が誤っている場合は従来どおり誤り箇所・正しい事実・理由・出典を伴う指摘を生成する（指摘の形・判定値は変更しない）
  - 観測可能な完了条件: 断定された誤りには従来どおりの指摘が残り、指摘の形・verdict 値が不変である
  - _Requirements: 1.6, 2.1, 3.2_
  - _Boundary: fact-check runner_

- [x] 7. 断定ゲート失敗時のフォールバックを実装する
  - 断定ゲートの呼び出しが失敗・スキーマ不整合のときは、見逃し回避を優先して当該発言の全文を従来どおり検索検証に回す（フェイルオープン）。失敗はログに記録する
  - 観測可能な完了条件: 断定ゲートを失敗させたとき、全文が検索検証に回り従来挙動になり、エラーがログされる
  - _Requirements: 3.6_
  - _Boundary: fact-check runner_

- [x] 8. 断定ゲート＋検証フローのユニットテストを追加・更新する
  - 問いかけの前提・仮定・loaded question（問いの中の偽の前提）で断定ゲートが抽出を行わず、grounding 検証が呼ばれず指摘も生成されないことを確認する
  - 質問文中でも確定事実として述べた主張は抽出・検証され、誤りなら指摘されることを確認する
  - 制度変更を伴う断定（大会方式変更による試合数）が最新事実で誤りと判定されること、時間軸の断定が与えられた現在日時を基準に判定されることを確認する
  - 質問モードの発言でも断定された誤りは検出されること、混在発言で断定主張のみが検証に渡ること、断定ゲート失敗時に全文フォールバックすることを確認する
  - 既存挙動（出典0件は検証不能・引用の部分文字列照合）が不変であることを回帰確認する
  - 観測可能な完了条件: 上記ケースを含む runner のユニットテストがすべて green
  - _Requirements: 1.1, 1.4, 1.5, 1.6, 2.1, 2.2, 2.3, 2.4, 3.2, 3.3, 3.4, 3.5, 3.6_
  - _Boundary: fact-check runner tests_
