# Implementation Plan

> 各画面は独立したコンポーネント（別ファイル＝別境界）であり、コアの画面タスク（1〜6）は並列実行可能 `(P)`。共通部品は新設せず、各画面の `actions` を「左＝前に戻る / 中央＝実行1スロット / 右＝次に進む」で直書きする。討論タスク（4）のみ討論ドメイン操作の整理でモデル（`createTopic`）に触れるが、他タスクは同ファイルに触れないため競合しない。`GeneratePersonaPage` は骨格（中央1スロット・採用ゲート）を参照実装として維持しつつ、共通 forward 契約（承認中 loading・失敗時エラー表示）へ揃える軽微改修のみ行う（タスク6）。各画面タスクは自画面の spec を新様式へ書き換え、旧配置の重複 spec を削除して `topic-detail` 配下へ一本化する。

- [x] 1. (P) テーマ設定画面を統一骨格へ移行する
  - 操作ペインを「前に戻る無し・中央無し・右＝次に進む」の3領域構成にする（先頭ステップのため戻る無し・実行操作無しで左右配置を崩さない）
  - 「次に進む」を filled・rounded・右アイコン `arrow_forward`・全画面共通文言にし、入力が妥当なときのみ活性（タイトル必須・各上限・URL形式）にする
  - 「次に進む」押下で保存→参考URL本文取得→テーマ承認を実行し、成功時のみ事実リサーチ画面へ遷移する。遷移先はフェーズ順から導出せず当該画面が直接持つ
  - 承認処理中は「次に進む」を loading にして多重押下を抑止し、失敗時は遷移せず操作ペイン内に失敗理由を表示する（現行の例外握りつぶしと失敗時遷移を撤廃する）
  - 観測可能な完了条件: 妥当な入力で「次に進む」を押すと承認後に事実リサーチ画面へ遷移し、承認が失敗したときは同画面に留まりエラーメッセージが表示される。画面遷移がフェーズ順導出に依存しない
  - テーマ設定画面 spec を新様式（文言・遷移・失敗時挙動）に書き換えて緑にする。旧配置（`features/admin/theme/`）の重複 spec を削除し `topic-detail` 配下の1系統へ一本化する
  - _Requirements: 1.3, 1.5, 1.6, 1.7, 2.1, 2.2, 2.3, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 6.1, 7.5, 8.2, 8.4, 8.5_
  - _Boundary: ThemePage_

- [x] 2. (P) 事実リサーチ画面を統一骨格へ移行する
  - 操作ペインを「左＝前に戻る（テーマ設定へ）/ 中央＝実行1スロット / 右＝次に進む（ペルソナ生成へ）」の3領域にし、遷移先を当該画面が直接持つ（フェーズ順導出を撤去）
  - 中央スロットを状態で入れ替える単一ボタンにする: 未生成＝filled・rounded・`cached` の実行ボタン（確認ダイアログを挟まず直接実行）/ 実行中＝loading / 生成済み・停止・前進済み＝ghost・rounded・`cached` の再調査ボタン（確認ダイアログ経由）。実行ボタンの loading/disabled は自フェーズ状態のみから導出する
  - コンテンツ領域に実行ボタンを置かず、未生成は未生成メッセージのみ・結果が空なら空である旨・実行中はスケルトンを表示する
  - 「次に進む」で事実基盤を承認して前進する。結果が空でも生成完了として活性にする。「実行せず承認する」操作とそのハンドラを撤去する
  - 承認失敗時は遷移せずエラー表示にする（握りつぶし・失敗時遷移を撤廃）
  - 観測可能な完了条件: 未生成状態で実行ボタンを押すと確認なしで調査が始まり、空結果でも「次に進む」が活性になりペルソナ生成画面へ前進できる。「実行せず承認する」がUI・コードから消える
  - 事実リサーチ画面 spec を新様式に書き換え、`fact-research-lifecycle` のライフサイクル検証を「ドメインの phase 前進」の意図へ読み替えて更新する。旧配置（`features/admin/fact-research/` の `PhaseFactResearch`）の重複 spec を削除し `topic-detail` 配下の1系統へ一本化する
  - _Requirements: 1.1, 1.2, 1.5, 1.6, 2.1, 2.2, 2.3, 2.4, 3.2, 3.4, 3.6, 4.1, 4.2, 4.3, 4.4, 4.5, 4.7, 4.8, 5.1, 5.4, 5.5, 6.2, 6.3, 6.4, 7.2, 8.2, 8.4, 8.5_
  - _Boundary: FactResearchPage_

- [x] 3. (P) アジェンダ生成画面を統一骨格へ移行する
  - 操作ペインを「左＝前に戻る（ペルソナ生成へ）/ 中央＝実行1スロット / 右＝次に進む（討論へ）」の3領域にし、遷移先を当該画面が直接持つ（フェーズ順導出を撤去）
  - 中央スロットを単一ボタンにする: 未生成＝filled・rounded・`cached` の生成ボタン / 実行中＝loading / 生成済み・前進済み＝ghost・rounded・`cached` の再生成ボタン（確認ダイアログ経由で下流破棄）。loading/disabled は自フェーズ状態から導出する
  - 独立した「承認して次へ進む」ボタンを撤去し、承認を「次に進む」へ畳み込む（章立て生成済みのとき活性、押下で承認→前進、失敗時は遷移せずエラー表示）
  - 観測可能な完了条件: 章立て生成後に中央は再生成ボタン1つだけになり、「次に進む」で承認して討論画面へ前進する。独立承認ボタンが消える
  - アジェンダ生成画面 spec を新様式に書き換えて緑にする。旧配置（`features/admin/chapters/` の `Phase4Chapters`）の重複 spec を削除し `topic-detail` 配下の1系統へ一本化する
  - _Requirements: 1.1, 1.2, 1.5, 1.6, 2.1, 2.2, 2.3, 2.4, 3.1, 3.2, 3.3, 3.4, 3.6, 4.1, 4.2, 4.3, 4.4, 4.5, 4.7, 4.8, 5.1, 6.7, 8.2, 8.4, 8.5_
  - _Boundary: GenerateChaptersPage_

- [x] 4. (P) 討論画面を統一骨格へ移行し討論ドメイン操作を整理する
  - 操作ペインを「左＝前に戻る（アジェンダ生成へ）/ 中央＝実行1スロット / 右＝次に進む（編集へ）」の3領域にし、遷移先を当該画面が直接持つ（フェーズ順導出を撤去）
  - 中央スロットを単一ボタンにする: 未生成＝filled・rounded・`cached` の開始ボタン / 実行中＝outlined の停止ボタン / 停止・生成済み・前進済み＝ghost・rounded・`cached` の「最初からやり直す」（確認ダイアログ経由で下流破棄）。部分継続の「再開する」を廃止し、停止からの復旧を最初からのやり直しに一本化する
  - 「1章で討論を終了する」オプション（状態とチェックボックス）を撤去し、討論は常に最後の章まで実行する。中央領域はトグルを持たず実行ボタンの単一スロットのみにする
  - 独立した「討論を確定して編集へ」ボタンを撤去し、承認を「次に進む」へ畳み込む（討論生成完了のとき活性、押下で承認→前進、失敗時は遷移せずエラー表示）
  - 討論ドメイン操作のうち UI から不要になった「再開する」ラッパをモデルから撤去し、開始操作の1章モード引数と送信を撤去する（停止操作は存続。サーバ側ハンドラの存置は範囲外）
  - 観測可能な完了条件: 停止状態では中央が「最初からやり直す」1つだけになり「再開する」が存在しない。1章モードのチェックボックスが消え、討論は最後の章まで走る。「次に進む」で承認して編集画面へ前進する
  - 討論画面 spec を新様式（開始・停止・やり直しの単一スロット、1章モード撤去、再開撤去）に書き換えて緑にする。旧配置（`features/admin/debate/` の `Phase5Debate`）の重複 spec を削除し `topic-detail` 配下の1系統へ一本化する
  - _Requirements: 1.1, 1.2, 1.5, 1.6, 2.1, 2.2, 2.3, 2.4, 3.1, 3.2, 3.3, 3.4, 3.6, 4.1, 4.2, 4.3, 4.4, 4.5, 4.7, 4.8, 4.9, 5.1, 5.2, 5.3, 6.8, 7.2, 8.2, 8.4, 8.5_
  - _Boundary: GenerateDebatePage, createTopic 討論操作_

- [x] 5. (P) 編集画面を統一骨格へ移行する
  - 討論未完了でも操作ペインを常時描画し、「前に戻る（討論へ）」を出せるようにする。討論未完了時はゲート文言（「討論が完了すると編集を開始できます。」）をコンテンツ領域に表示し、中央領域は空にする（編集開始の前提未充足を、実行ボタンを出さずゲート文言で示す）
  - 最終ステップとして「次に進む」を表示しない。中央スロットを単一ボタンにする: 未生成＝filled・rounded・`cached` の開始ボタン / 実行中＝loading / 生成済み・停止・前進済み＝ghost・rounded・`cached` の「編集をやり直す」（確認ダイアログ経由）。loading/disabled は自フェーズ状態から導出する
  - 「原本との差分を表示」トグルを操作ペインから外し、コンテンツ領域に配置する（中央領域は実行ボタンのみにする）
  - 記事要素の個別再生成・差分表示などコンテンツ本体側の既存操作は維持する
  - 観測可能な完了条件: 討論未完了でも編集画面で「前に戻る」から討論へ戻れる。差分表示トグルがコンテンツ領域に移り、操作ペイン中央は実行ボタンのみになる。最終ステップとして「次に進む」が無い
  - 編集画面 spec を新様式（ゲート位置・前に戻る・差分トグル移設・単一スロット）に書き換えて緑にする。旧配置（`features/admin/editing/` の `Phase6Editing`）の重複 spec を削除し `topic-detail` 配下の1系統へ一本化する
  - _Requirements: 1.1, 1.4, 1.5, 1.6, 2.1, 2.4, 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 4.8, 4.9, 5.1, 6.9, 6.10, 7.4, 8.2, 8.4, 8.5_
  - _Boundary: EditingPage_

- [x] 6. (P) ペルソナ生成画面を共通 forward 契約へ揃える
  - 骨格（前に戻る／中央1スロット＝生成・再生成／次に進む）と採用ゲートは参照実装として現行維持する
  - 「次に進む」に承認中の loading・多重押下抑止を追加し、前進（`advancePastPersonas`）の失敗時は遷移せず操作ペインにエラーを表示する（現行の loading 無し・失敗時無反応を是正し、他画面と同一契約にする）
  - 取材専用のボタン・状態分岐・コメントアウトされたマークアップが無いこと、採用ペルソナが1件も無いときは「次に進む」を disabled にし理由の注記を出すことを維持する
  - 観測可能な完了条件: 「次に進む」押下中は loading になり、承認失敗時は同画面に留まってエラー表示・遷移しない。採用0件で前進不可、採用1件以上で前進できる
  - 既存のペルソナ画面 spec を新契約（loading・失敗時エラー表示）を含めて緑にする
  - _Requirements: 3.3, 3.4, 4.10, 6.5, 6.6_
  - _Boundary: GeneratePersonaPage_

- [x] 7. Validation: 非退行・構造制約の検証
- [x] 7.1 ドメイン前進とナビ束ねの維持、構造制約を確認する
  - 承認時の phase 前進がフェーズ順（`nextPhase` のドメイン用途）で引き続き成立し、レイアウトの未到達フェーズ・リダイレクトガードが phase 単位で機能することを確認する
  - ステップ束ね定義がナビ表示コンポーネント内に閉じたまま外部へ切り出されていないこと、画面遷移を導出する新たな共通機構（ステップ順テーブル・前後解決ヘルパー・中央ディスパッチャ）が作られていないことを確認する
  - 観測可能な完了条件: 画面遷移の `nextPhase` 導出が全画面から消え、ドメイン前進とガードは維持され、遷移先は各画面が直接保持する。新たな共通遷移機構が存在しない
  - _Requirements: 2.5, 2.6, 8.1, 8.3_
  - _Depends: 1, 2, 3, 4, 5, 6_

- [x] 7.2 全画面の非退行と遷移ガード整合を検証する
  - 型チェックと全 page spec が緑であること（旧配置の重複 spec が削除され `topic-detail` 配下へ一本化されていること）、押下直後の楽観的な実行中表示が維持されること、再生成時の下流破棄範囲と確認ダイアログの文言・danger 指定が現行のまま維持されることを確認する
  - 事実の手編集・保存、ペルソナ採用チェック、記事要素の個別再生成などコンテンツ本体側の既存操作が壊れていないことを確認する
  - 承認による前進が反映される前に次画面へ遷移してガードに弾き返されないこと（承認直後の遷移整合）を、6画面の前進経路で確認する
  - 観測可能な完了条件: 6画面をテーマ設定から編集まで同一骨格で前進でき、既存の生成・破棄挙動とコンテンツ操作が非退行のまま、承認直後の遷移がガードに弾かれない。旧配置の重複 spec が残っていない
  - _Requirements: 7.1, 7.3, 7.5_
  - _Depends: 1, 2, 3, 4, 5, 6_
